### 5 与旧实现差异清单及归因（S-3 §2.3 口径：按诊断码族）

**F1（blocker，验收失败判据）nid 节点身份冲突 × 19 处**
- 现象：同一 nid 对应**不同节点**（如 list.subl nid=70 = HirParam@19:42 与 HirNamedType@0:0；
  错误处理.subl nid=9 = HirFunDecl@9:5 与 HirNamedType@0:0）。涉及 11 样本（list/map/
  optional/result/set/tuple/JSON内建/上下文弥散/标准库集合/模式匹配/错误处理）。
- 归因：`semantic/SymbolTable.kt` `builtinValueTypeOf()` 为内建值字面量类型
  （null→Null、true/false→Bool）构造合成 `HirNamedType` 时，第五位 nid 传的是**符号表
  计数器 `nextId++``（符号 id 空间），与 Elaborator 的节点计数器 `nextNid`（自 1 前序）
  冲突。破坏 D-9「nid 节点身份」与 ADR-1 §3.7「诊断↔节点绑定」——envelope diagnostics 的
  nid 反引在冲突 nid 上歧义，产物 diff / LSP 定位同样失真。
- 修复建议（semantics 拥有人）：合成型类型节点改由节点 id 空间分配 nid（经构造期计数器或
  独立合成 nid 段）；本 e2e 套件的 nid 身份一致性判据即为回归锁定。
- 同节点多处引用（DAG 共享，nid 重复但 kind/pos 一致）为**正确形态**，判据已区分，不计违规。

**F2（high）E-SYNTAX 解析层分歧 × 38 处 / 7 样本（旧 pass/新拒）**
- 定理声明形态（`@theorem` + 反引号名 + 理论参数 + `<命题>` 体）：peano 43/44·61/62、
  zfc 66/67·75/76·86/87、derived 33/34·52/53·57/58·62/63·88/89·94/95 + 124 收尾，
  共 34 处（旧 check 全过）。报「期望 var 变量声明/期望>，实际'fun'」。
- `unchecked print(+(4, 5))` 前缀算符调用与尾随 lambda 语境：函数与调用形式 47/50（2 处）。
- 无 `is` 的构造子解构模式（`Excellent() => …`）：类型类 14-17、日常-容器范型 15、
  日常-账单统计 37（12 处）——或为文法收紧（`is` 显式化）的有意分歧，**由 parser/文法
  拥有人裁决**：收紧则同步修订样例，否则修解析器。
- 归因层：parser（t4 D-1~D-21 覆盖外形态或恢复点分歧）。

**F3（medium）内建类型名单口径：BUILTIN_TYPES 不含容器类型**
- 新名单仅原子/异步内建（Nat/Int/Rat/Real/Str/Bool/Null/Nothing/Any/EmptyTuple/SingleTuple/
  Task/Channel/Mutex/Flow），不含 List/Optional/Result/Set/Map/Functor；旧单文件期惰性登记
  stdlib 类型名。→ io/json/string/script/net/real/math/regex 等大量「未知类型 Result/List/Optional」

- 归因层：semantics（P-7 名字层对齐口径，t7/t8）——裁决：补容器类型惰性登记，或明确
  「无 stdlib 单文件期不登记容器类型」为 V1 范围（则旧样例预期失败、文档需注记）。

**F4（medium）`@root` 无体函数被判 E-TYPE-MISMATCH「函数体是 Nothing」**
- encoding（base64Encode 等 4 处）、json 等：`@root fun f(...): Str` 无体在旧实现为内建
