## 容器构造类型合成裁决（00:17）

**队长误记纠正**：本语言**没有 `[]` 空列表语法**。用户裁决：`ListOf()` 返回 `List[Nothing]`；`MutableListOf()` 返回 `@mut List[Nothing]`，但后续写入语句使元素位成为**新鲜元变量**并由约束合成。

**形式化**：
```
var xs = MutableListOf()   ⟹  xs : @mut List[?T]
xs.add(1)                  ⟹  Nat <: ?T（实参位）
                              ?T <: Nat（@mut List 参数不变 ⇒ 反向也收）
                           ⟹  ?T = Nat
无其他冲突                  ⟹  xs : @mut List[Nat]
```
用户比拟：**类似 Kotlin 的类型合成器（builder inference）**。

**队长提炼的两条结构性结论**：
1. **可变性直接决定变构性**：`List[T]` 协变、`@mut List[T]` **不变**。理由：若 `@mut List` 允许协变，则 `@mut List[Nat]` 可当 `@mut List[Any]` 用，再 `add("abc")` 就能把 `Str` 塞进 `Nat` 列表——正是 ST-1 禁止的。这条把 P-11 的容器合成与 P-10 步骤 3 的变构性推断**硬绑定**。
2. **两种「不变」必须分开**（易混点，已写入 §3.4.1）：
   | 情形 | 例子 | 处置 |
   |---|---|---|
   | **声明位**不变（写了界）| `fun f[T: Nat](a: T, b: T): T` | **报错** `E-BOUND-INVARIANT`（界方向无法确定，猜就是静默错误）|
   | **推导位**不变（元变量）| `@mut List[?T]` 的元素位 | **不报错**：不变 ⇒ 约束为等式，两方向取交，机械可解 |

这两者看似矛盾实则不同：前者要求猜一个方向，后者两边都是约束。

## ST-13.1 视图相关变构性（00:2x 裁决）

用户裁决：变构性**看使用位置**，且**按视图分别是不同的值**——

| 规则 | 内容 |
|---|---|
| R1 | 只在形参位 ⇒ 逆变 |
| R2 | 只在返回位 / 不可变属性位 ⇒ 协变 |
| R3 | 两者皆有 ⇒ 不变 |
| R4 | 非 `@mut` 全协变，`@mut` 中有逆变位 ⇒ **`(σ_imm=协变, σ_mut=不变)`** |
| R5 | 对称情形 ⇒ `(σ_imm=逆变, σ_mut=不变)` |

**队长提炼的结构性后果**：
1. 变构性不是单值，而是**一对** `(σ_imm, σ_mut)`，由**视图**选择；
2. **单调性恒成立**：`@mut` 视图只增加使用处 ⇒ `σ_mut` 的混合程度 ≥ `σ_imm`。可作机械自检断言（P-10 步骤 3 验收 #3）；
3. 子类型后果：`List[A] <: List[B]` 要求 `A <: B`；`@mut List[A] <: @mut List[B]` 要求 `A = B`；
4. 推导后果：元变量在 `@mut` 视图下 ⇒ **等式约束**；在不可变视图下 ⇒ 按极性 `lub`/`glb`。

**反例探针（必须被拒绝，已写入 P-10 步骤 3 验收）**：
```
var ns : @mut List[Nat] = MutableListOf()
var as : @mut List[Any] = ns
as.add("abc")     // 若 @mut List 协变，则把 Str 塞进声明为 List[Nat] 的容器 → 违反 ST-1
```

**已同步三处**：ST 卷新增 **ST-13.1**（含开放问题：`@mut` 构造子自身出现在参数位时如何参与外层极性复合，待步骤 3 实测补）；P-10 计划步骤 3 新增 3.4a/b/c 与三条验收；P-11 极性表改为「按视图判定」，并明确「推导位不变 ⇒ 等式，声明位不变 ⇒ 报错」的分野（§3.4.1）。

## 减法裁决落定：Int + 证明驱动收紧（09:3x）

用户裁决：「`Nat - Nat` 应该返回 `Int`，由自动证明器进行智能转换，比方说当前环境可以证明前 `Nat >=` 后 `Nat`，就智能转换返回值为 `Nat`。」

⇒ **ST-10.1 保留不动**（t63 不退），新增 **ST-10.2**：
```
a - b（a,b : Nat）  Γ ⊬ a >= b ⟹ Int      Γ ⊢ a >= b ⟹ Nat
```
**方向是收紧**（Nat 比 Int 严），证明失败即退回 ST-10.1，**错误面不变**——这是安全的扩展。

### 队长实测三个探针，发现使能条件两个都缺
| # | 探针 | 实测 |
|---|---|---|
| 1 | `n : Nat` + `axiom n != 0` ⇒ `∵ n != 0 ∴ n >= 1` | ❌ 证不出（Γ 只有 `!=<n,0>`）|
| 2 | `if (n == 0) {} else { ∵ n != 0 ∴ n >= 1 }` | ❌ 证不出（**Γ 为空**）|
| 3 | `∵ a >= b ∴ a - b >= 0` | ✅ 通过 |

第 3 条通过 ⇒ 算术通道没问题；第 1、2 条失败 ⇒ **事实没进来**。

**最要紧的发现**：证明器**读不懂类型**——`n : Nat` 竟不产生事实 `n >= 0`。这意味着任何依赖「非负」的证明都得用户手写 `axiom n >= 0`，荒谬。这与 ADR-13 §三 推迟的「类型判定 (e:T)」是同一处缺口。
