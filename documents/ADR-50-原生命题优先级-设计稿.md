- 日期：2026-11-09

## 一 问题：为什么必须做

用户 11-09 早先裁决「中缀一律左结合、无优先级」时，我把它**过度推广**到了原生命题。实测后果：

```
fun rangeLowerBound[x, l, r]: Null <x ∈ (l..r) → x >= l>

解析为：  BinExpr >=                        ← 完全不是它看上去的意思
            left:  CallExpr →(BinExpr ∈(x, l..r), x)
            right: l
```

这条**定理的名字与内容不符**，而编译器给了绿灯。用户 Q22 裁决正是根治：原生命题有优先级。

## 二 优先级表（**核心提案**）

从**紧**到**松**：

| 层 | 算符 | 结合性 | 说明 |
|---|---|---|---|
| 0 | `¬`（前缀） | — | 作用到紧随的一个命题项（`¬<p>` / `¬p` 形态见 ADR-48）|
| 1 | 算术 `+ - * / % ^` | 左 | **单层**：`1 + 2 * 3` = `(1 + 2) * 3`（用户裁决不变，`H-ARITH-PREC` 提示保留）|
| 2 | 关系 `= ≠ ∈ <: >= <= < >` | 左 | `x + 1 >= l` = `(x + 1) >= l`；`x >= l + 1` = `x >= (l + 1)` |
| 2.5 ⚠️ | **用户定义中缀**（如 `⊗`） | 左 | 位置待确认：现提案放在关系之下、`∧` 之上 ⇒ `p f q → r` = `(p f q) → r` |
| 3 | `∧` | 左 | 结合律使结合性无差别 |
| 4 | `∨` | 左 | 同上 |
| 5 ⚠️ | `→` | **右**（提案） | 逻辑惯例 `a → b → c` = `a → (b → c)`；⚠️ 与「中缀一律左结合」的旧裁决**冲突点** |
| 6 | `↔` | 左 | 最松 |

### 效果对照（落地后）

| 写法 | 今天（全左结合） | ADR-50 后 |
|---|---|---|
| `x ∈ S → x >= l` | `((x ∈ S) → x) >= l` ❌ | `(x ∈ S) → (x >= l)` ✅ |
| `p ∧ q → r` | `((p ∧ q) → r)` ✅（碰巧对）| 同 ✅ |
| `p → q → r` | `(p → q) → r` | ⚠️ `p → (q → r)` |

| `1 + 2 * 3` | `(1 + 2) * 3` + 提示 | **不变** + 提示 |
| `¬<p> ∧ q` | `(¬<p>) ∧ q` | 同 ✅ |

## 三 三个必须由用户确认的点

### A `→` 的结合性 —— ✅ **用户裁决：右结合**
- **右结合**（逻辑惯例；`a → b → c` 几乎总被理解为 `a → (b → c)`，因为库里 `imp trans` 型定理都是这个形状）；
- **左结合**（与你早先「中缀一律左结合」保持一致，改动最小）。

实测样本里 `→` 连写：**0 处**（若你选右结合，无需迁移任何样本）。

### B 用户定义中缀的层位 —— ✅ **用户裁决：关系级**
- **关系级**（提案）：`p f q → r` = `(p f q) → r`，符合直觉；
- **最松**：`p f q → r` = `p f (q → r)`，反直觉；
- **不参与**：用户中缀与命题算符混用一律报错（最保守，但会挡掉将来算子库）。

### C 表达式层 `&` `|` 的优先级 —— ✅ **用户裁决：也定，`&` 紧于 `|`**
你裁决「表达式层一律 `&` `|` `!`」，但未说它们之间谁紧。两个选择：
- **也定** `&` 紧于 `|`（与集合论/布尔代数惯例一致：`a & b | c` = `(a & b) | c`）；
- **不定**，保持单层左结合 + 混用提示（与算术同款）。

我建议：**也定**（`&` 紧于 `|`），因为布尔逻辑里 `a && b || c` = `(a && b) || c` 是**所有人**的预期，不定优先级反而每次都要加括号。

## 四 实现要点（确认后执行）

1. **改在 `Parser` 的命题通道**：现在是「D-5 中缀糖 + 左折叠」。要换成**优先级爬升（precedence climbing）**，只在**命题位**生效（值位/类型位不受影响）；
2. **`H-ARITH-PREC` 必须保留**：算术现在虽嵌在层级 1，但**层内仍无优先级**——`1 + 2 * 3` 依旧 `(1+2)*3`，提示不变；
3. **`H-MIXED-PROP`（t76）与优先级的关系**：优先级落地后 `x ∈ S → x >= l` 被**正确定义**，不再需要提示；但 `(a & b) | c` 之类的**同类混用**提示仍有用 ⇒ t76 的规则转成「**层内**混用提示」；
4. **回归要求**：
   - 全量测试只增不减；
   - **68 样本 HIR JSON 必须逐字零 diff**（优先级只影响**原本被误解析**的形态；若某样本因此变了结构，**该样本就是错的**，要作为 finding 报出来，而不是默许 diff）；
   - 新增测试至少覆盖上表「效果对照」的六行。

## 五 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| **大面积解析树变化** | 任何现有命题的树都可能变 | 68 样本 JSON 逐字比对 + 逐条 finding |
| 与旧裁决表面冲突 | 「中缀一律左结合」vs 「原生命题有优先级」 | 按**用户定义中缀 vs 原生命题**分层：前者左结合无优先级，后者按本表 |
| 括号语义 | AST 无 `ParenExpr`（已知债务）| 本次不动，仅作为层级重置记录在**令牌深度图**（沿用 ADR-47 机制）|
