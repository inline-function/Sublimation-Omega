## 1 @mut 可变性推导主体（R-06 机理设计）

### 1.1 触发清单（P-11 §5 + 边界补全）

| # | 触发 | 当前对应物 | 提升目标 |
|---|---|---|---|
| T1 | 局部变量被**声明初值式之外**赋值（理念文档原话「二次赋值」） | `AssignStmt` 名字位（:1518） | `SymbolEntry.mutable=true` + 视图 `@mut T` |
| T2 | 形参被赋值 | 同上（形参 declare 位 :4284） | 形参符号 mutable + 形参类型升 `@mut T`（R-06 原话「提升出的 @mut 即形参推导类型」） |
| T3 | 形参/变量被传入 **@mut 接收者位** | 调用签名核对（R-15 接收者闸，§2.2） | 同上——**需 R-15 方法面落位后才有此触发** |
| T4 | 字段被赋值 | `fieldWriteOk` 字段闸 | **不提升**——C-5：字段层声明制（t98 已落字段级 @mut 为类型层事实） |

### 1.2 机制：单调闭包，共用赋值通道

判据位与生产位的关系（本提案的核心机械决策）：

- **共用赋值通道**（任务书面裁决）：判据读既有的 `AssignStmt` 名字位写闸通道（:1516-1530）——该位已经在查 `SymbolEntry.mutable`，提升只需把「断言 mutable」从**声明时 one-shot** 改为**使用处单调累计**。零新 walker、零新遍历秩序（同 t122 闭包/t123 上提复用既有边的纪律）。
- **二次扫描 vs 轮内回填**：变量 mutable 位今天是**声明期**写入（:1495、:1501-1502：`"mut" in s.annotations || declared is HirMutType`），而 T1 触发发生在**声明之后**的语句位。两个形态：
  - **形态 A（轮末回填，倾向）**：mutable 位改 `var`（同 t123 `preps` 口径），AssignStmt 名字位在脚本模式记录 `mutDemands[name] = pos`（证据尝试清单，同 D-LIFTED-CONTEXT 的 `tried` 口径）；轮末（或函数体出栈位）单调回填符号 + HIR 视图。**单趟主遍历 + 一次回填**，无中途类型漂移（类型通道不受影响——@mut 只影响写权限与变构位，不影响 adaptOk 的主结论）。
  - **形态 B（双趟）**：先扫使用处再重声明——破坏「树即一遍」的 walker 纪律（I-1 A 方向背道而驰），**不取**。
- **单调性**：mutable 只加不减（P-11 §5 原话），无冲突格、无不动点振荡——比纯度闭包（t122）更弱：**不需要 R 轮**（纯度闭包跨函数传播必须轮；可变性触发起终在同一函数体的词法序内，唯一跨函数形态是 T3 形参提升 ⇒ 调用者位看签名——这落在签名通道，同 t123 preps 的处理）。若 T3 与 T2 交叉出现环（f 的形参提升因 g 的 @mut 接收者位，g 又调 f），复用 R 轮天然消化（轮内累计、轮末回填），**不为可变性新开轮次预算**。
- **与 R-17 的轴别**：R-17（§3.4）是**效应轴**（@ref @mut × @mut 方法 ⇒ 不纯种子，入 t122 闭包第五类）；本节 R-06 提升是**写权限轴**（mutable 位）。两轴独立——提升出的 @mut 形参被 `&`/`@ref` 借走再调 @mut 方法时才触发 R-17；值语义深拷（无 @ref）永不触发。S5 实现件的状态机按「写权限轴（§1）× 效应轴（§3.4）」两象限画，不得合并判据。

### 1.3 推导 vs 声明的界（R-06 + C-5）

| 载体 | 脚本模式（.subs） | 工程模式（.subl） |
|---|---|---|
| 局部 var | **自动提升**（T1） | 声明制：`@mut var` 或 `@mut T`（E-IMMUT-ASSIGN 冻结逐字不变） |
| 形参 | **自动提升**（T2/T3）——提升结果入形参推导类型（C-8 provenance 族：`inferred`+`evidence`，同 t108 最小集） | 声明制：`a: @mut T`（注意：**当前即便显式标 @mut 形参也不可写**——§3.2 判据不对称，OQ-3） |
| 脚本顶层 var | **自动提升**（R-06 同族；脚本顶层是 root 帧的局部） | n/a（工程模式无顶层语句） |
| 结构体字段 | **不提升**（C-5：字段层声明制——字段是数据契约，t98 已落字段级 @mut 类型层事实） | 声明制（已落） |
| 容器类型位（`List[T]` vs `@mut List[T]`） | **不自动提升**——类型族的视图是确立型（§3.3 红线） | 声明制 |
| 混标（脚本里显式写 @mut） | 标注作**约束**参与（P-11 §2 口径）：显式 @mut 单向蕴含推导位（写了就不必再触发），不覆盖、不冲突 | n/a |

### 1.4 HIR 载体与审计

- **载体最小集**（C-8 纪律，schema 保持 v3）：
  - 符号侧：`SymbolEntry.mutable` 回填（内部态，不入产物）。
  - HIR 侧：`HirVarStmt`/`HirParam` 携带的视图类型升 `@mut T`——**不新增字段**（复用既有类型树形态，同 t123 合成 prep 走既有 HirPAtom 的口径）；推导元信息走 t108 的 `inferred`+`evidence` 两尾参（触发位列表 = 证据尝试清单）。
- **观察级四元组**（同 t122/t123 审计族口径，OQ-4 同族）：`D-MUT-INFERRED`——函数/变量名 + 提升视图原文 `<@mut T>` + 触发分类（二次赋值 / @mut 接收者位）+ 证据尝试清单（赋值位 `名@pos`）。supplement 级、不进冻红、`--no-lift` 同族门未涉（可变性提升无「健全性绕过」风险——它只开写权限，不开类型开口，**OQ-6 倾向不给门**；给门与否留队长裁）。
- **产物级零新增**：68/14 样本零 @mut ⇒ 工程模式产物逐字不动；脚本模式提升样本入差分对拍（护栏③扩面，同 t123 dp-lift-chain 口径：忽略 `inferred`/`evidence` 后结构签相等）。

### 1.5 工程模式接驳（.subl 基线零风险的机械保证）

提升通道处处门控 `scriptMode`（同 t115 元变量的 :608/:620 位、t123 gateLift 的 :3411 位）：`if (!scriptMode) 既有路径逐字`。写闸 `E-IMMUT-ASSIGN` 两种文案（名字位 :1528、字段位 :2909/2914）**零变动**——T98 16 测、T107 12 测（含「捕获可变形参必拒」）逐字冻结为回归保护。

## 2 R-15 容器面落点

### 2.1 `trait List[T]` 住哪——三形态评估

| 形态 | 描述 | 代价 | 倾向 |
|---|---|---|---|
| **A 沿用扩展函数桶** | 方法位 = 扩展函数 `fun (List[A]).add(x: A)` 的 `FunDecl.annotations` 标 `@mut`；接收者闸挂方法糖改道位（callExpr 的 FieldExpr 分支 :2446-2487，已在 `extCallType` 前查接收者视图） | 零新表：方法糖分派、签名核对、可见集遮蔽全既有；prelude 方法以虚拟 FunDecl 注入 `SymbolTable.extFuns`（同 preludeMethod/preludeFun 的 Kotlin 表口径，不落产物） | **推荐**（最小变动、与「方法糖=扩展函数」的 TS-12 既有裁决一致） |
| B 虚拟 trait 声明 | PreludeDecls 增 `trait List[T]` 虚拟声明 + 成员表，接收者闸读 trait 成员注解 | 需新走 trait 解析通道（当前 trait 只用于命题面/变构面，无 impl 方法分发——S-5 无特质 impl 方法，消解闭名单 1 :2450 已写死该事实） | 多造一层无分发用途的声明 |
| C 标准库 .subl 源（S2 阶段） | 标准库规划 §5 的 S2/S3：核心库迁本语言源码 | 依赖模块系统（未落） | 与本件无关，登记不落 |

**结论**：**A 形态**——「trait List[T]」的**类型位**已存在（`List[T]` 虚拟联合别名 + 虚拟 struct Nil/Cons）；R-15 新增的只是**方法位标识与接收者闸**，两者都挂在既有扩展函数/方法糖通道上。命名统一（C-7 队长裁 PascalCase）：`MutableListOf()` / `ListOf()` 入 prelude 自由函数族（SymbolTable:399-403 的 `PRELUDE_FUNS` 表——返回 `@mut List[T]` 的 T 新鲜元变量是 §2.4 的事）。

### 2.2 @mut 标方法的接收者闸（诊断口径）

- **判据**：方法糖改道位（:2461-2482）在 ext 桶命中且方法带 `@mut` 注解时，核接收者静态类型视图：`viewKindOf(recvT) == MUT`（即 `@mut List[T]`）放行；`PLAIN`（`List[T]`）/ `REF`（`@ref List[T]`）⇒ 拒。`@ref @mut T` 写穿透放行（同 isWritableView :350-354 口径）。
- **诊断码**：【R-18 终裁更新】@mut 方法的**接收者闸 = `E-IMPURE-REQUIRED`**（未注 @impure 且无 unchecked 前缀 ⇒ 红码文案「纯函数不能调用 @mut 方法 `add`——要改它？给调用方标 @impure，或调用位写 `unchecked`（S-25）」）。**类型位**另有一道既有闸：去糖形参 `@mut @ref T` 的拒绝格（`T → @ref @mut T` 落 E-TYPE-MISMATCH，borrowView:398）——视图不达的方法调用到不了纯度位。原 OQ-1 的 E-IMMUT-ASSIGN 复用/E-IMMUT-METHOD 单立之争**随 R-18 收口**：纯度闸即接收者闸，不再单立视图闸。
- **只核最后一跳**（同字段写闸既有口径，讨论稿 §4 漏风 #2 已登记为既有边界，不在本件扩）：接收者表达式静态类型即判据，不做别名/嵌套链分析。

### 2.3 `List[T]` vs `@mut List[T]`：视图与深拷通路（R-01 表 + R-14）

- **视图语义不改矩阵**：`@mut List[T]` 是 `HirMutType(NamedType List[T])`——16 格逐格不变（copyDispatch :388-393 对 want=MUT 一律深拷、want=REF 视图共享）。R-05 原话「容器无特殊语义」机械保住。
- **R-14 深拷递归到元素层**：当前 `copyDispatch` 是**整树视图判定**（want 持 @ref ⇒ 共享；否则深拷），不问泛型实参。R-14 要的是「`@mut List[@mut T]` 的深拷递归到元素」——前端只落**类型层判定**（实际深拷随后端运行时，R2 §三 既有口径）：判定函从布尔升级为**递归判定**——want 不持 ref 且源持可写视图时，返回「深拷」并**递归到元素位**（`@mut List[@mut T]→List[T]` 的元素格单算）。机械落点：`copyDispatch` 增元素位递归分支（`HirQualifiedType.args` 逐参 `copyDispatch(argGot, argWant)`），产物留痕 `D-REF-DISPATCH` 文案挂元素层结论。**注意**：判定从布尔变（布尔+元素表）是**签名变动**——`赋值语义矩阵` 16 格文档逐格不变（顶格局），新增的是元素层结论，T99 矩阵测扩充（护栏③）。
- **`List[T]` 与 `@mut List[T]` 的互传**：`@mut List[Nat] → List[Nat]` 深拷（want=PLAIN、got=MUT）、`List[Nat] → @mut List[Nat]` 造格深拷（want=MUT）——R-01 表格 02/05 的容器版，无新格。

### 2.4 类型合成（`MutableListOf()`，P-11 §5.1 已裁）

- `MutableListOf()` ⇒ `@mut List[?T]`，?T **新鲜元变量**（不是 Nothing——可变容器不变性需要等式约束闭合）；`xs.add(1)` ⇒ 传 `@mut` 接收者位 + `Nat <: ?T` 与 `?T <: Nat`（不变 ⇒ 双向）⇒ `?T = Nat`。
- **落点**：`MutableListOf`/`ListOf` 入 `PRELUDE_FUNS`（prelude 自由函数族，零实参重载形态）；?T 元变量复用 t115 meta 机制（`slotOf` 增一槽位族 `CONTAINER_ELEM`？或复用 RET 槽按调用位归属——**OQ-2**：元素元变量的归属形态，倾向「表达式结果位的 var 元变量 + add 调用位约束」，不新开槽族——`var xs = MutableListOf()` 的 xs 元变量（VAR 槽）在初值位接 `@mut List[?T]`，?T 挂在 xs 的证据链上）。注意 t118 已落「无证据回落」：`var xs = MutableListOf()` 无 add ⇒ ?T 无证据 ⇒ 回落 `Nothing` ⇒ `@mut List[Nothing]`（P-11 §5.1 表第三行，健全：add 仍可后续写）。
- **变构联动已就位**：`@mut List[T]` 不变——`BuiltinVariance.TABLE` 的 List 双格（CO_INV）+ `genericArgsByVariance(useMut=true)` 已经在按视图分派（TypeInfer:410-412）。R-15 落地**零变动**变构表。

## 3 判据边界

### 3.1 R-07 捕获（类型位 @mut）与 R-15 方法位 @mut 的交互

- **OQ-10 已裁（S4 提案）**：R-07 只读**类型位** @mut（containsMutT:3126），R-15 方法位 `@mut` 标识**不产生新纯度判据**——调用 `xs.add(1)` 的不纯性来自既有通道（方法体若是用户扩展函数，其 @impure 由 t96 闸管；内建 `add` 若入不纯名表则照旧）。本件**写死该边界**：接收者闸只核视图，不回写纯度。
- **R-17 补位**（队长 2026-11-12 亲述，§3.4）：纯度与可变性的交点**只有一处**——`@ref @mut T` 上调 @mut 方法。R-07（外部捕获）与 R-17（实参按引用传入）同族不同源，判据互不重叠（§3.4 状态机）。

### 3.4 R-17/R-18 落档（队长 2026-11-12 亲述+终裁）——@mut 方法的纯度纪律

**R-17 原话**：「不准在纯函数中修改状态，意思是如果要在函数 f 中对 @ref @mut T 调用它的 @mut 函数，f 需要标注 @impure；没有带 @ref 是深拷贝语义，不影响原值，因此没有副作用。」
**R-18 终裁（五点）**：

1. **去糖模型**：`fun T.f()` ≡ `fun f(self: @mut @ref T)`——接收者=**借用可变视图**（天然在 R-17 @ref 线上；附录登记去糖形态）
2. **方法体写接收者字段 = 变更原语，不要求 @impure**——罪恶在调用边界，不在方法体内
3. **调用 @mut T 的 @mut 方法 ⇒ 调用方 @impure，或调用位加 `unchecked`**（既有 S-25 语句级前缀，零新语法）
4. **V1 一刀保守**：深拷实参上的 @mut 调用**照门**（副作用实际未逃逸，但初版不做分析）；**逃逸分析留后版**（证「未逃逸出函数」的调用放行）——未来优化，不堵 V1
5. 旧样本注释「参数位不深拷」是**旧行为**（R-17 已改深拷语义）——S5 件内更正（注释级，产物零变）

**判据状态机（按 R-18 1-4 重画——本提案 §3.4 初版按 R-17 的「深拷豁免」行被 R-18.4 收回）**：
