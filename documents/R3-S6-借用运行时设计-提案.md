## 1 `&` 表达式语义（R-01 锁定口径的机械模型）

R-01 原文（任务书 §1）：「`f(&list)` 与 `f(list)` 并存时后者深拷贝；**形参视图由函数体推导**，
`&` 为**调用点开关**」；落点写明「t99 copyDispatch，**want 合成 `@ref <形参视图>`**」。

### 1.1 want 合成模型（got 不动，want 加衣）

```
脚本模式（无注解位）：
  var list = MutableListOf(1)              ⟹ list : @mut List[?T]（虚拟构造族 + 元变量）
  fun f(list) { list.add(0) }              ⟹ 形参视图由体推导：@mut List[a]（T3/等式通道，S5c 已落）
  f(list)                                  ⟹ want = @mut List[a]（形参视图原样）
                                              copyDispatch(got=@mut List[?T], want=MUT)      = 深拷 ✓ R-01「后者深拷贝」
  f(&list)                                  ⟹ want = @ref @mut List[a]（合成 @ref 衣）
                                              copyDispatch(got=@mut List[?T], want=REFMUT)  = 共享 ✓ R-01「借用分享同一引用」
```

**判据归属（锁定）**：`&` 不是值类型的一部分，是**调用点的 want 侧开关**——合成发生在 want，
got（实参静态视图）逐字不动。三种机械方案评估：

| 方案 | 机械 | 评估 |
|---|---|---|
| **A：want 合成**（R-01 落点原文） | 实参位 adaptOk(borrowView(got, **refWrap(want)**)) | ✅ **采用**：与锁定口径逐字一致；got 侧零改 ⇒ recordCallArgs 记录的是剥离借用的形参视图（元变量通道不受污染，§5.1）；矩阵 16 格直接复用（REFMUT 行Want） |
| B：got 包装 | HirBorrow.type = `@ref <operand 视图>`，etype 走带衣类型 | ❌ 形参会解到带 @ref 的视图 ⇒ 体内 `list.add(0)` 的接收者核对需再剥衣 ⇒ 与「形参视图由体推导」冲突；且元变量下界带衣污染 callee 签名合成 |
| C：共享旗标位 | HirCall 加 shareArgs: List<Boolean>，旁路 adaptOk | ❌ 旁路类型核对 ⇒ 矩阵两拒绝格（T → @ref @mut T）失守——不可变值借入可写引用必须落 E-TYPE-MISMATCH |

A 的**合成函数**：`refWrap(want) = if (viewKindOf(want) == PLAIN) HirRefType(want) else want`——
仅 PLAIN 形参加 @ref 衣；形参视图已含 @mut（或 @ref）时**衣融**：`@mut T → @ref @mut T`、
`@ref T → @ref T`（折叠，见 OQ-4 嵌套 @ref 折叠规则）。

**边界（矩阵两拒绝格的借用面）**：

| got（实参视图） | want 合成后 | copyDispatch | 判据 |
|---|---|---|---|
| T（不可变） | @ref T | 共享 :150 | 无罪（借不可变入只读视图） |
| T（不可变） | @ref @mut T | **拒绝**（矩阵未给格，按不安全侧） | E-TYPE-MISMATCH——「不可变值不能借入可写引用；先 `var m : @mut T = v` 造格再借」 |
| @mut T | @ref @mut T | 共享 :113 | R-01 主用例 |
| @mut T | @mut T（无 &，对照） | 深拷 :104 | R-01 后者深拷 |

### 1.2 生命周期与别名口径（本语言无生命周期系统）

ADR-53 已锁定「无生命周期系统」（双重借用拒绝文案即此口径）。S6 语义层据此定**别名形态**：

1. **零生命周期、零独占性**（非 Rust 借用）：`&` 只表达「此次调用共享对象身份」，编译器**不跟踪别名集**、
   不要求唯一借用。`f(&x, &x)`（双实参同借一变量）合法——运行时别名行为由后端观测口径管，前端不门。
2. **单向视图传递（无回写绑定）**：形参重绑定（`list = Cons(0)`）**不穿透**回调用方变量名；
   字段写（`list.n = 1` / `list.add(0)`）**穿透**（共享对象身份的写效应）——与根文档 :113-117
   「`b.n = 1` 后 `a.n` 是 1」同源。前端不证穿透（运行时对象图），只按 R-17/R-18 纪律门效应。
3. **借用不延寿**：`&` 的共享仅在调用生命周期内语义有效；返回值/逃逸形态（`fun g() = &x` 类）
   **当前不存在**——`&` 只在实参起始位（R-04.1），返回位/初值位无 `&` 语法 ⇒ 零逃逸形态面。
   后版若开 `@` 逃逸通道须先裁生命周期项（范围外登记，OQ-9）。

### 1.3 形参视图回写（callee 侧 HIR 载体）

「形参视图由函数体推导」的推导结论已由 S5 系落进 HIR：
- 省略型形参元变量解 → HirParam.type + inferred/evidence（t108 载体）；
- 可变性提升 → promotedView(`@mut` 衣入签名，S5b/S5c，含 T3「传入 @mut 接收者位」）。

**S6 增量（评估）**：调用 want 合成读的形参视图 = 这些既有载体，**零新字段**；仅当终轮回放态
（§3 warn）需要「形参是否曾被借用」的可观察量时，**或**需 HirParam 加借用标记位（OQ-5 形态裁）。

### 1.4 方法糖接收者位的视图形态（S5c 定序项收口）

R-18.1 去糖模型：`fun T.f()` ≡ `fun f(self: @mut @ref T)`——接收者 = **借用可写视图**（REFMUT 语义，
队长原文嵌套序 MUT(REF(T)) 不可写、实现按 REF(MUT(T))，S5c 已登记机械定序项）。

S5c 虚拟 `add` 的 receiver 形参当前是 **`@mut List[a]`（MUT）**——即接收者走「深拷实参」口径
（want=MUT ⇒ 矩阵深拷行；不可变接收者经 borrowView demoteView 放行后深拷成可写副本——
R-18.4 V1 一刀的同族保守态）。两条收口路：

| 路 | 接收者 want | got=PLAIN List | got=@mut List | 评估 |
|---|---|---|---|---|
| **现状（S5c 落）** | @mut List[a]（MUT） | demoteView 放行（深拷副本） | 深拷 :104（R-01 无 & 侧） | ✅ 已验收（1043/1043、SAME 68/68）；但与 R-18.1 「接收者=借用」不一致——写效应实际不穿透源（深拷），R-17 判据仍照门（V1 一刀自洽） |
| **R-18.1 定序项** | @ref @mut List[a]（REFMUT） | **两拒绝格**（T → @ref @mut T）⇒ E-TYPE-MISMATCH「不可变接收者不能调 @mut 方法」 | 共享 :113（接收者借用，写穿透源） | ✅ 与去糖模型逐字一致、与 R-17 @ref 线同源；样本零冲击（68+14 零方法糖）；但**改矩阵落点**：不可变接收者从「深拷放行」变「类型位先拒」——需队长裁（行为变红，非纯重构） |

**倾向**：**现状保留，定序项登记 OQ-1**——R-18.4 V1 一刀（判据不看实参视图）在 MUT 接收者形态下
自洽（深拷后写副本，效应不逃逸，纯度照门）；REFMUT 接收者是后版「回到 R-17 二分」的同期件
（开逃逸分析时一并）。**若队长裁 R-18.1 定序项先行**：改动面 = PreludeDecls 虚拟方法 receiver 一行 +
T99 矩阵测试两格挪位（不可变接收者 E-TYPE-MISMATCH 红例），验收复用既有门。

## 2 R-01 矩阵运行时通路（三落点，复用 CopyDecision 不重造）

分派的三个消费位点与现状：

| 落点 | 判据通道 | 留痕 | 状态 |
|---|---|---|---|
| **var 初始化位** | HirVarStmt 侧 refDispatchNote（Elaborator:1565-1568） | D-REF-DISPATCH | **已落**（t98/t125，含 R-14 元素层附录） |
| **赋值位** | HirAssign 侧 refDispatchNote（:1617-1623） | D-REF-DISPATCH | **已落**（同上） |
| **调用边界（实参位）** | adaptOk(got, borrowView(got, **refWrap(want)**))（TypeInfer:1197 借用口径位） | **零** | **本件落**（§2.1） |
| 容器元素位 | R-14 elementDecisions（copyDispatch 内递归） | 随顶层 D-REF-DISPATCH 附录计数 | **已落**（t125，借用态边界见 §2.2） |

### 2.1 调用边界落点设计

**机械位**：callExpr 实参批次（Elaborator:2541-2543 / :2588+ 既有结构）——
`val args = …map { expr(it) }` + `val argTypes = args.map { etype(it) }` 之后、
sigCheckedCall/extCallType 之前，**逐实参**：

1. **登记借用边**（mutMethodCalls 同款注册表，非产物通道）：`borrowArgs[nid] = argIndex`（实参为 HirBorrow 时）；
2. **want 合成**：将 refWrap 施于 callee 形参视图（仅登记位实参；零借用位数零改——SAME 门机械保护）；
3. **分派留痕**：对每个 HirBorrow 实参落 copyDispatch(got, refWrap(want))——**note 挂在哪**：
   - 方案 i：挂 HirCall.notes（节点级，多借用实参合并成一条「逐实参」附录式 note）；
   - 方案 ii：挂 HirBorrow.notes（实参级天然对齐——每借一 note，无合并问题）。
   **倾向 ii**：实参级对齐、与 HirBorrow 同源；D-REF-DISPATCH 码逐字复用（refDispatchNote(
   `(e.pos)`, got, refWrap(want), "借用实参 i")），文本形态=`借用实参 i 视图分派：…`——
   与既有「<what> 视图分派」前缀字节同族（what 位参数化，零新码）。
4. **nid 幂等纪律（ADR-57 实装陷阱复述）**：argTypes 既有局部量复用，**不得二次 etype**；
   refWrap 合成类型走既有 freshNid-free 结构（HirRefType 壳复用内层 nid? 否——HirRefType 是
   壳节点无独立 nid，零消费）。⇒ 借用零命中时全文件 nid 序列不变——SAME 门逐字保护。

**工程模式**：`&` 在解析层已拒（R-03，t101 落），want 合成通道在工程模式**恒空**（零借用实参）；
工程侧引用语义继续走 @ref 注解位既有四规则（t98，冻结）——零交叉。

### 2.2 容器元素位的借用态边界（R-14 已落件的借用面）

R-14 elementDecisions 的下钻条件是「顶层 deep」；借用态下：
- `f(&list)` 共享路径（want=REFMUT 且 got=MUT ⇒ top=false）⇒ **零下钻**（元素随整体共享，
  矩阵「共享 ⟺ 目标持引用」的整对象语义——元素位不可能单独深拷）——既有逻辑天然覆盖，零改；
- `f(list)` 深拷路径（want=形参视图 @mut List[a]，top=true）⇒ 元素层下钻既有（t125）。

**边界**：借用合成 want 嵌套容器（`@ref @mut List[@mut Box]`）时，元素层递归以合成后的 want
为输入——元素位元素的 @mut 视图随顶层共享（R-14 文档「共享路径零下钻」同源口径）。零新判定。

### 2.3 形参视图推导的借用证据（recordCallArgs 通道）

recordCallArgs（Elaborator:750-768）为省略型形参收**下界**：实参类型源序登记。want 合成模型下
（§1.1 方案 A），**登记的 got 是剥离借用的形参视图**（HirBorrow 的 etype 透传内层——t101 既有
形态天然满足：`etype(HirBorrow) = 内层类型`，零改）。⇒ 元变量解不被 @ref 衣污染、
P-11 §5.1 双等式取交（`xs.add(1)` ⇒ `Nat <: ?T` 与 `?T <: Nat` 双向收）**逐字复用**——
借用是 want 侧开关，不进推导。**这是选方案 A 而非 B 的决定性机械理由**。

## 3 warn 与诊断族（任务书「warn + copyDispatch 联动」）

### 3.1 既有口径（复用，零改）

- **D-REF-DISPATCH**（SUPPLEMENT，t98/t125）：`<what> 视图分派：r(got) → r(want)（深拷隔离…/
  共享同一对象…）（前端类型层判定，实际深拷随后端运行时，R2 §三）`——what 位参数化
  （既有「var 名」/「赋值」），S6 加「借用实参 i」同族前缀（§2.1）；
- 诊断级位：WARN 级存在（Severity WARN，W-* 码族先例：W-EXT-OBSOLETE / W-NON-EXHAUSTIVE /
  W-PROP-UNBOUND）；S6 新族按 W- 前缀落（非 D-，与任务书「warn 级诊断」逐字一致）。

### 3.2 新族：W-BORROW-REDUNDANT（R-04.3 只读形参位 `&` 落 warn）

**触发判据**：调用点实参为 HirBorrow，且 callee 对应形参的**推导/声明视图不是可写视图**
（`!isWritableView(paramView)`——形参未解出来时**不落**（无证据不 warn，同 R-02 退化纪律））。

**语义**：形参不可写 ⇒ want 合成 `@ref T` vs 无 & 的 want `T`——两格皆共享（:150 / :155），
`&` **零语义差**（无深拷可省）⇒ warn 提示冗余。文案（建议，自身可编译 ADR-48 §八）：
`借用 `&` 冗余：形参 `f` 的参数 `x` 未被推导为可写视图——本次借用不省任何深拷（去掉 & 等价；R-04.3）`。

**机械位（终轮回放态——同 t122 gateReplay 阶段 2 同构）**：形参视图要等 callee 体推导收敛才知，
warn **不能在单趟 expr() 内落**——必须终轮回放：
1. expr() 期：borrowArgs 注册表（§2.1）记 (callNid, argIdx, calleeName, pos)；
2. runPurityGate 终轮（既有相位，gateReplay 同体）：遍历 borrowArgs，查 calleeDecl 形参位视图
   （HirParam.type / 符号表形参视图），非可写 ⇒ diag.warn("W-BORROW-REDUNDANT", …)。

**零命中证明（SAME 门）**：68+14 样本零 HirBorrow（t101 验收口径）⇒ 注册表空 ⇒ warn 零落 ⇒
产物零漂移。脚本门（14 subs 双编译）同。差分对拍扩量：新增借用样本对（`f(&list)` vs `f(list)`
同源 .subs/.subl 双门）验证 want 合成双形态——S6 件内拟 4-6 对拍样本。

### 3.3 新族：W-BORROW-IMMUTABLE（评估项，OQ-6）

对偶 warn：got 侧可写但**未借用**且 want=可写视图（`f(list)` 深拷形参生效）——深拷是用户主动
选择，**倾向不 warn**（语义正确非冗余；矩阵 :89/:104 例证形态）。若队长要「可省深拷提示」
（建议加 `&` 可免深拷），再裁码族与文案。**本件倾向不落**——warn 族最小化（任务书只点名 R-04.3）。

### 3.4 诊断族总表（S6 件后状态）

| 码 | 级 | 触发 | 形态 | 状态 |

| D-REF-DISPATCH | SUPPLEMENT | @ref 涉及的分派位（var/assign/**借用实参 i**） | 四元组（码+文案+got+want 渲染） | 既有 + §2.1 扩位 |
| W-BORROW-REDUNDANT | WARN | 借用实参 × 形参非可写视图（终轮回放） | 实参位 + 形参名 + callee 名 + 判据口径 | 本件 §3.2 |
| E-TYPE-MISMATCH | ERROR | 不可变值借入可写引用（矩阵两拒绝格） | 既有码 + 建议文案（先造格再借） | 既有（borrowView 两拒绝格） |

### 5.1 t96 双等式取交（P-11 §5.1）

### 5.2 R-07 捕获 @ref 形态（根文档 :142 口径评估）

根 :142「引用与可变一样不可预测，因此在上下文中享有和可变相同的待遇」；t98 规则 4 已按此落
命题待遇（E-PROP-VIEW warn）。**R-07 捕获的 @ref 面现状**：containsMutT（Elaborator:3225）
`@ref T` → 递归 inner → 无 @mut ⇒ **不触发捕获**；`@ref @mut T` 触发（inner @mut）。

| 形态 | 现判据 | :142 口径判据 | 评估 |
|---|---|---|---|
| lambda 捕获 `@mut T` | 不纯（t107 已落） | 同 | ✅ |
| lambda 捕获 `@ref @mut T` | 不纯（inner @mut） | 同 | ✅ |
| lambda 捕获 `@ref T`（只读视图） | **纯** | **不纯**（引用不可预测——″背后可经别名变″） | ⚠ **行为分歧**——OQ-2 裁 |

**红面风险**：`@ref T` 视图的捕获从纯翻不纯 ⇒ 68 样本需复测（t98 度量 @ref 分布为 0 fire，
但样本捕获面未专项度量）；**倾向**：按 :142 同计（根文档原文 + 规则 4 已同口径），但**先度量再翻**
（R2 闸族「报告态→硬拒」两阶段纪律同形：先度量 68 样本 fire 数，超阈报队长）。机械位极小
（containsMutT 加 containsRef 分支或并表）。

### 5.3 R-17 第五种子类（引用可变调用）与借用逃逸

- 种子第 5 类（S5c 已落）：`@mut` 方法调用在纯函数体内 ⇒ 推导 impure（D-PURITY-INFERRED
  种子源「引用可变调用」）。**借用面**：`f(&list)` 进入 callee，callee 体 `list.add(0)` ⇒
  种子第 5 类燃（callee 不纯）⇒ **纯调用方 g 调 f ⇒ 既有 E-IMPURE-CALL 传播**（t122 闭包单调
  不动点）——**零新通道**；
- unchecked 三路：调用位 `unchecked xs.add(1)` 既有降闸帧（S-25）；**借入链上的 unchecked**
  （`unchecked f(&list)`）同形（语句级前缀包住调用语句）——既有通道，零新语法；
- R-18.4 V1 一刀对借用面的覆盖：判据不看实参视图 ⇒ **深拷实参的 @mut 调用照门**——

  callee 自己被种子第 5 类推导为 impure ⇒ f 的 @impure 化使调用方门燃——同既有机械，零改。

### 5.4 t98 E-IMMUT-ASSIGN / 工程冻结

### 9.2 过程发现与处置

1. **零命中机械保护被急切求值破（修复）**：初版 borrowArgNotes 的形参视图实参在调用点无条件求值——type(ext.receiver)（虚拟 add 签名引用理论参数 a）在理论域外解析落 E-UNBOUND-NAME「未知类型 a」，g-base 无借用探件即红。修复：零借用快路径 + 理论域 enterTypeParams 包裹。**经验：Kotlin 严格求值下「注册表快路径」必须放在调用点而非函数体首**。
2. **refWrap 单层折叠不足（修复）**：初版 HirRefType(want.inner) 对 @ref @ref Nat 只剥一层仍叠一件（探件 j 红面抓到）——改 while 逐层落至最内层。
3. **t101 测件演进（有意覆盖）**：BorrowInertTest「零借用相关诊断」断言被 R-04.3 落地覆盖——演进为「仅 W-BORROW-REDUNDANT 一条 + D-REF-DISPATCH 留痕」正向断言（测件名与文档注释同步更新；测件总数不降）。
4. **git stash 往返的 CRLF 陷阱（处置）**：调试期经 git stash/pop 后主源文件行尾被 autocrlf 规范化为 CRLF——多行锚点替换随后全部 miss。处置：编辑脚本统一按目标文件实际行尾拼接锚点（保持现状不改换行风格）。
5. **工具件登记（后版）**：(a) 工程模式 & 仍由解析层 E-SYNTAX 拒（R-03 冻结，与 §2.1 工程面口径一致）；(b) unchecked 块形态静默异形（OQ-3 原登记）在探件 e 中确认仍存——借入链 unchecked { bump(&xs) } 块形态不降闸帧，与 S5c 登记同根，留后版；(c) 形参为理论参数位（fun List[a].add(v: a) 的 v）时 warn 经 borrowArgOk 前置过滤免（理论参数未代入位核对不成立）——与 R-02 退化纪律同源，登记后版观察。
