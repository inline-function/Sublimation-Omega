## 1 元变量生成

### 1.1 四空位与可省性（语法层先决）

| 空位 | AST 现状 | 提案 |
|---|---|---|
| 形参 | Param.type: Type **非空** | 改 Type?；parseParams 无冒号分支允许省略（替换既有 errType）；工程模式由语义层落 E-OMITTED-TYPE（OQ-1：工程口径——硬拒 or 警告） |
| 返回 | FunDecl.retType: Type? | 零改 |
| 字段 | 同 Param（struct fields 复用） | 随 Param 改 |
| 局部变量 | VarStmt.type: Type? | 零改（现行 varAnnotated 已是「单点推导」；扩展点在 §1.4） |

**为什么放语法层而非语义层造哨兵**：parseParams 现在的 errType 是**语法诊断**；让语义层看到「未标注」必须先让语法接受它——否则 E-SYNTAX 先行截断，推导面根本不出现。省略形态在工程/脚本都允许解析（解析器不知模式，D-12 真值单源），工程模式处置留给语义层（OQ-1）。

### 1.2 元变量本体

- **内存对象，不入 HIR**：InferMeta(kind=空位种类, declPos, name)——带**来源位置**与**空位种类**（P-11 §3.1 可追溯义务），存于 Elaborator 的元变量登记表 + 符号条目可变槽。
- **不贡献 nid、不落 JSON**（t110 零 nid 纪律同源）：最终产物只有「解出的类型 + inferred=true + evidence 位表」，皆走既有 t108 载体字段——**JSON 只增不漂**的硬约束复用。
- 符号表交互：fun/struct/脚本顶层 var 在 collectFile 预登记（:31）——元变量挂在这些**已登记条目**上；局部 var 挂局部帧。使用位点查符号时若槽位为元变量，见当前解（解可能 ⊥-种 / 部分解，§2.3）。

### 1.3 约束从何处来（使用点位态 × 四空位）

复用 P-11 §3.2，落到本前端既有判定函数（**复用 adaptOk/subtypeBody 语义，不另立判据**）：

| 使用点位态（锚点） | 约束 | 方向 |
|---|---|---|
| 调用实参 callFun（TypeInfer :938 / instCall :1061） | typeof(e) <: ?α | 形参下界 |
| 函数体需 τ 的位置（binExpr :872、字段访问 :343…） | ?α <: τ | 形参上界 |
| 返回位 returnStmt（:1196）/funBody（:1214） | typeof(body) <: ?β | 返回下界 |
| 调用方下游消费（ret 值进算术/比较/实参） | ?β <: τ | 返回上界 |
| 赋值位 assignTypes（:829 / Elaborator :1032） | typeof(v) <: ?local | 局部下界 |
| 初值位 varAnnotated（:810） | 既有单点推导升级为**元变量的首个下界** | 局部下界 |
| 字段读 Elaborator :1343 / 结构体字段写入位 | typeof(e) <: ?φ；字段取出 → 上界 | 字段下/上界 |

**证据来源 = 约束的源位置**：每条约束登记 use 位（"use:行:列"），闭合时收束进对应空位 evidence（t108 契约：列表、声明序、去重）。**证据必须真实可追溯**——t110 trustedBase 留一审计的同款诚实性。

### 1.4 与 t108 载体字段的回填契约

- 求解收敛后（终轮构造时，见 §2.1 调度）：解出的类型写入既有槽位（HirParam.type / HirFunDecl.retType / HirVarStmt.type——三者本就可空）+ inferred=true + evidence=[…]（按源序去重）。
- **默认填充（无证据）**：P-11 §3.6——形参 Nothing、ListOf() → List[Nothing]、MutableListOf() → 新鲜元变量。填默认的写类型槽、**inferred=false**（defaulted 语义待 C-10 二裁；t108 未落 defaulted 字段——本提案**不新增字段**，以 inferred=false + evidence 空 暂代，C-10 若裁 defaulted 再补）。
- **一旦出现任何写约束（如 xs.add(1)），该元变量即有证据，走等式合成（P-11 §5.1），不适用默认**——提案在约束袋里以「下界集 + 视图极性」实现：@mut 视图下取交（ST-13 不变位等式）。
- 编译单元内**轮次确定性**：evidence 逐字稳定（声明序 + 同输入同轮数，P-11 §9.3）。

## 2 约束收集与求解环

### 2.1 调度方案（本文核心主张）——同一 walker 至多 R 轮重跑

**问题**：约束来自使用位点（体内），只能由 Elaborator 主趟收集；求解若在文件末，则主趟构造的 HIR 使用位点类型已嵌入**未闭合元变量的瞬态类型**——HIR 不可变、JSON 直发，回填即造树遍历（I-1 债务禁区）。

**方案**：不回填、不造 walker——**主趟整体重跑**：

1. 第 k 轮：Elaborator 以「第 k-1 轮的解 + 符号表当前态」从头构造一棵**完整 HIR**（fresh NodeIdSource 每轮重置，保证同态输入逐字同构）；
2. 元变量/约束**每轮重建**（约束袋是构造的副产品，不跨轮保存实现态；**解**跨轮传递：符号条目槽位写第 k-1 轮终解）；
3. 收敛判据：本轮解与上轮解逐元变量 typeEq 结构相等（P-11 §3.5；判据复用 TypeInfer.typeEq :299——不新写）⇒ 停，**保留最后一轮的 HIR 与诊断**；
4. 上限 R=INFER_ROUNDS_DEFAULT（C-6 裁 **8**，允许调试期覆盖；OQ-2）。

**为什么合法**：P-11 §3.5「一轮=一遍全量约束求值」的自然读法即**整遍求值**——重跑是同一 walker 的 R 次使用，**不新增 walker**（§4.1）；每轮构造的 HIR 嵌入的是「该轮已就绪的解」，终轮产物无瞬态残留——**回填零成本天然成立**。

**纪律代价与守纪点**：
- **诊断只在终轮落**（中间轮诊断一律弃——否则同一错报 8 次；确定性按终轮）；
- **燃料同池**：所有轮的所有 adaptOk/subtype 调用计入 t51 同一池（P-11 §8），不开新池；
- 成本：≤ 8× 主趟——OQ-2 交队长裁阈值（建议复用 t51 燃料耗尽落既有 D-FUEL 口径先行观测，R 不收敛落 §3 分型）；
- Elaborator 可重跑性需一次体检（累积型成员如 narrowAttempts/trustedBase 等——需按轮重置；OQ-3）。

### 2.2 最小解与极性

- 候选取法按元变量**视图极性**（ST-13.1，复用 viewKindOf :367 + 变方差表 compileVariance）：正位 lub(下界)、负位 glb(上界)、推导位不变取交（等式约束——两方向都收）。
- 最小解定理（P-11 §3.3）：lub(L) ⊰ u ⇒ 无解——**不需要搜索**，判定走既有 subtypeBody（自足判定，ADR-39）。
- **声明位不变 + 写界**保持现状报错（E-BOUND-INVARIANT 既有口径）。

### 2.3 与 subtypeBody 算法判据的分工边界（任务第 2 项的正面回答）

**证算法先、算法封顶才上通道**——与 t109 proves 层级同构：

| 层 | 内容 | 何时 |
|---|---|---|
| L0 算法 | subtypeBody/adaptOk（自足、可判定） | 所有约束的**即时判定**与最小解校验 |
| L1 结构传播 | List[?α] 元素层推进、递归 ⊥→不动点（R 轮） | L0 不足以定解（复合类型相遇/递归） |
| L2 证明通道 | (e : T) 原子通道 / 公理救援（t109 P2 段） | **L0 判不出的上界契约**：候选 = lub(L) 而 U 契约需 (e:T) 可证（例：xs.head : T 需列表元素契约）——经 injectSyntheticFact 生产侧（§3.2）确立 |
| L3 拒绝 | 分型表处置（§3.1） | L0~L2 皆败且义务不可退化 |

**边界铁律**：subtypeBody 能判的一律不经通道（通道只对 L0 判不出而开；t110 measure 同构——算法可证的算术 decrease 不上通道）。**任何通道结论必须带 provenance**（synthetic/用户公理）与 trustedBase 留一审计（t109/110 已备）。

### 2.4 不收敛处置（OQ-2 预算界限口径）

- 燃料耗尽（t51 同池）⇒ 既有 D-FUEL 口径 + 回落（不分类型错）；
- R 轮未收敛 ⇒ E-INFER-NOT-CONVERGED（文案：R 轮仍在变 + 多半递归/多态递归 + 「加一处标注打破环」建议），处置**走分型表** §3.1——不单独硬拒。

## 3 义务生产侧（补 t109 留的洞 + R-02 退化通道）

### 3.1 分型表（C-9；续 R3-V1 §5.3，加推导族）

| 推导族义务 | 分型 | 失败处置 |

### 3.2 injectSyntheticFact 的生产点位（三个）

1. **解闭合点**（§2.1 终轮内、funDecl 体首）：形参/返回/字段的解闭合 ⇒ 注入 (x : T) 族 atom（provenance=SYNTHETIC 复用 t109 分账；CAP 同 TYPE_FACT_CAP 口径）——体级窄化/measure 直接消费（t110 的 n > 0 类事实同源）。**这正是 t109「确立型注入通道无生产侧」的洞**。
2. **跨声明签名事实**（符号表终态 ⇒ 下一轮可见）：调用点对 callee 签名的闭合事实按轮传递（R 轮调度的天然红利）。
3. **证明通道结论回写**（L2 闭合）：(e:T) 通道判出的上界契约元素经 injectSyntheticFact 注入，参与最小解的 U 校验——**公理族经 trustedBase 留一审计**（--no-trust CI 口径同设）。

### 3.3 R-02 退化通道（脚本模式；落地两锚点）

\`\`\`
