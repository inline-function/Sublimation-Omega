## 1 累积型成员盘点与重置分类

**核心事实**：Elaborator 是 private class（Elaborator.kt:327），**全部状态实例内**——
R 轮重跑若按「每轮 new Elaborator」实施，则下表**无需任何手工重置**；重置责任全部落在构造期
依赖与轮外驱动上（§3）。

| 成员（Elaborator.kt:354-441） | 类 | 跨轮命运 |
|---|---|---|
| typeParams / funFrames / patOrigins / factFrames / expectTypes | ArrayDeque 栈 | 实例内；全经 symbols.frame(kind) 通道（ST:304-307 try/finally pop）与配套 scoped 通道平衡，**无帧泄漏**（异常路径亦然） |
| funDecls / structDecls / aliasDecls / traitDecls | MutableMap | 实例内声明索引；每轮重建（含 PreludeDecls 预注入 :376-377，纯拷静态表） |
| aliasExpanding / inTraitBody / uncheckedDepth / lambdaExpect / classicMounted | 标志/栈 | 实例内 |
| varianceCache | 惰性缓存 | 实例内（acceptVariance 通道不污染） |
| axiomFacts / trustedBase / pendingByAsserts | 事实/审计集合 | 实例内（**trustedBase 即 t109 留一审计 = 合法轮内状态，不跨轮**） |
| narrowAttempts / measureProofs | 观察计数/列表 | 实例内（t110） |
| oracleImpl（defRules/spent/channelTraces/budgetReported，ORC:268-323）/ prover | 实例对象 | 实例内；PROOF_BUDGET=4096 每轮独立 |

**合法跨轮载体（现状可用的只读通道）**：
- symbols: SymbolTable（compile :35 一次 new；collectFile 只跑一次 :50）——全局层 frozen、帧平衡；
- parseNotes: Map（不可变）；scriptMode（常量）；AST 本身（不可变输入）。

**结论 1**：**累积成员清单为空**——重跑的重置面不在 Elaborator 内部，而在构造期依赖。
（这本身是体检的正面发现：ADR-6 §二「elaborate 纯函数」纪律把脏状态全挡在类外了。）

## 2 NodeIdSource fresh 的可行性（D-14）——**H1 回炉点**

现状（ST:44-42/474-481、compile :34-35）：
- 单一 NodeIdSource：compile() 里 new 一次，**同时**喂给 SymbolTable(nids::alloc)（符号侧
  合成类型节点的 id）与 Elaborator（HIR 节点 freshNid）——ADR-14 契约「同一 nid 同一节点，
  禁止第二个节点计数器（F1 blocker 级）」。
- NodeIdSource 无 reset 接口（:479-481 仅 alloc 单调递增）。

**t112 §2.1 原句「fresh NodeIdSource 每轮重置，保证同态输入逐字同构」判定为不可行**：
- 若每轮 new 一个：symbols 侧的 id 域停在**第一轮**（共享 symbols 已被第一轮 alloc 过合成 id），
  而本轮 HIR 从 1 重新计数——**两套 id 相交**（①不同节点同 id 违反 ADR-14 身份绑定；②JSON 产物
  nid 冲突——D-14 学故复发形态）；且「符号侧另开源」被 F1 级契约直接否决。
- 唯一合法形态：**跨轮共享一个单调 NodeIdSource**（即 compile 已建的那个，elaborate 反复调用）。
  后果：**终轮产物的 nid 布局依赖收敛轮数**（前 k-1 轮分配已落地）。确定性仍成立（同输入 ⇒
  同轮数 ⇒ 同 ids），但「逐字同构」必须放弃——与 t110 JSON SAME 门的关系：

**SAME 门保护条款（提案必须吸收）**：R 轮循环仅当**本单元存在至少一个未闭合元变量**时启动；
零元变量文件**单趟直通**（nids 与今日完全一致）⇒ 68 工程样本（全 .subl、零推导）基线零漂移。
脚本样本带 inferred 字段时多轮启动，nid 漂移属**预期差**（jsoncmp README 记账，同 D-12 条款形态）。

## 3 主趟可重入性——**H2 回炉点 + 一项 sink 接管**

elaborate()（Semantic :51）每次调用 new 一个 Elaborator 并跑 file()：**无一次性副作用落在
进程级或文件级**（逐项核：DiagBag 实例内 :61-64、无 static 可变域、FuelBook object 见 §4 为纯
观察、NativeProps/PreludeDecls 为只读静态表、isolatedFrame finally 还原 ST:318-322）。

两处「跨轮经 symbols 递解」的通道在提案口径里被写错，须回炉：

- **H2（解传递通道）**：t112 §2.1「解跨轮传递：符号条目槽位写第 k-1 轮终解」——**违反
  ADR-6 §二只读边界**（ST:39-42 全局层 collect 后对 elaborate 只读；SymbolEntry 是
  val type 不可变 ST:19-29）。回炉口径：解映射放**轮外驱动**（compile 层 Map，按元变量的
  空位键（种类+声明位）索引），以构造参数注入每轮 Elaborator；使用位点先查注入解、再查
  symbols（只读）。**零改 SymbolTable**。
- **H8（诊断 sink 接管）**：symbols.shadowHintSink / nativeReclSink（ST:75/81）在 compile :39-49
  挂到**编译级** hintDiag/collectDiag——轮内 declareLocal 的原生命名碰撞提示会逐轮重复落袋。
  R 轮驱动须按轮接管 sink（或终轮吸收时按轮去重）。小项，入重置清单。

经 symbols 的另一变体：nextId++（符号 id 每轮重分配）——**轮内自洽即可**（HIR 引用 id 在本轮
重建时与新 id 同步），不构成问题，仅记账。

## 4 燃料同池下的 R 轮预算形态（OQ-2 先观测口径）

- 池形态：TypeInfer 实例内（FUEL_DEFAULT=237_500 判定步；ADR-33 实测单次顶层检查 max=2375、
  深度限 800、:191-197）。**Elaborator 每轮 new ⇒ infer 每轮 new ⇒ 每轮一个全新 237.5k 池**。
- 即 t112 §2.1「所有轮的 adaptOk 计 t51 同一池」**在现架构下不成立**——现状给的是
  **R 个独立池**。两条口径任选其一（队长 OQ-2，不代裁）：
  1. **接受 R 个池**（总上限 8×237.5k ≈ 1.9M 判定步）：每轮拿满预算 ⇒ D-FUEL 不进常态路径；
     与 P-11 §8「同池」字面有距，但与 ADR-33「每请求一池」既成口径同源（一次 compile = 一请求）。
  2. **跨轮共享燃料簿**（载入驱动层注入）：严格同池，但把 D-FUEL 拉入常态相关面（前几轮乱烧
     压终端预算）——需先观测分布再裁。
- FuelBook（object，:200-243）**只记账不执法**（SUBL_FUEL_STATS opt-in）：R 轮下每文件记
  R 条样本、top200 截断——**观测口径受影响（样本数×8、按轮混叠），执法不受**。OQ-2 观测时
  按轮打 label（setFuelLabel 已有接口 :188）即可分离，无新机制。

**结论 4**：燃料不构成阻断；口径二选一，属 OQ-2 队长面，本文仅给形态。
