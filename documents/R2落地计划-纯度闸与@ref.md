## 一、N1 纯度闸族

### 前置（硬依赖，必须先做）
**lambda 纯度推导**。现状：`Elaborator.kt` 8 处硬编码 `HirPurity.PURE`（:1188/:1190/:1253/:1257/:1535…）。**不做这个就上闸，闸必误报**。

### pure<f> 四步升级（qa t93 方案）
1. Γ 注册：纯函数声明注册 `pure<f>` 命题；
2. 调用闸：纯作用域内调 `@impure` 函数，若 Γ 无 `pure<f>` ⇒ `E-IMPURE-CALL`；
3. 上文转嫁：`@impure` 函数体内放行（效应沿调用链向上传播）；
4. 借用形参：函数类型位 `@impure` 的形参，其调用按非纯处理。

### 停机闸
- 旧机制：自递归实参「变小」两条形态（子结构缩小 / 数值靠拢），`@impure` 可逃逸；
- 新工程 `callExpr` 已有 callee + 实参，**单 pass 可成**；
- **⚠️ 不可混用 `E-FUEL-EXHAUSTED`**——那是编译器自查燃料，与停机证明是两回事。

### 风险与预算（必须守）
- **闸先以「报告态」上线，度量样本冲击，再转硬拒**。样本是新工程在没有闸的情况下写的，可能有合规违反；
- 度量口径：68 样本里会触发 `E-IMPURE-CALL` 的位点数；超阈（>0）先报队长，不擅自改样本；
- lambda 纯度推导会改变 HIR 的 purity 位 ⇒ **68 样本 JSON 可能出现 authorized diff**：凡是 body 含不纯调用的 lambda 从 PURE 翻 IMPURE。这是**规格允许的 diff**，但必须逐处归因、单独记台账（沿用 t80/t82 的「DIFF 归因集」方式）。

## 二、N2 @ref

### 分层（qa t93 估：词法近零成本，语义四规则是大头）
1. 词法：`@ref` 走注解通道；
2. 语法：类型位注解语法接受 `@ref T` / `@ref @mut T`（Parser.kt:625 现在是关的）；
3. AST/HIR：`@ref` 类型节点；
4. 语义四规则：**可写性 / 子类型 / 拷贝分派 / 命题待遇**——σ 双视图分派机制可作模板；
5. 命题待遇：`@ref` 与可变更同等待遇（不进上下文、不承认相等命题）——根文档 :142 原文。

### 形态矩阵（根文档 :89-163）
`@mut T`/`@ref T`/`@ref @mut T` 两两赋值，共 8 种组合的拷贝/共享判定。这是 N3 的输入。

## 三、N3 深拷贝规则

- **前端只做类型转换规则 + 文档**，不动运行时（前端无运行时层）；
- 8 格矩阵逐格定义「拷贝/共享」判定，落在类型层；
- 实际深拷贝随后端运行时实现，前端文档标注「随后端」。
