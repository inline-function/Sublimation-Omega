# R3 V1：上下文系统 + 自动证明器设计

> **状态**：纯设计文档（Ver v1 草案），不写码、不裁决。
> 来源：队长分叉任务（2026-11-10）；**C-2 新裁决（2026-11-10）：「V1 就做证明器」**——V1 通过上下文系统 + 自动证明器取得可判定性，
> 不走 P-11 的单态 + 有限轮围栏兜底。本文回答队长六个必答项。
> 依据（已通读）：ProofChecker.kt、Elaborator.kt（帧栈/收窄/闸）、P-11、P-12 前瞻稿、R3 接口设计（t102）、
> ADR-13/39/41/42/43/55，以及 R3 裁决记录 R-01..R-08。

## 0 核心论断（先给结论）

1. **命题层机制可复用度约八成**：五段通道、Γ 帧栈、类型/分支事实、trustedBase 审计、R-NO-GUESS 姿态——全部既存，
   唯一真正缺的是**类型判定 (e : T) 通道**（ADR-13 §三已列为 P-12 硬前置）与**类型义务进 Γ 的形态**。
2. **证明器不替代算法判据**：subtypeBody（ADR-39 唯一判据）、视图规则（t98）、copyDispatch（t99）保持算法执行；
   证明器进入的是它们**解不出**的义务——这与 F<:ω 不可判定的事实精确对应：不可判定的是**义务可证性**，不是
   「基础子类型检查」本身。V1 用证明器把「围栏拒绝」换成「证明通道尝试」，不是把子类型塞进证明器。
3. **红线的形式化（本文提出的置换原则）**：证明成功只能替换一个**已有独立算法支撑的类型判定**（兜底解先在位）；
   证明失败 ⇒ 回落该先在解（更粗但健全），或硬拒。**证明永远不会创造一个无算法支撑的接受**——这才是「不退化为动态
   检查」的可操作定义。先例已在：t66 收窄失败回落 `Int`（L454-461 落 D-NARROW-SCOPE，保持原类型）。

### 1.3 类型层判据（全部算法化、独立于证明器）

- `subtypeBody`（ADR-39）：全前端唯一相容性判据，含假设集余归纳处理递归类型——**自身可判定**。
- 视图规则族（t98）与 `copyDispatch`（t99）：纯类型树语法判定，无证明义务。
- 变构性推断（ADR-41）：σ_imm/σ_mut 双视图极性。

- 四级漏斗（约束求解 → 定义性归约 → 证明通道 → 拒绝）与每级 `provenance` 标记（constraint-solve / reduce /

## 2 义务编码（必答 1）

### 2.1 三族约束的判分

| 约束族 | 例子 | 处置 | 理由 |
|---|---|---|---|
| **基础子类型** | `Nat <: Int`、`List[Nat] <: List[Int]` | **算法**（subtypeBody）| 自身可判定；ADR-39 唯一判据不被旁路 |
| **使用点界** | `lub(L) ⊰ U`（P-11 §3.3 定理检验失败）| **算法 + 证明救援** | 纯算法无解时，证明通道救一条：`∀x. id(x)=x` ⇒ `id(1) : Nat`（P-12 裁决 A 的原例）|
| **视图/可变/拷贝** | isWritableView、copyDispatch | **算法**（不编码）| 类型树语法判定，无义务内容；编码反增复杂度 |
| **运算后承** | `Nat - Nat` 期望 Nat ⇒ 证 `左 >= 右` | **证明**（已落地）| t66 先例 |
| **归纳性质** | 递归函数的停机性、结构归纳命题 | **证明**（但 V1 受限）| t97 停机闸 + ADR-13 归纳缺口 |

### 2.2 编码形态：三个选项

**选项 A（合成 atom 入 Γ）**：类型义务写成 `HirPAtom("<:", [τ1, τ2])` 或 `(e : T)` 命题注入帧栈，与 `pure<f>`（t96 合成_atom 同族）并列。
消费：在 `proves` 五段通道后追加第六段 **A-SUBTYPE（判据 oracle）**——命中合成 atom 时委托 subtypeBody 判定。
优点：义务随 Γ 流动可供 axiom 命名（P-12 裁决 C「axiom 可参与类型精化」的直接落位）、可见性与审计天然；
代价：需 C-8 provenance 区分用户/合成（否则 trustedBase 审计口径被污染）。

**选项 B（约束直译、不入 Γ）**：义务在 obligation 位点临时构造 goal、取 allFacts 快照调 proves（复刻 narrowMinus 的写法）。
优点：零新增 Γ 形态、闸零改；代价：义务不可被 axiom 二次利用、不可跨函数残留（上文上提没有载体）。

**选项 C（混合）**：**确立型**义务走 A（要可见、要上提、要审计）；**选择型**义务走 B（一次性、回落安全）。
分型定义见 §5.2。本文不代裁，但给出工程后果矩阵：A/B/C 的差别只在**可见性与复用**，soundness 均由 §0 置换原则保障。

### 2.3 命题层复用度（八成）

| 复用 | 内容量 | 说明 |
|---|---|---|
| ✅ 直接复用 | `proves` 五段、closure 饱和、normalizeFacts/render、帧栈、类型/分支事实、预算与截断、R-NO-GUESS | 零改 |
| 🔧 扩展 | `proves` 加第六段 A-SUBTYPE（判据 oracle）；`HirTerm` 需承载类型项——而 `HirTName/HirTInst/HirTCall/HirTField` 等本就是 HirTerm 形态族（见 ProofChecker 顶部 import 的 HirT* 双重身份），**类型作为项的形态已在**，缺的是判定通道本体| 增量小 |
| ❌ 新造 | 类型判定通道主体、选项 A 的合成 atom 注入时机、证明义务与 t96/t97/t98 消费侧的接驳时序 | 本设计主体 |

## 3 上下文系统对类型义务的承载（必答 2）

**已有能力可直接承载**：factFrames 的类型事实（ADR-42）与分支事实已证明可承载「类型相关的命题」；`expectTypes` 栈
提供义务位点；GateScope 的 preps（d.preps）提供**函数级**的义务挂点位（R3 接口设计 §2.2 已为 `pure<f>` 使用）。

**处置（本文方案，待队长认）**：
- 函数帧内义务：入帧（选项 A）或临时快照（选项 B），与 t66 一致；
- **跨函数义务上提**（理念文档「证明义务上提」的本体）：落 callee 的 `d.preps` 作合成 `<谓词名>` 命题，与 `pure<f>` 同族——
  R3 接口设计 §2.2 已测得消费位零改（`g.proven(nm)` 放行链自动生效）。
- **时序红线（qa R1 同款）**：合成 prep/退化 @impure 必须在 t96 尾闸**之前**注入——义务上提与 R-02 退化共享同一条「先于闸」
  注入序（已在 R3 任务书 §6.5 记为 M7 落实项）。

**不另造上下文容器**：不新建「类型义务帧栈」——与既有 factFrames 合流，避免 I-1 同族的双 walker 债务重演。

## 4 三相求解循环（C-2 后的 V1 组织）

```
P1 结构传播   约束图最小解/极性/双向 fuel（复用 P-11 §3.3 定理 + ADR-41 极性）——算法，不动点
   ↓ 剩余未解义务（每项带待救清单：位置 + 已知上下界 + provenance=constraint-solve）
P2 证明通道   定义性归约（单表达式纯函数重写，P-12 第二级裁决 B 的范围）→ (e : T) 判定 →
   A-SUBTYPE oracle → 用户公理（trustedBase 审计）——proves 六段，预算同池
   ↓ 仍未知
P3 拒绝       硬拒 + 诊断（能证/不能证分类、可尝试方向）——不发明「放行」兜底
```

- **P1 不收敛的处置**（P-11 §3.5 E-INFER-NOT-CONVERGED 的命运）：结构不动点无 R 轮硬断，改为「每轮预算同池消耗，
  池空才停」——池预算是**执行界限**不是**语义围栏**；停在结构未收敛态 ⇒ 进 P2 判定是否仍有救 ⇒ 否则 P3。
  **该项推翻 P-11 §3.5，属队长认领区（OQ-2）**。
- **稳定性**：所有截断按**源序确定**（narrowMinus 的 NARROW_TRY_CAP 与 TYPE_FACT_CAP 已立此口径），单线程声明序遍历，
  保证同输入同结果同轮数（P-11 §9.3 纪律不变）。
- **单态（P-11 §3.7）的命运**：C-2 下不再以「拒绝多态」换可判定；P-12 裁决 A 的 `∀x. id(x)=x` 救援正式进 V1。
  **推翻 P-11 §3.7，属队长认领区（OQ-1）**。

## 5 兜底策略：unknown/超时（必答 3，给 C-9 输入）

### 5.1 红线的形式化——置换原则

> 证明成功替换的类型判定，其**兜底解**必须先在位（由 P1 算法独立给出）；证明失败 ⇒ 回落兜底解（更粗但健全）或走 P3 硬拒。

推论：`proof` 永远不创造「算法无支撑的接受」。全部「动态类型」形态（JS/Python 运行期检查）一律无入口。
这与「不退化」红线等价，且是**可测试的**：任一 HIR 类型位的 provenance 若为 proof:*，其兜底解必须同时可查。

### 5.2 两类义务的分野（本文提出的分型，供 C-9 裁决）

| 分型 | 定义 | 失败处置 | 先例 |
|---|---|---|---|
**选择型** | 兜底解先在位，证明只是**收窄**（使类型更精确）| 回落兜底 + 提示（D-NARROW-SCOPE 同款），**不报错** | t66 收窄 |
**确立型** | 无兜底解——接受此程序**必须**证明成立 | P3 硬拒（E-CANNOT-PROVE/E-INFER-* 族），**绝不延期接受** | 因为∴/by 断言（R-NO-GUESS）|

**与 C-9 的联动输入**：P-12 原稿 E-INFER-PROOF-DEFERRED 的口径「这不是错误，是能力边界」只适用于**选择型**（回落成立）；
对**确立型**保留该口径 = 让程序带未证义务通过 = 事实上的动态退化。故 C-9 的裁决输入是：**分型表**（下 §5.3）逐项规定
每族义务属于哪型。本文给的默认分型在表中标注，队长可逐行改判。

### 5.3 兜底分型表（默认值=本文建议，C-9 可逐行改判）

| 义务 | 默认分型 | 失败处置（默认）|
|---|---|---|
| 基础子类型失败 | 确立型 | 硬拒 E-TYPE-MISMATCH（既有）|
| 使用点界 `lub(L) ⊰ U` | 确立型 | 进 P2；仍败 ⇒ E-INFER-NO-SOLUTION「最小解定理无解——无任何解存在」（P-11 §3.3 定理）|
| 纯函数定义性归约 | 选择型 | 回落 P1 结果 + D-* 提示 |
| (e : T) 用户公理救援 | 确立型 | 硬拒；--no-trust 下审计失败 |
| 归纳/停机性质 | 确立型（工程）/ 退化（脚本 R-02）| 工程硬拒 E-NON-STRUCTURAL-REC（既有）；脚本退化不纯 |
| 表达式收窄（t66 族）| 选择型 | 回落 + D-NARROW-SCOPE（既有）|

## 6 消费接口一致性（必答 4）

证明通道不新造遍历——与 R3 接口设计（t102）§1 同源：

| 供给 | R2 消费位 | 备注 |
|---|---|---|

| 停机退化 | t97 FunFrame.impure（:2630）| 先于尾闸注入 |

**唯一新适配**：A-SUBTYPE 通道需要 subtypeBody 作 oracle 调用——这一步在 `proves` 内部，消费侧零改。

## 7 V1 边界与不完备（必答 5）

### 7.1 能证（V1 落地后）

- 常量真值、线性算术全通道、莱布尼茨代换、MP 闭包（现役）；
- 类型/分支事实驱动的运算后承（t66 族，扩展到更多算符与期望位）；
- 单表达式纯函数的定义性归约（`∀x. f(x) = body` 重写，P-12 裁决 B 范围）；
- **(e : T) 类型判定 + axiom 救援**（P-12 第二级提前）；
- 用户公理参与的证明，含 trustedBase 留一审计与 --no-trust CI 口径。

### 7.2 不能证（V1 已知不完备，及拒绝路径）

| 不能证项 | 现状 | V1 拒绝路径 |
|---|---|---|
| 归纳（数学/结构归纳）| ADR-13 补登：零处实现 | 确立型义务硬拒；用户须手工 `axiom` 喂归纳原理（现役口径）|
| ∃! 唯一性 | prove 恒 false（ADR-13 §三）| 硬拒 E-QUANT-UNPROVEN |
| 定理空间搜索 / 反证法 | 推迟 | 同上族拒绝 |
| 高阶会话（三维池/迭代加深）| 推迟 | 同上 |
| 深归约的递归函数展开 | 无终止依据不展开（P-12 §4.4）| 回落 + D-* 提示（选择型）|

**不完备是可观测的**：每条被拒义务的诊断必须给出（a）已尝试通道列表、（b）失败原因分类、（c）可尝试方向的构造性建议
（公理/守卫/标注）——E-CANNOT-PROVE 的既有文案已是该范式。
