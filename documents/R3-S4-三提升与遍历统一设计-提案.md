## 1 不纯推导（机理设计）

### 1.1 缺口的精确形态（实测）

t96 的注册步 runPurityGate（:3265）做三件事：①Γ 注册（注解，O(声明数)）；②R-07 捕获预扫描
（mutCaptureScan(d.body) 逐函数**全体遍历**）；③gateWalk 逐函数再遍历（含 lambda 位内联
捕获扫描）。P-11 §4 的传播规则 2/3/4（f 调 g 且 g 不纯 ⇒ f 不纯；SCC；不动点）**没有任何实现**：
gateCheckCall（:3320）只在调用位**诊断** E-IMPURE-CALL，从不回写调用方纯度。
理念文档要求的「自动加 @impure」在具名函数上唯一已落的反推是 R-07 捕获（:3282-3285 把
declaredPurity[fn] 写真）——即**判据存在、闭包不存在**。

### 1.2 机制：单调闭包（每轮一次，并入 t96 注册步）

```
PurityClosure（在 elaborateRound 的 runPurityGate 注册步内，每轮重算）:
  节点 V = 全局具名函数（hir.entries）+ 局部 fun（词法序 GateScope 登记位）
  种子 imp:true =
      注解 @impure（gatePurityOf，声明真值优先）
    | 名在内建不纯表（遮蔽口径同 impureName:3223——用户同名声明优先）
    | R-07 捕获成立（既有预扫描，直接复用其结果）
    | t118 退化位（degradedFuns 集合——Semantic.kt:160 已透传至 Elaborator 构造）
    | t94 闭包体效应（HirLambda/HirAnonFun.purity——主趟构造位已算好，读字段即可）
    | 脚本顶层语句（隐式入口不纯——既有 stack 顶 GateScope(true)，本件只把同结论并表）
  边 E = 调用位 (caller → callee)：calleeName 已在三处调用槽算出
      （checkTermination 的 c.name / plan.second / callCalleeName，:2455/:2551/:2600）
  传播 = 工作表单调算法（源序入表/出表，O(V+E)，≤|V| 轮内必然终止——P-11 §4「单调不动点」
      的算法形态；SCC 规则 3 是其特例：任一不纯成员经传播最终污染全 SCC，不必显式 Tarjan）
  产物 = declaredPurity 表（**同一张表、同一消费位**：g.proven / gateClassify 零改）
```

关键接驳决定：**边集不从 HIR 树另遍历收集**——gateWalk 本就逐调用位访问（:3374），
在 gateCheckCall 已算完 callee 名的点上把 (caller 名, callee 名) 记入工作表即可——
零新增遍历（I-1 纪律：本提案不得给三 walker 加第四个）。

### 1.3 与 HIR 产物的接驳（零 schema 变动）

HirFunDecl.purity 字段本就在 v3 schema（Decl.kt:29，t94/t118 已写）。闭包产物回写规则：

- 用户注解 **@impure 优先**（声明真值不推翻——t118 degradedFuns 已同口径）；
- 无注解 + 闭包判不纯 ⇒ purity=IMPURE + **D-PURITY-INFERRED** 观察级（函数名 + 传播路径
  「f 不纯 ← 调 g@<pos>（g：捕获不纯/内建/…）」+ 种子源分类，审计口径同 D-INFER-DEGRADED 四元组）；
- 闭包判纯且用户**未**注解 ⇒ 保持 PURE，不发观察级（静默推导，P-11 §9.1 差分对拍口径）。

诊断可见性是 P-11 §6「诊断第一职责」的延续：自动加 @impure 必须告诉用户**为什么加**。

### 1.4 「证出即纯 / 退化即不纯」分型表（R3-V1 §5.3 口径的纯度族）

| 判据 | 证出（成立）| 失败（证不出）| 落点 |
|---|---|---|---|
| t110 measure 停机义务 | 停机成立——**纯度面无加成**（停机与纯度正交：纯函数仍可因效应不纯；闸只跳 impure 帧）| 脚本 ⇒ R-02 退化 ⇒ **即不纯**（t118 已落）；工程 ⇒ E-NON-STRUCTURAL-REC 硬拒 | 已落，本表归位 |
| R-07 捕获（@mut 自由变量）| 无捕获 ⇒ 不加纯度（纯候选）| **即不纯**（已落，:3282/3436）| 已落 |
| t94 体效应（闭包）| 体无效应 ⇒ 纯 | **即不纯**（:1921/2002）| 已落 |
| 调用传播（理念文档自动 @impure）| — | **即不纯**（本提案 §1.2 新增）| 本件 |
| 内建不纯 / 注解 / 顶层语句 | 种子 | — | 已落（注解+内建+R-07；顶层语句仅作用域，未回写——见 OQ-2）|

**红线（R-02 口径提醒）**：不纯推导是**判决的自动化**，不是放行的新通道——证不出 ⇒ 填 Any+
不纯（脚本）/硬拒（工程），无解双模式硬拒。闭包只把「已判不纯」传播，不产生「无罪推定」。

### 1.5 确定性与轮次耦合

- 闭包每轮重算（runPurityGate 本就每轮跑：Elaborator:190/220）；R≤9 轮 × O(V+E) 相对主趟可忽略。
- 工作表按**源序**（声明序 + 词法序）——同输入同结果，P-11 §9.3 稳定性不变；
  差分对拍（.subl 全标注 vs .subs 推导）的验收尺不受影响（忽略 inferred/evidence 后结构相等，
  purity 注解与推导结论必须一致——**该差分对拍首次使「自动 @impure」可机器验证**）。


### 3.2 方案 A：主趟事件框架（统一遍历）

主趟保留遍历序（nid 分配序不变——SAME 适用的前提），把每个节点位改为发事件：
enter(e)/exit(e)/call(callee,args,pos)/varDecl/assign/return/lambdaExit，
判据改订阅者：
- t97 停机：已是调用槽内联判据（:2455/:2551/:2600）⇒ 直接订阅 call 事件；
- t94 纯度：lambdaExit 累加器替代 containsImpureCall 子遍历（bottom-up 信息从 exit 事件回流）；
- t96 纯度闸：call 事件订阅（读 §1 闭包表）；作用域栈由 enter/exit 维护；
- t107 捕获：enter/exit 携带 bound 集状态机（词法序累计——事件序天然提供）。
保留项：t96 的 Γ 注册 + R-07 预扫描**合为 §1 闭包的单次注册**（O(V+E)，无全体遍历）。

### 3.3 方案 B：判据并入最近 walker

把 mutCaptureScan 的两用形态并入 gateWalk（GateScope 携带 bound 集）；containsImpureCall 维持现状。
