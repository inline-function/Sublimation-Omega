## Q3 留痕丢失（D-9）：两个通道都丢，且这是「产物逐字不变」的必要代价

D-5 在 `Parser.kt:1238` 通过 `note(call, "D-INFIX", ...)` 把「中缀 `a X b` 展开为自由函数 `X(a, b)`」挂到 `CallExpr`。值位回落把 `CallExpr` 换成**新建的** `BinExpr`（`Elaborator.kt:1100`），`notesOf(e)` 读的是新节点的（空）notes。

2. **命题位是否也丢——是。** 导出 `fun f[p, q]: Null <p ∧ q>` 与 `<∧<p, q>>`：`HirPAnd` 的 `notes` 均为 `[]`（`PropNormalizer` 的 `propCtors` 分派不取 `CallExpr` 的 notes），角表形对照本就无糖、也是 `[]`。
3. **是否违反 D-9——是信息丢失，但是有意的权衡**：t74 前 `p ∧ q` 走 `LAND→BinExpr`、`true ∧ false` 同样无 `D-INFIX`，**旧产物本就没有这条留痕**。若补留痕，HIR JSON 相对基线新增 notes → 直接破坏 `SAME=68/DIFF=0` 的逐字不变承诺（这正是 jsoncmp 字节比对才能拦住、e2e 看不见的那类差异——ADR-49-b2 §二 的方法论在此仍然成立）。**D-9 与产物逐字不变在此直接冲突，须裁决，不应静默。**

   - **建议**：先按 A 保持，把本条作为 ADR-49-b2 §七 的明文遗留项（现列 3 条，加第 4 条：D-INFIX 留痕在连接词双通道的取舍），等 Q16 值位收窄那批再连同 F2/F4 一并处理。

## Q6 优先级爬升预演（ADR-50：→ 右结合、∧>∨>→>↔、算术单层最高、关系次之、用户中缀=关系级）

现状：`Parser.kt:1159-1241` 是**平坦左折叠**，判定顺序即优先级（`:1155-1157` 注释明写），无优先级层。改成 precedence climbing 时，按风险从高到低：

| # | 上下文特例 | 现位置 | 风险 | 理由与要点 |
|---|---|---|---|---|
| 1 | **stopArrow 两条件（D-21/t42）** | `:1164-1165` | **高** | ① `stopArrow && ARROW` 截断；② `stopArrow && LPAREN 且 precededBySpace` 截断。这俩是**全局停词**（退出整个表达式，不是「本级没有算符」）。naive climbing 若只在某层检查，外层会绕过截断把 `(` 吞成后缀调用。必须抽成统一哨兵（如 `isStopToken()`）在**每一层**前置检查。且「空格 `(`」的截断与 D-5 糖的 `precededBySpace` 判定**同源**，极易混淆。 |
| 2 | **is 同行判定（D-4）** | `:1184-1187` | **高** | `leftEnd != t.line` 用 `peekAt(-1)` 的**物理前 token 行号**。爬升后 left 是子树，但 peekAt(-1) 仍是物理前 token——这一点在右结合（→）下仍成立；真正的风险是**跨行 is 必须 break 退出全部层**（它是 when 下一分支模式的起始）：若实现成「本层不处理则返回给外层」，外层会把 is 当高优先级算符消费 → 破坏 `when` 分支切分。break 语义必须保持 = 整体退出。 |
| 3 | **D-5 前瞻谓词与优先级表的耦合** | `:1235-1241` + `infixOperandAhead :1248-1257` | **高** | D-5 的「算符性」靠前瞻谓词（下一 token 带空格+同行+非停止符）而非 Kind。ADR-50 要求 `∧ ∨ → ↔` 有真实优先级——**它们全是 IDENT、全走 D-5 通道**：优先级表须给「特定文本的 IDENT 名」分级（`"∧"`→某层、`"∨"`→低一层…），普通用户中缀（=关系级）又另一级。**注意这是行为变更不是纯重构**：`a → b → c` 从左结合 `(a→b)→c` 变右结合 `a→(b→c)`；`p ∧ q ∨ r` 从 `(p∧q)∨r` 变 `p∧(q∨r)`——68 样本 JSON 必然 DIFF，e2e 诊断码也可能动。`maybeArithHint`（`:1220`）与 `arithClass`（`:1269`，目前只三级）的提示逻辑也要适配多级。 |
| 4 | **isCtorForm + ifIsCond 哨兵** | `:1188-1195` + `:1152` | **中高** | `isCtorForm(1)` 依赖 cur() 位于 is 处的 peekAt 相对偏移（爬升不改 cur() 位置，peekAt 仍成立）；但 `ifIsCond` 与 `stopIdents`（`:1149`）是**全局可变 var**，递归分层的保存/恢复顺序容易错——沿用 `parseIf:1612` 的 saved 恢复模式。 |
| 5 | **RANGE `..` 与 `in` 的专用右操作数** | `:1200-1204`、`:1207`、`parseRangeOperand :1323-1327` | **中** | `in` 的右操作数用**专用** `parseRangeOperand`（只吃一层 `..`，不是完整表达式）。若爬升表把 `..` 与 `in` 统一进表，`a in b..c` 的语义会变。必须为 `in` 保留专用右操作数绑定力或特殊分支。 |
