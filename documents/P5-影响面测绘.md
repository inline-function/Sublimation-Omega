**给 P5 的裁决选项**（survey 只摆事实）：
- 方案 A（保守）：名字化仅限命题位入口，值位经 ASCII 别名（&&/||/<->）继续 Bool 语义——值位 Unicode 直接写 p ∧ q 则按名字解析为调用（未注册值位实现 → E-UNBOUND-NAME）。改动最小、零 e2e 转红。

- **无论哪个方案，&& / || / <-> 的 ASCII 归一链不能断**（C.1）。

## D. 风险清单

### D1 ∈ 的归一头名问题（**最高技术风险**）

- 现状：∈ 走 SYMBOL 通道 → D-6 中缀 → BinExpr（∈）；归一层 PropNormalizer:88 与 Elaborator:386 **两处独立地**做「∈」→「in」头名改写；消费层 ProofChecker **三处仅认「in」**（:584 区间归属、:775 ground 枚举、:894 rangeOf）、**一处双保险**（:230「in」‖「∈」）、等式双形式「=」/「==」（:349/393/517/800）、不等双形式「!=」/「≠」（:813）。
- P5 风险映射：若 ∧∨→↔ 的**新归一路径（CallExpr/InstExpr 名字分派）**直接产 HirPAtom 而不经 BinExpr 通道（B.1 的 Must-fix 就是防这个），会产生头名错误的原子——比如把 p ∧ q 产成 PAtom（∧），则元数/规则全部静默旁路（P-STRUCT-EQ 让它安静地混入事实集）。
- **结论/要求**：P5 实现必须**单点归一**（NativeProps 表驱动 + PropNormalizer 唯一分派），并为每个二元名断言产物节点类型（HirPAnd 等）而非 PAtom——这正是 B.1 的必须项。另外建议顺手把 :584/:775/:894 的单形式「in」统一为 :230 的双形式（消除历史漂移的隐性定时炸弹），但这超出 P5 本范围，须另记账。

### D2 → 的结合性：**任务书前提与实现不符——现状是左结合，无冲突**

- 任务书问「→ 的右结合（a → b → c 现有语义）」——**实测无右结合**：
  - Parser.kt:1128 注释逐字：「四层结构全左结合、**无优先级**（D-10）」；
  - 形式化文法.md:314「四层结构，全部左结合、无优先级（D-10）」；:484 逐字「命题蕴含 → 是 binops 成员（可与 ∧∨↔ == != 同层混排，**全部左结合无优先级**）」；
  - ADR-7:81、ADR-47:8/20/24/46（用户裁决 A1-A3「没有优先级，中缀一律左结合」）。
- 即 a → b → c 现解析为 (a→b)→c（中缀循环 :1210-1214 平铺左折），HirPImp 嵌套左倾。

### D3 ↔ 可降糖为 → 的双向（**可部分降糖，有 1 处真实阻断**）

- 证据 1（目标侧已降糖）：ProofChecker.kt:377-378 is HirPIff -> prove(facts, HirPImp(a,b)) && prove(facts, HirPImp(b,a))——**证明器早已把 ↔ 目标按双向 → 处理**，无 Iff 专用目标规则。
- 证据 2（事实侧真实消费）：ProofChecker.kt:936 val iffs = facts.filterIsInstance<HirPIff>()——substBfs（莱布尼茨代换）**把 iff 事实当作可改写等价**专用消费（:934-938，eqs 与 iffs 并列）。这是唯一非遍历性的 Iff 消费点。
- 证据 3（结构遍历代价）：HirPIff 出现在 10 处 when 分支（render:75、collectProp:139、substProp:168、substDollar:208、prove:377、substBfs:936、rewriteTerm:973、rewriteSubprop:1011、+ import/HirJson）——其中 8 处是纯遍历（取消节点即删 8 个分支）。
- **结论**：注册表**不能**直接少 HirPIff——除非同时改写 substBfs：把 iff 事实在归一层（PropNormalizer）拆成 (a→b)∧(b→a)（则 :936 的 iff 通道退化为 ∧ 分解 + 双 → 改写）。可行性与收益：归一层拆解后 HirPIff 可完全删除，消费侧 -10 分支、JSON schema -1 kind、render -1 分支；**代价**是产物形态变化（↔ 不再是第一公民，P-STRUCT-EQ 的事实集形态变化会影响既有测试 ProofCheckerTest/HirTest 的 Iff 断言——需同步改测试）。**这是设计裁决而非测绘结论**，建议 ADR 单独立项；若不动，则 P5 与 Iff 无关（零改动）。
