## 0. 结论先行

`@mut` 今天既不是纯文档标注，也不是数据竞争防线——它是**类型层视图 + 编译期写闸**：
参与子类型偏序（ST-11.1）与变构推断（ST-13.1，σ_mut），并挡变量重赋值与字段写。
实测发现**四处漏风**（§4）：别名无分析、嵌套写只看最后一跳、造格判定按位置不一致。
**前置问题**（比选字段级/结构体级更靠前）：**结构体是值语义还是引用语义**——不裁决它，「挡住数据竞争」这档目标无法定义（§1 末）。
我判断**当前语言实际需要的量级 = 档 B**（§1），理由在 §1.4；最终选哪档是用户的决定，本文只摆事实与代价。

## 1. 根问题：`@mut` 到底要证明什么

| 档 | 主张 | 需要的机制 | 工程量（相对） |
|---|---|---|---|
| **A 文档标注** | 「这里会变」，仅给程序员看 | 无类型机制 | ~0（撤销现有机制即可） |
| **B 类型精化 + 写闸**（**现状所处的档**）| 可变性参与类型计算与写权限 | 视图子类型（已实现 ADR-38/39）+ 变构推断（已实现 ADR-41）+ 写闸（已实现） | 现状已完成 ~70%，补一致性（§6 方案一，约 1.5 批）|
| **C 阻止共享可变别名/竞争** | 两个名字不能同时持有可变访问 | 借用/所有权分析（flow-sensitive）、值/引用语义定义、与 Channel/Mutex 联合类型设计 | **数量级上升**：新子系统 ≈ 5+ 批，且依赖前置裁决 |

**档 B 不能挡的**（实测）：`d1` 两个 `@mut` 别名同时可写、`d2` 同一对象作两个 `@mut` 实参——无别名分析；`h1` 经不可变中间字段写字段也通过。

### 1.4 为什么我认为当前需要档 B 而不是 C
1. 用户已表达的目标里**没有并发安全**：脚本模式是核心、定理库已降级待讨论；`async` 是 codegen 翻译到 JS（`core/async` 全是 `@impure @async` 声明——前端只做类型检查，并发行为在运行时）。
2. 档 B **已经是既成事实**：变构推断（ADR-41，VarianceInfer 31 例测试）依赖 `@mut` 的视图对；撤销它 = 撤销已裁决的 P-10 成果。
3. 档 C 的前置：**值/引用语义未定义**——`d1` 说类型系统假装挡了写权限，但语言没说 `t` 与 `s` 是否共享存储。引用语义下才谈得上竞争，值语义下 `@mut` 只需档 B。这个先裁决，C 才可落地。

## 2. 现状（全部实测，探针名即文件名）

### 2.1 合法位置
| 位置 | 结果 | 证据 |
|---|---|---|
| 参数 `fun f(a: @mut Nat)` | ✅ | a1 |
| 局部 `var x: @mut Nat = 1` | ✅ | a2 |
| 字段**注解** `struct S(@mut a: Nat, b: Nat)` | ✅ | c1（注意：写在字段**类型位**无效，须是字段注解）|
| 返回类型 `fun g(): @mut Nat = 1` | ❌ E-TYPE-MISMATCH（造格位拒）| a4/b3 |
| 泛型实参 `List[@mut Nat]` | ✅（类型位合法）| a5/h2 |
| trait 成员 `@mut fun bump()` | ✅ | a6 |
| 语句注解 `@mut var x = 1` | ✅ | f1 |

### 2.2 沿用性（subtyping，ADR-39 ST-11.1）
| 方向 | 结果 | 证据 |
|---|---|---|
| `@mut T → T`（降级）| ✅ 处处接受 | b1/b2/c4/d6/g1 |
| `T → @mut T`（造格）| **按位置不一致**：返回位 ❌（a4/c7）、泛型实参位 ❌（h2 Cons 不匹配）、**var 初始化位 ✅ 放行**（b4/d5）、**调用实参位 ✅ 放行**（g2/d4）| 见 §4 |

### 2.3 写闸（`@mut` 的实际约束力）
| 行为 | 结果 | 证据 |
|---|---|---|
| `var x: Nat = 1; x = x + 1` | ❌ **E-IMMUT-ASSIGN**（普通 var 不可重赋值）| c6 |
| `@mut` 局部重赋值 | ✅ | c5/f1 |
| 字段写`s.a = 3`：字段须 `@mut` **且** 接收者可写（`@mut` 类型或 `@mut var`）| 两闸分别落 E-IMMUT-ASSIGN（信息不同：字段闸 c2 / 接收者闸 c3）| c1/c2/c3/c1b |
| 读字段自动降级 `var n: Nat = s.a` | ✅ | c4 |

> 性质判断：`@mut` **有约束力**（挡写），但只挡**写入语句本身**——档 A 不成立，档 C 未达成。

## 3. 关键分歧：字段级 vs 结构体级

- **现状是双轨混合**：结构体级视图（`@mut S`、`@mut var`，§2.2/2.3）+ 字段级注解（`@mut a: Nat`，§2.1）。
- **若要做纯字段级**（每个字段独立可变）：
  - **子类型**：ST-13.1 变构对的直接后果——`@mut` 字段使结构体类型**不变**（`@mut T <: @mut U ⟺ T = U`，ADR-39 子句 5），字段级 `@mut` 越多，类型越「僵」。h2 已实测到该效应（`Cons[Nat]` 与 `Cons[@mut Nat]` 不相容）。
  - **脚本模式字典传递（P-11 §5）**：字典要逐字段携带可变性标记，字典格式变胖；当前字典不带任何可变性信息。
  - **别名分析（致命前置）**：两个名字指向同一结构体、一个改字段——**现在零别名分析**（d1/d2 实证）。没有它，字段级 `@mut` 是**假安全**：闸在写语句上，不在「谁能看到这次写」上。h1 更直接：`o.i.v = 2` 经**不可变**中间字段 `i` 也通过——字段写闸只核最后一跳。

## 4. 已发现的四处漏风（实测，建议不论选哪档都修）

| # | 现象 | 探针 | 性质 |
|---|---|---|---|
| 1 | 两 `@mut` 别名同写、同对象入两 `@mut` 参：均通过 | d1/d2 | 无别名/唯一性分析 |
| 2 | 经不可变中间字段写深层字段：通过 | h1 | 写闸只看最后一跳接收者 |
| 3 | 造格（`T → @mut T`）在 var 初始化位放行 | b4/d5 | 与返回位/泛型位判定不一致 |
| 4 | 造格在**调用实参位放行**——`@mut` 形参不约束调用方 | g2/d4 | 同上；要么规则化（=借用式松绑）要么堵 |

（#3/#4 若按「`@mut` 形参=按需借用」解读，是特性不是 bug——这本身就是要在裁决里说清的语义。）

## 5. 与 async / Channel / Mutex 的交互

| 行为 | 结果 | 证据 |
|---|---|---|
| `Task { var x: @mut Nat = 1; x = x + 1 }` | ✅ 按普通块体类型检查 | e1 |
| `Channel[@mut Nat]` 类型 + `ch.send(1)`（传不可变值入 `@mut` 元素通道）| ✅ | e2/e3 |
| `Mutex` | **无类型参数**（`core/async/mutex` 声明：`Mutex()` 无类型形参）——「`Mutex<T>` 包住消解 `@mut`」这个写法**在当前语言中不存在**；`Mutex` 构造是运行时注入，前端只有类型名 | core/async/mutex.subl |

**结论**：async 层完全不识别 `@mut`——`@mut` 在异步边界被当作普通视图类型原样传递（`Channel[@mut Nat]` 即 `T = @mut Nat`）。挡数据竞争：**零规则**。若要档 C，Channel/Mutex 需要联合设计（例如 `Channel[@mut T]` 禁止、或要求 `T` 无 `@mut`）。

## 6. 建议方案（两个，不列五个）

### 方案一：维持档 B，补一致性（推荐作为基础）
- **规则一句话**：`@mut` 是类型层视图 + 编译期写权限标记，不构成任何运行时安全保证；`@mut` 形参按「借用」解读（调用方实参不要求 `@mut`——把 g2/d4 的实测提升为规定）。
- **能挡**：写权限误用（不可变重赋值/不可变字段写）、类型精化/变构错误。
- **挡不住**：共享可变别名、数据竞争、嵌套写绕过（h1）、跨 `Channel` 的可变共享。
- **代价**：统一造格判定（var 初始化位）、写闸改「全链路接收者可写」或明确只核最后一跳、ADR + 测试 ≈ 1.5 批；同时把「字段级 `@mut` 只挡写语句、不做别名分析」写进语言文档。

### 方案二：要做真安全（档 C），先裁决前置
- **规则一句话**：`@mut` 绑定唯一写权限，让渡/借用须显式（借用检查器，flow-sensitive）。
- **能挡**：共享可变别名、（配合 Channel/Mutex 联合类型）异步竞争。
- **挡不住**：值语义下的逻辑错误；且脚本模式的字典传递（P-11 §5）需重新设计。
- **代价**：前置裁决「**值语义 vs 引用语义**」→ 新增借用检查子系统 → `Mutex` 加类型参数、`Channel[@mut T]` 规则 → 5+ 批，且与 codegen/运行时必须同步（当前运行时是单线程 JS 翻译）。
