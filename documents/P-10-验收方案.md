## 0 方法论声明：为什么先写负例

P-10 最危险的失败模式是「规则写错了但测试全绿」。健全性缺陷的**表现恰恰是静默放过**——它不产生诊断、不破坏任何现有断言，只是让本该非法的程序通过。若验收口径是「测试 0 失败 + e2e 不回退」，则「规则正确」与「没人试出反例」不可区分——用前者证明后者是循环论证。

因此本方案的第一原则：**先把「该被拒绝的东西」逐条列成可执行的最小用例并给定期望诊断码**。规则被证健全的唯一途径是负例实测落错；规则被证「未被放宽」的唯一途径是负例的落错原因可归因到该规则（排除语法错/未定义名等替因）。

**「不是靠放宽判据通过」的佐证通式**（下文每条负例遵循）：对负例 N（期望因规则 R 被拒绝），
1. 构造**对照例 C**：与 N 仅在「R 关注的那一处」不同、且该处按 R 为合法——C 必须通过；
2. N 落错的诊断码必须是 R 指定的码（或已登记的替代码），且诊断指向 R 关联的位置；
3. 若 N 通过、C 也通过 → R 未被实现或被放宽；若 N 落错但码不符 → 判据漂移，按 §7 反向门禁判失败。

### ST-1 健全性铁律（元规则）

- 规则陈述：不使用 axiom / unchecked 时，类型系统必须健全；为让常见写法通过而放宽的规则一律不合法。
- 正例：无独立正例——本规则是其余规则的合取。
- 负例：**无独立负例，但不是躲避**：ST-1 的验收 = 下表其余全部负例（ST-6/7/8/11/12/13/15 及专项探针 §2）**实测落错**。元规则的可验收化即「负例库整体通过率 = 100%」。
- 判据：见 §7 反向门禁 G1——任一标为「必须健全」的条目负例缺失或通过，即 ST-1 判失败。
- 可观测点：无（它是验收口径本身）。

### ST-3 满足即子类型

- 规则陈述：T 满足特质 C（P-8 结构化满足）⇒ T <: C，隐式成立。
- 正例：
    trait Show[T] { fun show(): Str }
    struct Point(x: Nat, y: Nat)
    fun Point.show(): Str = "P"          // 扩展函数承担实现（P-8）
    @impure fun main() { var s: Show = Point(1, 2); print(s.show()) }
  期望：通过；HIR 装箱值可追到 Point 的 show 实现。
- 负例：Q 不满足 Show 却装箱：
    struct Q(v: Nat)
    var s: Show = Q(1)
  期望：**E-TYPE-MISMATCH**（待创语义：期望 Show、实际 Q，缺成员 show 的满足证据）。
- 判据（排除替因）：Q 已在文件内声明（排除 E-UNBOUND-NAME 的「未定义名」）；对照例：给 Q 补上 fun Q.show(): Str = "q" 后同句必须通过（证拒绝确因缺少实现，而非名字或语法）。
- 可观测点：HIR 存在类型节点 + 满足证据（字典）。
  现状：trait 关键字尚未落地（样本侧 class 15 处、trait 0 处，P-9 报告 §7），本属步骤 0.2 之后才有可跑形态。

### ST-5 泛型类型参数可为特质

- 规则陈述：List[Show] 这类「特质作泛型实参」合法。
- 正例：

  期望：通过（List 协变 + Show 满足位）。
- 负例：实参不满足特质：

- 判据：对照例 listOf[Point](…)（Point 满足 Show）必须通过；Q/Point 均已声明。
- 可观测点：泛型实参位的子类型检查痕迹（诊断位置指向实参位）。

### ST-6 底类型 Nothing（单向）

- 规则陈述：Nothing <: T 对任意 T 成立；反向 T <: Nothing 不成立（T ≠ Nothing）。
- 正例：发散体赋任意声明返回位（既有 ADR-18 行为）：fun f(): Nat { panic() } 或 var n: Nat = panic()。期望通过。
- 负例（必须）：**fun f(): Nothing = 5** —— 期望 E-TYPE-MISMATCH（实际 Nat，期望 Nothing）。
- 判据（排除替因）：5 的类型推导确定为 Nat（非 synthetic——诊断须给「实际 Nat / 期望 Nothing」）；对照例 fun f(): Nat = 5 必须通过。**今日基线**：因 TypeInfer.adaptOkBody:284 的 isNothingT(got) || isNothingT(want) 双向放行，此负例今日**通过**——这正是 P-10 步骤 1 要求的「此前能过、现在必须报错」型反例，其转红是**预期红**（§3 预期红清单 R1）。
- 可观测点：诊断实际/期望类型对；Nothing 若按 L4 真类型化，还应在符号表登记、可被 is 判定（收口勾选）。

### ST-7 函数类型变构性（参数逆变 + 返回协变）

- 规则陈述：(A) => R <: (B) => S ⟺ B <: A 且 R <: S。
- 正例（返回协变）：var f: (Nat) => Int = { n: Nat => n }（Nat→Int 升塔，返回位合法放行）。期望通过。
- 正例（参数逆变）：var f: (Int) => Nat = { n: Nat => n }（参数位 Nat<:Int，函数更一般可赋特定期望）。期望通过。
- 负例（必须）：**var f: (Int) => Nat = { n: Int => n } 之外的直接形态**——按任务书口径：
    var g: (Int) => Nat = …（实参为 (Nat) => Nat 类型值）
  即把 (Nat)=>Nat 赋给 (Int)=>Nat 变量：参数位 Int 不是 Nat 的超类型（需 Int <: Nat 不成立）→ **期望 E-TYPE-MISMATCH**。
- 判据（排除替因）：对照例 —— 把同一函数值赋给 (Nat)=>Nat 变量必须通过；两侧都已声明（排除未定义名）。**今日基线**：TypeInfer.adaptOkBody:309-311 对参数位与返回位用同向 adaptOk（双协变），此负例今日**通过**——预期红 R2。
- 可观测点：诊断须指向**参数位**（位置列在诊断内），证拒绝源于变构性而非别处。

### ST-8 联合类型（单向注入）

- 规则陈述：A <: A | B（注入单向）；A | B 不可当 A 用，消去须 is 收窄。
- 正例：var u: Nil | Cons[Nat] = Cons(1, Nil)（成员注入联合）。期望通过（t41 既有行为）。
- 负例（必须）：**var y: Cons[Nat] = someUnion**，具体形态：
    struct Nil
    struct Cons[T](head: T, tail: List[T])
    type List[T] = Nil | Cons[T]
    @impure fun main() { var u: List[Nat] = Cons(1, Nil); var h: Cons[Nat] = u }
  期望：E-TYPE-MISMATCH（实际 List[Nat] 联合，期望成员 Cons[Nat]，未 is 收窄）。
- 判据（排除替因）：u 已通过合法注入得到 List[Nat]（自洽，无未定义名）；对照例：经 is Cons(h, t) 收窄后赋值必须通过（P-9 既有 list.subl ground 形态）。
- 今日基线：期望位为成员、实际为联合时 adaptOk 无规则（:287-311 均不命中）→ 今日**应已报错**；本条属于**确认型验收**（防回归），不是预期转红项。
- 可观测点：联合展开诊断位置（D-INDUCTIVE-TYPE 类补充若触发须可追）。

### ST-9 特质继承（父子子类型 + 规范并集）

- 规则陈述：trait Sub[T] : Base[T] 保留，Sub <: Base，规范取并集（TS-8 继承闭包有效）。
- 正例：
    trait Base[T] { fun b(): Nat }
    trait Sub[T] : Base[T] { fun s(): Str }
    struct W(v: Nat)
    fun W.b(): Nat = v
    @impure fun main() { var x: Base = W(1) }      // W 满足 Base（经 Sub 并集路径不需要，直接满足亦可）
  期望：通过。更严格的正例：W 只实现 Sub 的并集（b 来自 Base、s 来自 Sub），以通过 Base 直接装箱。
- 负例：W 缺并集中某成员：
    struct V(v: Nat)      // 只有 b，无 s —— 但 V 直接满足 Base 是否合法？
  更干净的负例（规范并集方向）：声明 trait Sub[T] : Base[T] 但 Sub 体内**未覆盖** Base 的全部成员 → **期望声明层并集校验码（待创/待登记；调用点位已有 E-TC-NOT-SATISFIED——Elaborator.kt:2365，语义/位置不同，不可混用）**——声明层并集校验，与实例层满足判定分开。
- 判据：对照例：补全成员后同一 trait 声明必须通过。排除替因：成员名均为已声明函数形态。
- 可观测点：继承闭包在 HIR 特质节点上的投影；诊断指向缺失成员所在父特质。

### ST-11 顶端类型 Any（真类型化）

- 规则陈述：T <: Any 为真子类型关系；Any 须成真类型（可作变量类型、可被 is 判定、出现在诊断文本）。

### ST-12 变构性自动推断（位置极性复合）

- 规则陈述：特质类型参数按使用处位置自动推断协变/逆变/不变（形参负、返回正、函数类型内负×负=正、@mut 下不变、嵌套泛型乘极性；递归不动点迭代）。
- 正例（复合极性）：trait F[T] { fun g(op: (T) => Nat): Nat } —— T 在「函数参数位的函数参数位」= 负×负 = 正 → 协变。
- 负例（必须，防止极性误算）：**负×负=正的判反形态**。若实现错把 T 算逆变，则 [T: Nat] 的界方向判反（该收上界变下界），用调用点观察：
    trait F[T] { fun g(op: (T) => Nat): Nat }
    fun use[T: Nat](x: T, f: F[T]): Nat = f.g({ n: T => 0 })
    // 若 T 判为协变→上界 T<:Nat：use[Int] 合法、use[Str] 报错
    // 若误判逆变→下界 Nat<:T：use[Str] 合法、use[Int] 报错（方向颠倒）
  期望：use[Int] 通过、use[Str] 落错（上界语义）。**双向对照**：use[Str] 落错 + use[Int] 通过 = 上界判定正确；反向组合 = 极性算反，判失败。
- 判据：界方向的两种表现形态（合法实参集合的翻转）是变构性推断的**唯一直接可观测面**；辅以 HIR 变构性标记（若步骤 3 输出）。
- 今日基线：无变构性推断（泛型实参位当前为同向逐参 adaptOk，:300-301）；无 e2e 样本使用 [T: X]（0 处）——**ST-13/ST-12 无样本回归保护，必须新建测试**（本方案 §7 G7）。

### ST-13 界的方向由使用处变构性推断（不变则报错）

- 规则陈述：[T: X] 中 X 是上界还是下界由 T 的位置极性定；协变→上界、逆变→下界、不变→非法落 E-BOUND-INVARIANT。
- 正例（协变上界）：fun showAll[T: Show](xs: List[T]): Str → T 只出现在协变位 → 上界 T <: Show。
- 正例（逆向下界）：T 只出现在**直接形参位**：fun g[T: Nat](a: T): Nat → T 纯负位 → 逆变 → 界为下界 Nat <: T。期望实参集合形态：g[Nat] 通过；g[Str] 因 Str :> Nat 不成立、按偏序不可比 → 落错或走解选择（以实现方 ADR 为准）。
  → 逆向下界的可观测面就是「合法实参集合与协变形态互补」：同一 [T: Nat] 下，T 用在返回位（协变→上界）时 g[Str] 报错而 g[Nat] 通过；T 用在形参位（逆变→下界）时方向反转。
  ⚠️ **此区域语义最需要在步骤 3 开工前由实现方写清并 ADR 登记**——方案只锁住「界方向可由合法实参集合的双向对照观察」这一验收通式（见 ST-12 负例）。
- 负例 1（必须，不变带界）：**fun f[T: Nat](a: T, b: T): T** —— T 同时在形参（负）与返回（正）→ 不变 → **期望 E-BOUND-INVARIANT**（文案按 L6：「类型参数 T 在使用处既作协变又作逆变（不变），`:` 界无法确定是上界还是下界；请改为 [T] 不加界，或调整使用处使 T 的变构性单一」）。
- 负例 2（判据对照）：同形态去掉界 fun f[T](a: T, b: T): T 必须**通过**——证拒绝源于「带界 + 不变」而非语法（「加界报错、去界通过」= 界导致拒绝的佐证）。
- 判据（排除替因）：负例 1 与负例 2 的差集 = E-BOUND-INVARIANT 的落点；任何其它原因的拒绝都无法做到「去界即通过」。
- 今日基线：E-BOUND-INVARIANT 全仓 0 命中（main+test）——待创码；[T: Nat] 今日被 E-TC-BOUNDARY 拒（Elaborator.kt:1969 等 5 处），故负例 1 **今日即报错但是错码**——验收须核对码名而非只看「报错了」。⚠️ 这是「负例被放宽/漂移通过」门禁（G3）的高风险点：实现方可能复用 E-TC-BOUNDARY 应付，必须拦。
- 可观测点：诊断码 E-BOUND-INVARIANT + 位置指向界声明位。

### ST-14 `:` 与满足判定的统一（E-TC-BOUNDARY 语义作废）

- 规则陈述：T : Show ⟺ T <: Show ⟺ T 满足 Show；[T: Nat] 变合法（上界 Nat）；satisfiesCheck 并入子类型偏序判定。
- 正例：fun f[T: Nat](a: T): Nat = a（界为具体类型，合法）。
- 负例（必须）：fun f[T: NoSuchType](a: T): Nat —— 界的类型不存在/不可为界 → **期望改造后的 E-TC-BOUNDARY（「界的类型不存在/不可为界」新语义）或 E-UNBOUND-NAME**（二选一须在 P-10 ADR 登记）。
- 判据（排除替因）：NoSuchType 未在文件/符号表声明（若同名已声明则换名）；对照例 [T: Nat] 必须通过（同一句法位置、仅界名不同——拒绝确因界名无定义）。
- 反向门禁（G5）：L7 要求 E-TC-BOUNDARY 「约束必须是类型类」旧语义**不可达**——验收方式 grep 实现树：旧码路径全部删除或改写，且码名迁移台账.md 已登记（旧名/新名/位置/ADR 与测试同步）。⚠️ 依 L2，未登记者一律视为未改。
- 可观测点：偏序判定成为唯一相容性判据（步骤 2 验收口径：adaptOk 中所有「特例放行」逐条迁移为偏序规则或删除——旧路径已死）。

### ST-15 燃料与不可停机拒绝（兜底）

- 规则陈述：双向类型检查须燃料保证有限停机；耗尽 → 拒绝并落 E-FUEL-EXHAUSTED，文案严格为「编译器进行检查时无法停机」，不得降级、不得吞、不得改 warn。
- 正例（不误伤）：正常代码与合理深度嵌套不耗尽——e2e 全绿基线即证（FUEL_DEFAULT 取「正常代码消耗的 100 倍以上」量级）；步骤 1-4 每步回归不新增 D-FUEL-EXHAUSTED 于既有样本。
- 负例（必须，发散结构比较）：诱导别名↔联合互追（t47/R-28 双向合一 × 归纳别名）：
    struct Zero
    struct Succ[T](n: T)
    type Peano = Zero | Succ[Peano]
    @impure fun main() {
        var a: Peano = Succ(Zero)
        var b: Succ[Peano] = a            // 联合→成员反向（ST-8 负例同源）
        var c: Peano = b                  // 再注入回去，诱导互追
    }
  期望：**E-FUEL-EXHAUSTED + 补充 D-FUEL-EXHAUSTED**（附件含①触发位置②检查目标实际/期望③已消耗步数与上限④建议）；exit 1；**绝不允许通过**。
- 判据（排除替因）：对照例——去掉 c 行（单次注入/反向，无互追）必须按 ST-8 落 E-TYPE-MISMATCH 而非燃料耗尽（证燃料消耗源于展开发散而非样本本身非法）；若单次反向就耗尽燃料，说明预算过低（G8）。
- 今日基线：**已实现**（TypeInfer.kt:115 文案逐字 + :120-122 附件 ①②③④ + :101-108 步预算 + :85-86 深度哨 + checkScope 池语义 :126-134）——确认型验收 + 反向门禁 G4（grep 确认无降级分支：fuelExhausted 只走 diag.error，无 warn/吞掉路径）。
- 可观测点：D-FUEL-EXHAUSTED 的③已消耗步数（验收时记录数值作为预算回归基线；ST-15.5：若递归类型场景经常耗尽，说明缺的是余归纳假设集而非预算，须单独立项）。
