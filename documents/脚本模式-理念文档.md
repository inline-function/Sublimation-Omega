# 脚本模式

> 本文档是理念文档

## 不再出现的main函数

脚本模式中语句无需写在main函数中，可以直接写在顶层，顺序执行。

## 完全类型推导

脚本模式理应支持完全不标注类型，还能做到自动推导并保证健全。意思是决不退化为类似js/python那种不检查类型的情况，只是编译器自动推导出类型而已。

函数参数、结构体属性、变量类型都理应可以不标注类型，全部依照使用处约束推导出唯一的类型。

比方说如下：

```
fun f(n) = 1 + n
```

此时推导出一个使用点`Nat.+(Nat)`，这产生对n的类型`T`产生约束`T <: Nat`，于是T就自动推导为`Nat`。我们的类型系统类似于完整的`F<:ω`，这导致检查与推导都是不可判定的，我们需要思考通过上下文系统与自动证明器取得可判定性。

## 上下文提升

某个函数内部使用了不纯函数，则自动推导这个函数是不纯函数，即自动增加`@impure`；类似的，对于变量，如果检测到对它的二次赋值，自动增加`@mut`。

某函数是递归函数，但是没有通过停机检查，编译器会把函数退化为非纯函数。

某函数内部使用了需要上文的函数f，但是函数无法证明这个f的上文，于是编译器就自动为这个函数加上了f的上文，即证明义务上提。

## 显式借用

在编译模式下，明确区分引用和非引用类型，非引用类型之间的赋值会发生深拷贝。在脚本模式中无需标注类型，因此需要程序员显式表达借用。

```
fun f(list) {
    list.add(0)
}
var list = mutableListOf()
f(&list)
```

通过使用`&`，表示对一个变量显式地借用分享同一个引用。
