# P-12 证明驱动的类型精化（前瞻设计）

> 状态：**前瞻稿**。V1（P-11）不实现，只预留接口。
> 来源：用户 2026-11-08 00:0x～00:2x 三轮口述裁决。

## 1 用户裁决原文

A. 证明可救推不出类型的程序：

> 「`id` 函数有一个自然命题 `∀x. id(x) = x`，而 `1 + id(1)` 则要求 `id(1) : Nat`，从 `∀x. id(x) = x` 推出 `id(1) = 1`，而 `1 : Nat`，于是推出 `id(1) : Nat`，恰巧通过类型检查。我们不要求第一版就做这个，但是我们要知道需要记下——使用自动证明器可以智能转换函数类型。」

B. 自然命题的产生范围（**精确化**）：

> 「对非纯函数，不产生有关它函数体相等的自然命题，也就是你说的不展开，**仅在单表达式纯函数上**产生我说的那个自然命题。」

C. 公理是信任：

> 「`axiom` 应该允许用户产生任何的命题，包括类型的智能转换，**这是编译器对用户的信任**。」

## 2 自然命题的产生范围（裁决 B 落实）

| 函数形态 | 生成 `∀x. f(x) = body`？ |
|---|---|
| 单表达式 + 纯（`fun f(x) = body`） | ✅ 生成（按定义重写规则） |
| 多语句体 | ❌ 不生成 |
| 推导为 `@impure`（含不纯调用） | ❌ 不生成 |
| 递归 / 相互递归 | 命题可生成，展开须有终止依据（V2） |

**这条同时定下了归约的边界**：归约 = 单表达式纯函数的重写规则，**不是**任意函数体展开。

## 3 架构：类型推导的四级漏斗

```
待解约束（P-11 求解器解不出的那些）
      ↓
① 约束求解（最小解 + 极性 + R 轮）              ← P-11
      ↓ 解不出
② 定义性归约：单表达式纯函数重写 + 常量折叠      ← P-12 第一级（V1.5）
      ↓ 归约后仍不定
③ 证明通道：(e : T) 判定 + 定理/公理            ← P-12 第二级（V2）
      ↓ 仍不成
④ 拒绝：诊断列出冲突使用点 + 可尝试方向
```

每一级都要在 HIR 记录 `provenance`：`constraint-solve` / `reduce` / `proof:definitional` / `proof:user-axiom`。**接受路径必须可追溯**。

## 4 信任模型（裁决 C 落实）

### 4.1 裁决
- 用户 `axiom` **可以**参与类型精化，**放宽与收紧都允许**；
- 本语言**不承诺无条件健全**：健全性以**用户公理为条件**（trusted base）。这是设计选择，不是缺陷；
- 一行 `axiom "abc" : Nat` 可以让该程序的类型检查失效——**这是被明确授予的权力**。

### 4.2 但信任必须可见、可审计（工程要求，不削弱信任）

| 机制 | 作用 |
|---|---|
| HIR `trustedBase` 段 | 列出**参与过类型接受**的每条用户公理（位置 + 命题） |
| `W-TRUST-ASSUMED` | 编译期提示：本次检查有 N 条接受依赖用户公理 |
| `--no-trust`（建议） | CI 模式：凡接受依赖用户公理即判失败——**用于验收管道，不用于日常开发** |
| `provenance: proof:user-axiom` | 单条类型位的来源标记 |

**理由**：信任不等于失明。用户有权断言任何命题，也有权知道自己的程序建立在哪些断言之上。这与「诊断第一职责是告诉用户真相」是同一条纪律。

### 4.3 不纯函数不参与归约（裁决 B 的语义后果）

```
@impure fun read(): Nat = nextRandom()
// 不生成 ∀x. read(x) = nextRandom() ⇒ 永不展开 ⇒ 语义不被改变
```

推导为 `@impure` 的函数一律不产生自然命题，因而不参与第 ② 级；但**仍可参与第 ③ 级**（用户若为它写了 `axiom`，那是用户的断言）。

### 4.4 终止性

| 情形 | 处置 |
|---|---|
| 单表达式纯函数（非递归） | 正常重写 |
| 递归 / 相互递归 | 展开须有终止依据（V2）；否则不展开，回落第 ④ 级 |
| 深度/步数 | 计入 t51 燃料池 + 另设 `REDUCE_DEPTH_MAX`；耗尽 ⇒ 停止归约（**不是错误**） |

## 5 与 P-11 的接口（现在就要留）

| 接口 | 作用 |
|---|---|
| `HirType.provenance` | `constraint-solve` / `reduce` / `proof:definitional` / `proof:user-axiom` |
| `HirType.evidence` | 归约链（如「`id(1) → 1` 得 Nat」） |
| `HirUnit.trustedBase` | 参与接受的用户公理清单 |
| `E-INFER-PROOF-DEFERRED` | 判定「本可证明救回」但本版未开时使用 |
| 求解器钩子 | 每个失败元变量留**待救清单**（位置 + 已知下界/上界） |

`E-INFER-PROOF-DEFERRED` 的语义必须写清：**这不是错误，是能力边界**。

文案示例：

> 「无法在有限轮次内确定 `id(1)` 的类型。本版只做约束求解；给定 `id` 的定义，`id(1)` 可归约为 `1 : Nat`——该能力将在下一版提供。**这不是你的程序的错误。**」

## 6 四个难点在完整方案下的结局

| 难点 | 纯 P-11 | 加归约（②） | 加证明（③） |
|---|---|---|---|
| 多态丢失（`id` 用于 Nat 与 Str） | 拒绝 | `id(1)`、`id("a")` 各自重写 ⇒ 两个调用点都过 | 可处理无体/不可归约的情形 |
| 字段无证据 | 报错 | 构造实参可归约 ⇒ 有证据 | 同上 |
| 数值默认（`n - 5`） | 算术约束抬到 `Int` | 同上 | 可用 `axiom n >= 5` **收紧**回 `Nat` |

**证明通道既能放宽也能收紧**，且按 §4.1 **两者都允许用户公理参与**：
- 收紧例：`axiom n >= 5` ⇒ `n - 5 : Nat`（纯推导只能给 `Int`）；
- 放宽例：`axiom "abc" : Nat` ⇒ `"abc"` 可作 `Nat` 用（信任型转换）。

这是本语言相对其他语言的真正独特性：**类型系统与证明系统共用同一个信任基础**。代价是健全性有条件，收益是表达能力没有人为上限。

## 6.1 第一个落地实例：减法非负性收紧（用户 2026-11-08 09:3x 裁决）

> 「`Nat - Nat` 应该返回 `Int`，由自动证明器进行智能转换，比方说当前环境可以证明前 `Nat >=` 后 `Nat`，就智能转换返回值为 `Nat`。」

```
a - b（a, b : Nat）
  Γ ⊬ a >= b  ⟹  Int     （ST-10.1）
  Γ ⊢ a >= b  ⟹  Nat     （ST-10.2，证明驱动收紧）
```

**为什么选它当试点**：
| 理由 | 说明 |
|---|---|
| 不涉及函数体展开 | 只需「算术事实 + 证明」，不需要自然命题/归约 |
| 立刻有实用价值 | 下标算术 `take(xs, n - 1)` 在 `Γ ⊢ n >= 1` 时不再报错 |
| 是**收紧**方向 | 不会放行非法程序——证明失败时行为退回 ST-10.1，错误面不变 |
| 暴露真实缺口 | 队长实测发现证明器**读不懂类型**：`n : Nat` 不产生事实 `n >= 0`（见下）|

**队长实测（09:4x）——使能条件两个都缺**：

| # | 探针 | 实测 |
|---|---|---|
| 1 | `n : Nat` + `axiom n != 0` ⇒ `∵ n != 0 ∴ n >= 1` | ❌ `E-CANNOT-PROVE`（`Γ：!=<n, 0>`）|
| 2 | `if (n == 0) { } else { ∵ n != 0 ∴ n >= 1 }` | ❌ `E-CANNOT-PROVE`（**Γ 为空**）|
| 3 | `∵ a >= b ∴ a - b >= 0` | ✅ 通过 |

第 3 条通过 ⇒ 算术通道没问题；第 1、2 条失败 ⇒ **事实没进来**。故本试点的前置是两件事：
1. **类型事实注入**：`x : Nat ⇒ x >= 0`（已派 t65）；
2. **分支事实注入**：`if (cmp)` 两支注入 `cond` / `¬cond`（已派 t65）。

然后才是 t66 的收窄本身。**顺序不能反**：先做收窄而没有事实，收窄永远不会触发，等于白写。

## 7 开放问题

| # | 问题 | 备选 |

| Q1 | 归约是否允许跨函数边界（`f(g(x))`） | 建议允许，计入深度；否则 `id(id(1))` 救不回来 |

## 8 路线

| 阶段 | 内容 | 前置 |
