## 一、机制回顾（R-38 闸的位置）

```
TypeInfer.reportMismatch(got, want, pos, msg):
  if (fuelExhaustedNow()) return            // t51/t52 口径
  if (containsSynthetic(got) || containsSynthetic(want)) return   // R-38：推导未完成容忍
  diag.error("E-TYPE-MISMATCH", pos, msg)   // 真失配（两边均具体）照报
```

合成位的两个来源家族：(a) **无签名/无根因**（未知字段、无签名方法糖、prelude 方法）——本身无根因诊断，
经闸全静默；(b) **lambda 形参位未回代 / 泛型位未解**——lambda 型含合成叶，闸容忍。家族 (b) 在实参位
且形参具体时由 ADR-22 回代消解（见负向证据 N1），因此掩盖是**位置特异**的。

## 六、任务 4：looseEq 旧路径审查（8 处）

looseEq 自身：`if (a.isSynthetic() || b.isSynthetic()) return true`（TypeInfer.kt:305 定义，第 310 行
参数位递归）——自带 synthetic 放行，独立于 R-38 闸。

| 调用点 | 上下文 | 能否掩盖真失配 | 理由（谁保证） |
|---|---|---|---|
| TypeInfer.kt:453/461 | unifyInto 内部（cur != null → looseEq(cur, bb/aa)） | 不作诊断（仅影响解集） | 合一侧不产生绑定（loose 匹配只返回 true）；下游由 M 族/具体通道处理，不构成额外掩盖 |
| TypeInfer.kt:507 | unifyInto 非名义分支 | 同上 | 同上 |
| TypeInfer.kt:676 | binExpr 中缀比较族前置 isNominal() | **不能** | isNominal（第 278 行）显式排除 isSynthetic()——合成操作数到不了 looseEq；合成情形走第 622/628 行的 !isSynthetic 旁路（= M3，已登记同族） |
| TypeInfer.kt:687 | binExpr 中缀非比较族 | **不能** | 同上（isNominal 前置） |
| Elaborator.kt:862 | FieldExpr 方法糖内建分派 looseEq(tt, bt.first[0]) | **能**（登记 M2 同族） | 接收者合成型会匹配任意内建首参 → 返回内建型；掩盖「接收者型不对」——但根因仍是 M2 的无根因合成接收者，随第四节序 1 的签名字典自然消解 |
| TypeInfer.kt:305/310 | looseEq 定义与其 args 位递归 | 不适用（定义体） | 递归深入仅用于参数位一致判定，见上各行结论 |

结论：looseEq 的 8 个调用点中，binExpr 两点（676/687）由 isNominal 机械排除合成位，**不能掩盖**；
unify 内部三点不发射诊断；唯一能掩盖的是 Elaborator.kt:862（FieldExpr 内建分派），与 R-38 的 M2 族
同源同批（合成接收者本身无根因），随清零路线序 1 消解。
