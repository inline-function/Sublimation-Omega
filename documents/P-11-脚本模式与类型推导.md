## 1 范围与非目标

### 1.1 目标
`.subs` 脚本文件的两个要点：
1. **不写 `main`**：顶层直接写语句（**现状已支持**，`--script` 已验证）；
2. **无标注风格**：函数返回类型、形参类型、结构体字段类型、变量类型**全部可省**；`@mut`、`@impure` **也可省**，由使用处反推。

### 1.2 非目标
- 不做 let 多态（V1 单态，见 §3.7）；
- 不做调用点特化（V1 不复制函数体）；
- **不做证明驱动的类型转换**（V1 只做约束求解；归约与证明通道见 `P-12-证明驱动的类型精化-前瞻.md`）；
- 不改 `.subl` 既有语义：`.subl` 仍要求标注，**推导只发生在 `.subs`**（判定 `.subl` 里出现省略位 ⇒ 维持现有 `E-SYNTAX`）。
  - （t104 注，2026-11-10）R3 任务书待裁项 **C-1** 提的是同一问题（同一文本 `.subl` 硬拒 / `.subs` 推导的分歧确认）。本文此条为既定设计稿口径；裁决归属队长，本文不代裁。

## 2 `.subs` 与 `.subl` 的差异

| 项 | `.subl`（工程模式） | `.subs`（脚本模式） |
|---|---|---|
| `main` | 必需 | **不需要**，顶层语句按序执行 |
| 形参/返回/字段/变量类型 | 必需 | **可省** |
| `@mut` | 必需（写可变才有） | **可省**（推导） |
| `@impure` | 必需 | **可省**（推导） |
| 显式标注 | 必需 | **允许**，作为**约束**参与求解（不是覆盖） |

**HIR 不合成假的 `main`**。`unit.mode = "script"` + 顶层语句有序列表；诊断位置指向用户真实书写处。理由：SynthesizeMain 会让诊断出现「main 里第 3 行出错」，而用户从未写 `main`——用内部实现污染用户视角。

## 3 类型推导

### 3.1 元变量
每个省略位生成一个**元变量** `?α`，带**来源位置**（声明处）与**空位种类**（形参 / 返回 / 字段 / 局部变量）。

元变量必须可追溯：HIR 中落 `inferred` 标记与 `evidence`（参与求解的使用处位置列表）。

### 3.2 约束
每处使用产生一条子类型约束（**复用 `adaptOk` 语义，不另立判据**）：

```
实参 e 传入形参 ?α            ⟹  typeof(e) <: ?α          （下界）
?α 出现在函数体需 τ 的位置      ⟹  ?α <: τ                  （上界）
返回位 ?β：body 类型 <: ?β     ⟹  typeof(body) <: ?β        （下界）
调用方要求 ?β <: τ             ⟹  ?β <: τ                  （上界）
```

于是每个元变量有一组**下界**（`L`）与一组**上界**（`U`）。

### 3.3 最小解定理（为什么不需要搜索）
取 `候选 = lub(L)`，校验 `候选 <: U` 中每一条。

**定理**：若 `lub(L) ⊀ u`（某条上界），则**不存在**任何解。
理由：任何解 `s` 必满足 `lub(L) <: s`；而约束 `s <: u` 对 `s` 单调反向（`s` 越大越难过）。故 `lub(L) <: s <: u` 要求 `lub(L) <: u`，矛盾。

**推论**：最小解是**最优候选**，往大处找永远没救。因此「有限轮次」不是格上爬升搜索，而是**结构传播的不动点**：
- `List[?α]` 与 `List[Nat]` 相遇 ⇒ 解需推进到元素层；
- 递归函数 ⇒ 从 `⊥` 迭代到不动点。

这正对应用户裁决：**迭代到不动点，最多 R 轮；R 轮不收敛 ⇒ 拒绝**。

### 3.4 极性与变构性（复用 ST-13）
若元变量处于**逆变位置**（函数型形参内），最小解方向反转：

| 极性（**按视图判定**，ST-13.1）| 取法 |
|---|---|
| 正（协变）| `lub(下界)` |
| 负（逆变）| `glb(上界)` |
| 不变（推导位）| **等式约束**：两方向都收，取交（如 `@mut List[?T]`）|
| 不变（声明位，写了界）| **报错** `E-BOUND-INVARIANT`（ST-13 / L6）|

视图决定变构性：`List[?T]` 协变 ⇒ 取 `lub`；`@mut List[?T]` 不变 ⇒ 取交。**同一个类型参数在不同视图下极性不同**，故求极性时必须知道当前视图（ST-13.1 的 `(σ_imm, σ_mut)`）。

极性计算**必须复用 P-10 步骤 3 的变构性推断**，不得另写一套——否则会出现「推导用的极性」与「子类型用的极性」两份真相。

#### 3.4.1 两种「不变」必须分开（**关键区分，易混**）

| 情形 | 例子 | 处置 |
|---|---|---|
| **声明位**不变：类型参数在声明体里两个方向都用到，且**写了界** | `fun f[T: Nat](a: T, b: T): T` | **报错** `E-BOUND-INVARIANT`（ST-13 / L6：界的方向无法确定）|
| **推导位**不变：元变量落在不变位置 | `MutableListOf()` 的元素类型 `T` 在 `@mut List[T]` 中不变 | **不需要报错**：不变 ⇒ 约束是**等式**，两方向都收，取交即可 |

两者不矛盾：**声明位的界**要求编译器猜一个方向（猜错就是静默错误），而**推导位的元变量**两边都是约束，取交是机械的。

### 3.5 不动点与轮次上限
| 项 | 规定 |
|---|---|
| 迭代单位 | 一轮 = 一遍全量约束求值 |
| 收敛判据 | 本轮解与上轮解**结构相等**（`typeEq`）|
| 上限 | 常量 `INFER_ROUNDS_DEFAULT`，初值 **8**，允许调试期覆盖 |
| 超限 | **拒绝**，落 `E-INFER-NOT-CONVERGED` |
| 预算 | 求解期所有 `adaptOk` 调用**必须计入同一燃料池**（t51 机制），不得开新池 |

单线程、声明序遍历，保证**同输入同结果同轮数**。

### 3.6 无证据与默认
| 空位 | 处置 |
|---|---|
| 形参无任何使用处 | `Nothing`（底类型：任何实参可传，最宽松且健全）**用户裁决** |
| 结构体字段无任何使用处 | 见 §10-Q3（V1 建议报错 `E-INFER-NO-EVIDENCE`）|
| 字面量 `5` | `Nat`，由算术约束自然抬升（`n - 5` 引入 `Int` 下界 ⇒ 解为 `Int`）|
| `ListOf()` | 声明返回 `List[Nothing]`（协变：可赋给任意 `List[T]`）|
| `MutableListOf()` | 声明返回 `@mut List[T]`，`T` 为**新鲜元变量**（不是 `Nothing`）|
| `MapOf()` / `MutableMapOf()` 等 | 同构：不可变取 `Nothing`，可变取新鲜元变量 |

**默认填的必须标记 `defaulted: true`**，与 `inferred: true` 区分。默认不是推导，不能让读者误以为有证据。

**注意**：默认只用于「**完全没有证据**」的元变量。一旦出现任何写操作（如 `xs.add(1)`），该元变量就有证据，走 §5.1 的等式合成——**不适用默认**。

### 3.7 单态（V1 裁决）
用户裁决：**多态性丢失的节目，第一版拒绝**。

```subl
fun id(x) = x
print(id(1) + 1)      // 要求 x: Nat
print(id("a") + "b")  // 要求 x: Str
```
最小解把 `x` 聚合为 `Nat | Str`，返回类型同为 `Nat | Str` ⇒ `id(1) + 1` 不合法 ⇒ **拒绝**。

诊断须**指出两处冲突使用**，并给出「拆函数 / 加一处标注」的建议。不要只说「无法推导」。

### 3.8 四级漏斗（**本文只实现第 1 级**）
```
1 约束求解（最小解 + 极性 + R 轮）        ← P-11 唯一实现
2 符号归约（纯函数体展开 / 常量折叠）      ← P-12，V1.5
3 证明通道（(e : T) 判定，ADR-13 推迟项）  ← P-12，V2
4 拒绝（诊断列出冲突点）
```
第 2/3 级的意义：用户指出本语言**内置自动证明器**，`id` 有自然命题 `∀x. id(x) = x`，可推 `id(1) = 1`，而 `1 : Nat`，故 `id(1) : Nat`。**V1 不做，但必须预留接口**（HIR 的 `provenance`/`trustedBase` 位、诊断的「可尝试的方向」文案）。

两条已落定的边界（见 P-12）：
- **自然命题只在单表达式纯函数上产生**（多语句体、`@impure` 函数一律不产生 ⇒ 永不展开）；
- **`axiom` 是编译器对用户的信任**：允许用户断言任意命题（含类型智能转换），**放宽与收紧都允许**；健全性以用户公理为条件，但须 `trustedBase` + `W-TRUST-ASSUMED` + `--no-trust` 可审计。

## 4 纯度推导（`@impure`）

调用图上做单调不动点：
1. 初值：函数体含**顶层语句**、或调用内建不纯操作（`print` 等）、或含 `@impure` 标注 ⇒ 不纯；
2. 传播：`f` 调用 `g` 且 `g` 不纯 ⇒ `f` 不纯；
3. **SCC**：强连通分量内任一成员不纯 ⇒ 整个 SCC 不纯（相互递归中一处有副作用，全体有）；
4. 迭代到不动点（单调，最多 `|V|` 轮，必然终止）。

脚本顶层语句本身即不纯（要执行），故脚本的隐式入口恒为不纯。

## 5 可变性推导（`@mut`）

**单调增长**：只要有**任何一处**使用要求 `@mut`，声明即为 `@mut`。

| 触发 | 说明 |
|---|---|
| 局部变量被赋值（声明初始化式之外）| `x = ...` 出现即 `@mut` |
| 形参被赋值 | 同上 |
| 形参/变量被传入 `@mut` 接收者位 | 需要可变能力 |
| 字段被赋值 | 该字段可变（见 §10-Q2：字段可变性是否进类型）|

方向是**只能加不能减**，故为一次单调闭包（与纯度同构），无需轮次上限。

**与 t60 的依赖（t104 刷新，2026-11-10）**：赋值类型核对已由 t60 落地（`Elaborator.kt:836` 注「t60-1：赋值类型核对」在位，qa t103 复核）——前置条件**已满足**，可变性推导与类型推导可直接共用赋值通道。旧文本「t60 修复中，必须等」已删（过时）。

### 5.1 容器构造的类型合成（用户 2026-11-08 00:17 裁决）

> 「`ListOf()` 返回 `List[Nothing]`；`MutableListOf()` 返回 `@mut List[Nothing]`。但如果后面有类似 `xs.add(1)` 的语句，编译器理应收集约束，硬性要求 `xs` 的 `add` 应接受 `Nat`，也就是说要求 `@mut List` 的首类型参数 `T` 能接受 `Nat`；因为 `@mut List` 的首类型参数是**不变的**，因此 `T` 必须是 `Nat`。编译器发现 `T` 是 `Nat` 不会引起其他位置冲突，就认为 `xs` 的类型应该是 `@mut List[Nat]`。这个逻辑类似 Kotlin 的类型合成器。」

**规则形式化**：

```
var xs = MutableListOf()        ⟹  xs : @mut List[?T]，?T 新鲜元变量
xs.add(1)                       ⟹  Nat <: ?T   （实参位，正）
                                    ?T <: Nat   （@mut List 的参数不变 ⇒ 反向也收）
                                ⟹  ?T = Nat     （不变 ⇒ 等式约束，取交）
无其他冲突                         ⟹  xs : @mut List[Nat]
```

| 情形 | 结果 |
|---|---|
| `?T` 的等式解与其他位置无冲突 | **接受**，定 `T = Nat` |
| 另有 `xs.add("a")` ⇒ `?T = Str` | **冲突**：`Nat ≠ Str` ⇒ 拒绝，诊断列出两处 `add` |
| 从未写入 ⇒ `?T` 无证据 | 回落声明类型 `Nothing` ⇒ `@mut List[Nothing]`（健全，且 `add` 仍可后续写）|

**为什么可变容器必须不变**：`@mut List[T]` 可被 `add` 写入，若允许协变则 `@mut List[Nat]` 当 `@mut List[Any]` 用，再 `add("abc")` 就能把 `Str` 塞进 `Nat` 列表——这正是 ST-1 禁止的。**可变性直接决定了变构性**：`List[T]` 协变、`@mut List[T]` 不变。

## 6 诊断族

| 码 | 时机 | 文案要点 |
|---|---|---|
| `E-INFER-NO-SOLUTION` | lub 与上界冲突 | 列出**冲突的两处使用**（位置 + 类型），给「加一处标注」建议 |
| `E-INFER-NOT-CONVERGED` | R 轮未到不动点 | 说明迭代 R 轮仍在变，多半是递归/多态递归；建议加标注打破环 |

| `E-INFER-PROOF-DEFERRED` | （P-12）证明通道可救但 V1 未开 | **必须写明「这不是错误，只是本版能力边界」**，附可尝试的方向 |

## 8 与既有机制的交互

| 机制 | 关系 |
|---|---|
| 燃料（t51）| 求解期的 `adaptOk` 调用**共用同一池**；另加轮次上限；两者缺一不可 |
| 子类型（P-10 步骤 2）| 推导的 `lub` 就是偏序的 `lub`，**同一实现** |
| 变构性（P-10 步骤 3）| 极性计算**复用**其推断结果 |
| 字典（P-10 步骤 4）| 推导需处理 `T : Trait` 约束 ⇒ **必须在步骤 4 之后** |

**顺序硬约束**：`P-10 步骤 2 → 3 → 4 → P-11`。推导放在偏序/变构性/字典之前，会逼出临时实现，之后返工。

## 9 验收策略

1. **差分对拍**：同一段逻辑分别写成 `.subs`（无标注）与 `.subl`（全标注），两者 HIR 在**忽略 `inferred`/`evidence`** 后必须**结构相等**，运行输出必须一致。
   这条能测出「推导是否补上了应有的类型」，而不是「能不能过」。
2. **负例先红后绿**（沿用 t58/t60 纪律）：拒绝类用例必须先证明它在**全标注版本**下也非法，才能算推导的功劳。
3. **稳定性**：同一输入两次编译，推导结果与轮数**逐字相同**。
4. 门槛：`.subl` 基线不得回退（**874/0**，2026-11-10 R2 轮末验收态——qa t103 读 58 套件 XML 求和复算；旧文本「553/0」系 t58 前数字，由 t104 于 2026-11-10 刷新；e2e 65/68，三冻结红永久豁免）；新增 `.subs` 样本计入**独立分母**，不与 e2e 混算。
