# 符号标识符与中缀命题（设计定案）

> 本文档把用户自 2026-11-08 16:3x 起的一系列裁决整理成**可实现、可验收**的规则。
> 凡与本文冲突的旧描述作废；末尾「待裁决」区是仅存的开放项。

## 0 三句话

> **ASCII 标点是语法；非 ASCII 符号是名字材料；量词与推理标记是关键词。**
> **命题即应用：底层只有 `名字<实参>`，中缀与前缀都是糖。**
> **表达式与命题严格区分：`f(a,b)` 是表达式，`f<a,b>` 是命题。**

## 2 字符类（四类）

| 类 | 字符 | 分词 | 可作名字 |
|---|---|---|---|
| **结构字符** | `( ) [ ] { } , ; . @ \ # "` | 单 token | 否 |
| **关键词** | `∀ ∃ ∃! ∵ ∴` | 单 token，**永不粘连** | **否** |
| **ASCII 符号串** | `! % & * + - / : < = > ? ^ \| ~` | **最大吞噬** | 是（`<:` `++` `=>` `..`） |
| **名字材料** | 字母、数字、`_`、**非 ASCII 符号**（`¬ ∧ ∨ → ↔ ⊗ ∈ ○`） | **最大吞噬** | 是 |

**抢占顺序**：反引号 ＞ 数字 ＞ 关键词 ＞ ASCII 符号串 ＞ 名字材料。
结构字符各自单 token；`$`+数字 保留既有 DOLLAR 特例。

### 2.1 分词样例（每条都要有测试）

| 源 | 分词 | 说明 |
|---|---|---|
| `x+1` | `x` `+` `1` | ASCII 符号不得混入名字 |
| `-7` | `-` `7` | 一元负号 + 数字 |
| `a<:b` | `a` `<:` `b` | ASCII 符号串最大吞噬 |
| `p<a,b>` | `p` `<` `a` `,` `b` `>` | `<` 后是字母 ⇒ 单字符 |
| `a⊗b` | **一个标识符** `a⊗b` | 非 ASCII 符号是名字材料（R1） |
| `¬p` | **一个标识符** `¬p` | N1 的直接后果 |
| `∀x. P<x>` | `∀` `x` `.` `P` `<` `x` `>` | `∀` 是关键词（K1） |
| `p ∧ q` | `p` `∧` `q` | 空格分隔 |
| `1.5` | FLOAT | 数字自定界（吞 `.`+数字） |
| `a.b` | `a` `.` `b` | `.` 结构字符 |
| ``a+b`` | 一个标识符 `a+b` | 唯一允许 ASCII 与字母混用的方式（C1） |

### 2.2 为什么 `<` `>` 必须留在结构字符类（实测）

| 现象 | 计数 | 结论 |
|---|---|---|
| 标识符紧贴 `<`（`p<a,b>`、`P<b>>`、`tagged<7>`） | **83 处** | 若 `<` 参与粘连，角括号应用全灭 |
| 代码里字母/数字紧贴非角括号算符 | **约 0 处** | 粘连规则对既有算术零成本 |

## 3 反引号（B1–B5）

| # | 规则 |
|---|---|
| **B1** | 内容为**任意字符**：结构字符、ASCII 符号、CJK、空格、**裸换行** |
| **B2** | 唯一转义 `\`` = 字面反引号（``\``` ⇒ 名字是一个反引号字符） |
| **B3** | 反引号**不进名字**：``foo`` 与 `foo` 同名（C4） |
| **B4** | 单个/多个空格是合法名字；`` `` 与 ``  `` 是**两个不同**标识符 |
| **B5** | **空反引号** ⇒ `E-BACKTICK-EMPTY`（**已实现，实测 `3:5` 起始位**） |

### 3.1 三处实现风险

| # | 风险 | 要求 |
|---|---|---|
| 1 | 裸换行让 token 跨行 | 行号照常推进；诊断一律指向 **token 起始位置** |
| 2 | 名字可能含换行/制表/引号/反斜杠 | **HIR JSON 必须完整转义**，否则产物非法 JSON（**须有"JSON 可解析"测试**） |
| 3 | 中缀糖依赖「带空格且同行」 | 跨行反引号 token ⇒ **中缀糖不跨行成立** |

## 4 命题即应用（N1）

```
p ∧ q   ⇒  ∧<p, q>       中缀糖
¬<p>    ⇒  ¬ 应用于 p     前缀必须带角括号
¬p      ⇒  一个标识符       不可拆，查不到就报错
f(a,b)  ⇒  表达式调用      R3
```

### 4.1 迁移量（实测）

| 形态 | 计数 | 命运 |
|---|---|---|
| `¬p` / `¬(p)` 紧贴 | **20 处 / 6 文件** | **必须迁移**为 `¬<p>`；`¬¬p` → `¬<¬<p>>` |
| `∀x` / `∃x` 紧贴 | **61 处 / 5 文件** | **零迁移**（K1：`∀` 是关键词，天然分开） |
| `∵` / `∴` 紧贴 | **0 处** | 保持语句标记 |
| 中缀逻辑符（已带空格） | 126 处 | 安全，不需动 |
| `+∵`（`Kind.PLUS_BECAUSE`） | 1 处死 token | **退役**（`Kind.kt:8` 已注"无消费点"） |

### 4.2 嵌套角括号已验证（队长探针，3/3）

```subl
fun conj[a, b]: Null <a & b>
fun f[p, q]: Null <p ∨ conj<p, q>>          // ✅ 通过，尾部 >> 相邻正常
fun h[p]: Null <conj<conj<p, p>, p>>        // ✅ 通过，三层嵌套正常
```

⇒ `¬<p>` 嵌在后件括号里（`<p ∨ ¬<p>>`）**不会**触到配对问题。原风险降级为"已排除"。

## 5 原生命题注册表（**实现契约**）

原生命题对用户**是名字**，对实现**是原生节点**。名字、元数、原生节点三者必须一一对应：

| 名字 | 元数 | 原生节点 | 中缀 | 级别 |
|---|---|---|---|---|
| `¬` | 1（前缀） | `HirPNot` | 否 | — |
| `∧` | 2 | `HirPAnd` | 是 | 8 |
| `∨` | 2 | `HirPOr` | 是 | 7 |
| `→` | 2 | `HirPImp` | 是 | 6（右结合） |
| `↔` | 2 | `HirPIff` | 是 | 5 |
| `=` | 2 | `HirPAtom("=")` | 是 | 9 |
| `≠` | 2 | `HirPAtom("≠")` | 是 | 9 |
| `∈` | 2 | `HirPAtom("in")` | 是 | 9 |
| `:` | 2 | `HirPAtom(":")` | 是 | 9 |
| `<:` | 2 | `HirPAtom("<:")` | 是 | 9 |
| `⊤` | 0 | `HirPTop` | — | — |
| `⊥` | 0 | `HirPBot` | — | — |
| `∀` `∃` `∃!` | 关键词 | `HirPForall` / `HirPExists` / `HirPExists1` | — | — |

**级别列**（t82 更新）= ADR-50 §六 优先级层号（越大越紧）：原生命题连接词 `∧`=8、`∨`=7、`→`=6（**右结合**）、`↔`=5；关系 `= ≠ ∈ <:`（皆归一为原子命题 `HirPAtom`，`∈`→head `in`）与**用户定义中缀**同为 9；算术 `+ - * / % ^` 为 10 但**层内无优先级**（D-10/H-ARITH-PREC）。`¬` 前缀与 `⊤⊥` 不参与层号。
**`⊤⊥` 命题专用**（t79）：仅在命题位合法——值位（表达式/实参/返回/模式）落 `E-PROP-POS` 并提示 `True`/`False`（t84）；原生节点为 `HirPTop`/`HirPBot`（旧写 `HTrue`/`HFalse` 已废）。
**约束**：用户不得重定义这些名字（新码 **`E-NATIVE-REDECL`**，见下）；它们**不进入** `trustedBase`（它们是逻辑常项，不是用户公理）。

### 5.1 保护规则：`E-NATIVE-REDECL`（新增一码，21:2x 裁决）

| 项 | 内容 |
|---|---|
| 触发 | 用户声明与注册表同名的函数/命题（`fun ¬(p) …`、未来的 `∧`/`∨`/`→`/`↔`…）|
| 文案 | 「`¬` 是**编译器内置的原生命题**，不可重定义；若需自定义否定，请换一个名字（如 `not`）」|
| 为何不复用 `E-DUP-DECL` | 用户**只声明了一次**，说「重复声明」是**假话**；真相是「这个名字属于编译器」 |
| 为何不复用 `E-DUP-NAME` | 同上：语义不同（与内建冲突 ≠ 与用户声明冲突）|
| 实现要求 | **表驱动**：从 §5 注册表生成保护名单，P5（`∧ ∨ → ↔`）落地时自动覆盖，不得逐个硬编码 |


## 5.5 结合性与优先级（t82/ADR-50 §六 更新）

> （t82 前裁决原文，见下注）「中缀函数都是**固定左结合**的，比方说 `a f b f c` 的结合顺序是 `(a f b) f c`，`+ - * /` 都是中缀，**所以没有优先级**，意思是 `1 + 2 * 3` 实际上是 `(1 + 2) * 3`。不过，编译器应该对遇见 `+ - * / ^` 的表达式判断一下，如果发现有类似 `1 + 2 * 3` 这种表达式，则输出**提示级别**的诊断，表示**不规范的代码**，应该显式通过**圆括号**指定。」

### 5.5.1 定案（A1–A3 原裁决；A4 为 t82 后增补）

| # | 规则 |
|---|---|
| A1 | **用户定义中缀与算术层内**一律左结合、无优先级。`a f b f c` = `(a f b) f c`；`2 ^ 3 ^ 2` = `(2^3)^2` = 64。**例外**：原生命题连接词 `∧ ∨ → ↔` 有优先级（A4）——用户中缀本身仍无优先级，与关系/算术混排时按 9 层统一分派 |
| A2 | `+ - * / ^ %` 都是普通中缀，**没有一个是"高级"运算符** |
| A3 | 混用不同"传统优先级类"的算符 ⇒ **提示级诊断** `H-ARITH-PREC`：不规范，建议显式圆括号 |
| A4 | **原生命题连接词有优先级**（t82 用户裁决 Q22 / ADR-50 §六）：`∧`=8、`∨`=7、`→`=6（右结合）、`↔`=5，关系与用户中缀=9。**本节 A1–A3 的适用范围**：用户定义中缀与算术层——A1 仍成立（用户中缀 `a f b f c` = `(a f b) f c`、无优先级），只是原生命题连接词不再适用。 |
| | **值位 `∧ ∨ → ↔` 的终态**：拒绝并提示 `&`/`|`（`→`、`↔` 提示「命题专用」）——**实现延后，t92 落地**（现行 `TypeInfer.builtinOps` 仍按值位回落，勿写成「已拒绝」）。 |

### 5.5.2 提示的触发规则（按裁决重写）

在**同一括号层级**内，若一条算术链同时出现下列**不同类**的算符 ⇒ 提示：

```
类 1：^            类 2：* / %            类 3：+ -
```

| 写法 | 应否提示 | 理由 |
|---|---|---|
| `a + b * c` | **提示** | 跨类 |
| `a * b + c` | **提示** | 跨类（左结合下虽与直觉一致，但仍属混用不规范）|
| `a ^ b * c` / `a + b ^ c` / `a % b + c` | **提示** | 跨类 |
| `a + b + c` / `a - b + c` / `a * b / c` | 不提示 | 同类，左结合无歧义 |
| `(a + b) * c` | **不提示** | 用户已显式加括号，本意明确 |

### 5.5.3 现状实测（队长探针 9 条）—— **当前实现不对称且有误报**

| 探针 | 源 | 现状 | 应有 |
|---|---|---|---|
| h1 | `a * b + c` | **0 提示** | 1（漏）|
| h2 | `a + b / c` | 1 提示 | 1 ✓ |
| h3 | `a ^ b * c` | **0 提示** | 1（漏）|
| h4 | `a + b ^ c` | 1 提示 | 1 ✓ |
| h5 | `a + b + c` | 0 提示 | 0 ✓（同类）|
| h6 | `(a + b) * c` | **1 提示** | **0（误报！用户已加括号）** |
| h7 | `a - b + c` | 0 提示 | 0 ✓（同类）|
| h8 | `a * b / c` | 0 提示 | 0 ✓（同类）|
| h9 | `a % b + c` | **0 提示** | 1（漏）|

⇒ 现在的规则是"右侧算符比左侧紧才提示"，且**不区分括号层级**。按裁决须改为"同类不提示、跨类必提示、括号内重置层级"。

## 6 固定性（fixity）

| 情形 | 固定性 |
|---|---|
| 内建/原生命题 | 用 §5 表 |
| 用户二元函数/命题 | **默认 `infixl`，级别 0（最松）**，无需任何注解（R2） |
| 用户想改 | 可选注解 `@infixl(6)` / `@infixr(2)` / `@prefix` |

**默认最松**的理由：`a + b ⊗ c` ⇒ `(a+b) ⊗ c`，用户算符不抢内建算符的结合，行为可预测。

## 7 表达式 vs 命题（R3/R4）

| 写法 | 归属 | 产物 |
|---|---|---|
| `f(a, b)` | 表达式 | `HirCall` |
| `f<a, b>` | 命题 | 命题应用 |
| `a f b` | 中缀糖 | 见下 |

**中缀解析顺序**：① 若 `f` 是值层二元函数 ⇒ `f(a,b)`（**R4 优先**）；② 否则若 `f` 是命题 ⇒ `f<a,b>`；③ 都不是 ⇒ 未定义诊断。

**一致性硬要求**：`a p b` 与 `p<a,b>`（或 `p(a,b)`）必须产生**同一个 HIR 节点**，否则类型线与证明线会分叉。

## 8 实现路线（**不要重写证明器**）

| 层 | 形态 |
|---|---|
| 语法层 | `¬<p>`、`∧<p,q>` 走**通用命题应用**通道，与用户命题同一套解析 |
| 符号表 | 原生命题登记为 **prelude 虚拟声明**（带 `native` 标记） |
| AST/HIR | **归一为原生节点**（`HNot`/`HAnd`…）——证明器一行不改 |
| 对外 | HIR/JSON 记名字，规则仍走原生 |

这与本项目已验证两次的 **t44 虚拟声明套路**一致（prelude 虚拟 struct、虚拟联合别名）。
