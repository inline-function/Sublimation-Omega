# t82 影响面预判：优先级落地会改掉哪些样本的解析树（队长实测）

- 日期：2026-11-09
- 方法：全仓 68 样本扫描「尖括号命题内、**同层**（括号深度 0）同时出现」的算符组合
- 目的：给 t82 一个**可证伪的预期**——改完若 diff 超出预期，说明引入了 bug

## 结论（先说）

**预期变化 = 1 个文件的 2 条定理**；其余 67 个样本的 HIR JSON **逐字不变**。

| 类别 | 行数 | 是否改变解析树 |
|---|---|---|
| 连接词之间同层混用（`∧ ∨ → ↔`，含 ASCII `& \|`） | 4 行（全在 `logic.subl`） | **否** |
| **关系算符与 `→` 同层混用** | 3 行（全在 `logic.subl`） | **1 行不变 / 2 行改变** |

## 明细一：连接词混用（4 行，**解析树不变**）

| 行 | 源 | 今天（全左结合） | ADR-50 后 | 结论 |
|---|---|---|---|---|
| 16 | `(a = b) & (b = c) → (a = c)` | `((a=b)&(b=c)) → (a=c)` | 同（`&` 8 > `→` 6）| ✅ 不变 |
| 113 | `p & q → p` | `(p & q) → p` | 同 | ✅ 不变 |
| 115 | `p & q → q` | `(p & q) → q` | 同 | ✅ 不变 |
| 119 | `p & (p → q) → q` | `(p & (p→q)) → q` | 同 | ✅ 不变 |

> 这 4 行**碰巧**都写成「连接词在前、`→` 在后」，而 `∧`/`&` 的层号 > `→` ⇒ 新旧解析一致。不是运气好，是**中文数学写法本来就把蕴含写在外层**。

## 明细二：关系算符与 `→` 混用（3 行，`logic.subl`）

| 行 | 源 | 今天 | ADR-50 后 | 结论 |
|---|---|---|---|---|
| 85 | `(x ∈ (l..r)) → (x >= l)` | `(∈) → (>=)`（括号已定）| 同 | ✅ 不变 |
| **105** | `x ∈ (l..r) → x >= l` | **`((x ∈ (l..r)) → x) >= l`** ❌ | `(x ∈ (l..r)) → (x >= l)` ✅ | **改变（修正）** |
| **107** | `x ∈ (l..r) → x <= r` | **`((x ∈ (l..r)) → x) <= r`** ❌ | `(x ∈ (l..r)) → (x <= r)` ✅ | **改变（修正）** |

这两条正是 `rangeLowerBound` / `rangeUpperBound`——**定理名字与内容不符**的那两条。优先级落地后它们**第一次表达了自己声称的意思**。

## 给 t82 的验收口径（据此收紧）

1. 68 样本 HIR JSON 比对：
   - **只允许** `core__logic__logic.subl.json` 有 diff；
   - 且 diff 必须**恰好**是这两条定理的树形变化（`HirPAtom(">=")` 外层变 `HirPImp`）；
   - 其余 67 个（含 25 个已污染基线的，做**结构比对**）**零差异**；
2. **t74 的 `n6_termPositionArrowKeepsHirTBin` 测试会被这次改动推翻**：该测试用 `x ∈ (l..r) → x >= l` 断言「项位 `→` 产 `HirTBin`」，而优先级落地后**那里不再是项位**。
   ⇒ 把该测试改成用**真正的项位蕴含**构造（例如把 `→` 写在函数调用的实参位：`f(a → b)` 之类），保留对 `NativeProps`/`PropNormalizer` 项位回落的回归保护——**不要删测试**（那是 t74 抓到的真实缺陷的哨兵）。
3. 若出现预期外的第 4 处 diff ⇒ **停手报队长**，不许改层号迁就。

## 更正（2026-11-09 15:2x）：实际变树 **4 条**，我预判 2 条 —— **我漏了 2 条**

syntax 用 68 样本 emit 实测指出：除 105 `rangeLowerBound`、107 `rangeUpperBound`，**111 `leqTrans`** 与 **121 `rangeSplitRight`** 也变树。

队长独立复核（按 `(kind, pos 起始行)` 序列比对 `base-t74/` 与 t82 产物）：
| 行 | 变化 |
|---|---|
| 105 | `HirPAtom→HirPImp`，`HirTBin→HirPAtom` |
| 107 | 同上 |
| **111** | `HirPAtom→HirPImp`，**`HirTBin→HirPAnd`**，`HirTBin→HirPAtom` |
| **121** | 同上 |

**我为什么漏**：我的扫描把「`&` 与 `→` 同层共现」整类判为"不变"。但实际是否变化取决于**箭头右侧是否还有关系算符**：
- 111 `a <= b & b <= c → a <= c`：旧左折叠 `((a<=b & b<=c) → a) <= c`，新解析 `((a<=b) ∧ (b<=c)) → (a<=c)` ⇒ **变**；
- 16/113/115/119：箭头右侧无关系算符 ⇒ 确实不变。

**教训**：「同层共现 ⇒ 不变」是**错误归纳**。正确判据是"新层级是否改变某个算符的操作数边界"，必须逐算符看，不能按共现对分类。
