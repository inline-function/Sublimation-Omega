## 1 挂载机制（设计范围 1）

### 1.1 .settings 形态

```
# <目录>/.settings —— 目录级挂载文件（非源码语句，不进 Parser/AST）
mount <相对路径 | 绝对路径> [as <别名>]
```

- 一行一挂载；`#` 行注释；空行略。出现非法行 → `E-MOUNT-SYNTAX`（挂在 .settings 文件位，不污染源码诊断面）。
- 路径相对**本 .settings 所在目录**；`..` 允许但**逃逸出编译根**报 `E-MOUNT-OUT-OF-ROOT`（编译根 = CLI 参数目录；可审计拓扑边界）。
- `as <别名>` 给挂载点短名（限定引用前缀用别名）；默认别名 = 被挂目录名。
- **解析器**：不复用 Parser（硬约束）；建议独立行扫描（trim/`#`/空格切分 + 路径校验），文件级错误用 DiagBag（复用 Severity/SourceRange，行位精度）。

### 1.2 目录树 ↔ 模块树扫描规则（目录即模块）

- **目录 = 模块**；目录名 = 模块名（`tool`、`数学` 皆可，与 S-4 名字集相交时以模块表先查为准——§2.3）。
- 模块体 = 目录内**全部 `.subl` 文件**（同目录文件按名字序串行入域；多文件 V1 口径：同年同模块平铺符号域，跨文件前向引用合法——对齐单文件既有语义）。
- 子目录**默认不自动挂载**（挂载是 .settings 的显式动作——与「无 import」的对称审计哲学一致）；隐式挂载备选见 OQ-2。
- 挂载图必须 **DAG**：环 → `E-MOUNT-CYCLE`（报环路径链）；重复挂载同模块不同别名允许（别名空间冲突 → `E-MOUNT-DUP-ALIAS`）。
- 扫描产 `ModuleTree`（模块节点：名/别名/路径/父链/挂载子集/源文件清单）——**解析前**一次性建成，后续全管线共享只读。

### 1.3 CLI 接线

- 新形态：`compile <目录> [-o <产物前缀>]`（check 同理）。目录缺 .settings → 兜底为**目录体模块**（零挂载，子目录不扫——兼容纯目录组织）；目录无 .subl → `E-MODULE-EMPTY`。
- 既有**单文件形态逐字不变**（`compile <file>`——单文件 = 自身模块零挂载，等价叶子；P-7/SAME 面零动是本设计的可证伪承诺）。
- 产物：每模块一个 envelope（unit.path = 模块相对路径），主模块产物落 `-o` 位，挂载子模块落 `<o 前缀>__<模块路径>.json`（对齐 e2e manifest 双下划线命名 `examples__模块系统__主.subl`）。

### 1.4 mount 解析时机：解析前（本文主张）

- ModuleTree 位于**编译入口与 parser 之间**——先扫目录 + 解析 .settings，再对模块体内每文件跑 lexer/parser。理由：限定引用的消歧需要模块表（§2.2），而 AST 零语义（S-1 §2）⇒ 消歧必在语义层；但**模块拓扑**无源码依赖，前置建成零循环依赖。
- 层位代价：S-2 §4 包结构需增 `sublimation.frontend.module`（ModuleTree / MountSettings / ModuleScanner），依赖方向 `module → diag`（横切），被编译入口依赖——**S-2 修订件（OQ-1，队长裁）**。

## 2 限定引用 `a.b.c`（设计范围 2）

### 2.1 实测报告（队长点名项）

`tool.triple(4)` 今日解析链（F5/F6）：

1. 解析层：`NameRef(tool)` 收于 FieldExpr.target → `CallExpr(FieldExpr(triple, NameRef(tool)), [4])`——**与 `p.x`（字段）、`o.show()`（方法糖）完全同产生式**，解析层无任何区分；
2. 语义层：`tool` 走 expr(NameRef) → resolver E-UNBOUND-NAME「未定义的名称 tool」；`.triple` 走 FieldExpr-callee 分派 → 四通道（struct 字段表 / 扩展函数桶 / builtinSig / 自由函数）皆空 → E-UNBOUND-NAME「方法不可解析」。

即：**限定引用从未有过通道——名字先在名称通道死，方法后死在扩展桶通道，双错同源**。

### 2.2 语法位的两个方案

| 方案 | 形态 | 风险 | 本提案倾向 |
|---|---|---|---|
| A · NameRef 扩展 | 名字位允许 `a.b.c` 点链（lexer 或 parser 位消歧，产 DottedNameRef） | 改 S-4 名字产生式（文法层修订）；解析层须判「点后标识符是字段还是模块段」——字段访问 `p.x` 与模块限定 `tool.triple` 同形，parser 零语义**无判据**（p 是变量还是模块名要符号表），强行拆即把语义漏进 AST（违 S-1 §2） | **否** |
| B · 语义层消歧（保留 FieldExpr） | 解析层逐字不变；语义层 FieldExpr 入口先查模块表：NameRef 段链命中模块 → 限定引用通道 | 消歧逻辑集中在语义层一处；AST/HIR 既有节点复用（SAME 面零动） | **采纳** |

### 2.3 歧义消解判据（方案 B 的消歧序）

FieldExpr(target=NameRef(s), name) 入口按序判：

1. **模块段链**：s（或逐段前缀链 `a.b`）命中模块表 → 目标按模块符号查询：下游段命中函数/ctor/类型 → 限定调用通道（HIR 载体见 §2.4）；
2. **字段/方法糖**：s 命中值符号 → 既有字段（:1998）/ 方法糖（:2601）通道逐字不变；
3. 双通道皆空 → 既有 E-UNBOUND-NAME 双错口径（诊断保形）。

- **碰撞规则**：局部/本模块符号名与模块名同名 → **本模块优先**（P-7 延伸：用户表在前，模块表兜底——与 prelude 虚拟声明同序位）；模块名间的同名（两个挂载别名撞）→ `E-MOUNT-DUP-ALIAS` 在挂载期先死，限定位不背锅。
- `a.b.c`（三段+）：前段先模块后段符号（`tool.math.pi`：tool 模块内 math 子挂载的 pi）；若中段是**变量**（`p.a.b`）走字段链兜底——字段通道既有递归解即收。

### 2.4 HIR 载体形态

| 方案 | 形态 | 取舍 |
|---|---|---|
| B-i 复用 HirField + symbol 挂模块源 + D-MODULE-REF 旁注 | 零 schema 变动（v3 不动）；限定调用 = HirCall(callee: HirField(qual, name, symbol=模块源符号)) | **倾向（最保守）**——SAME 门零面；模块源信息经 symbol 可追 |
| B-ii 新 HirModuleRef 节点 | 语义显式（产物可读性好） | v3 schema 变动 + json/hjr 两侧发射器改 + SAME 面翻新——OQ-3 队长裁 |

## 3 可见性（设计范围 3）

### 3.1 父→子可见口径

- **父模块见所有经 .settings 挂载的子孙模块符号**（沿挂载树向下传递闭包）；子模块不见父、不见兄弟（无回指）——冻红样本头注「父→子可见」的机械对应。
- 查询链（本提案主张）：`当前模块用户表 > 挂载子模块表（挂载序，别名区分） > prelude 虚拟声明`——P-7 口径逐字延伸（用户同名优先；模块符号是兜底层）。
- 样本头注「目录即模块/父→子可见/跨模块限定调用」落点 = **文件注释**（F12，无需机制消费；机制侧由 ModuleTree + D-MODULE-REF 旁注承载可审计性）。

### 3.2 跨模块全见 vs 限见

- V1 主张**限见 + 限定引用是唯一跨模块通道**：跨模块符号必须写全限定（`tool.triple`）——文本即审计面（与「无 import」约束同根：模块关系全在 .settings + 目录拓扑，源码内零隐式依赖）。
- 隐式见（不限定直接 `triple(4)`）否决：污染本模块名域 + 跨模块静默依赖不可审计；但保留**诊断友好**：本模块未定义而挂载模块有同名时，E-UNBOUND-NAME 文案附提示「挂载模块 tool 有 triple，请写 tool.triple」。

### 3.3 export 必要性评估

- **评估结论：不引入 export**（V1）。理由：可见性已由拓扑（父→子）+ 限定通道完整定义；export 会引入声明级修饰 → 与无 import 的对称性破缺 + 符号表入域规则复杂化（每声明按 export 位过滤）。
- 未满足的需求登记：模块内部实现细节的**隐藏**（V1 无此需求——限定引用即显式出镜；隐身需求低）→ 留 OQ-4。

## 4 符号表交互（设计范围 4）

### 4.1 挂载模块符号入域规则

- 编译单元从「单文件」扩为**模块单元集**：compile 改为对模块集逐单元构造（每模块独立 Elaborator 实例或共享符号表的分域——见 OQ-5），挂载侧的合并视图仅用于**父模块查询链**。
- 结构体/联合别名/扩展函数/自由函数/ctor 五张表全模块内既有口径（declareGlobal 等）；模块间共享只读快照（挂载拓扑 DAG ⇒ 父合子闭包无环）。
- 扩展函数桶跨模块：父模块可见挂载模块扩展函数（限定 + 非**限定**两通道——非限定的扩展桶按「同接收者头+名」查全局时并挂载集——OQ-6 是否并入）。

### 4.2 与 P-7（用户同名优先）

- 单文件口径零动（F8：BUILTIN_TYPES 已清容器裸名、虚拟声明被用户覆盖）。
- 跨模块延伸：本模块声明 vs 挂载模块同名声明 → **本模块优先**（同 P-7 精神）；**挂载模块之间**同名 → 不入隐式查询（限定位必须写别名消解），冲突在 `E-MOUNT-AMBIG`（挂载期预判）与限定位 E-AMBIG-NAME 之间分工——OQ-7。

### 4.3 prelude 虚拟声明（与 §5 联动）

- stdlib 根默认挂载后：PreludeDecls 的 11 虚拟 struct + 5 虚拟联合别名逐步由 **std 源码模块**替换（虚拟声明不落 HIR/JSON 的口径不变 → std 模块落 HIR 后产物**新增** std 条目——SAME 面差异必须由队长裁基线口径，OQ-8）。

### 4.4 联合别名表的碰撞与遮蔽

- aliasDecls 当前口径：prelude 预注入 + 用户 file 条目覆盖（t47）；跨模块别名 = **模块内别名优先**（查询链同 §3.1）；跨模块同名别名并挂载集时，限定位以别名前缀消解（`tool.List` vs 本模块 `List`）。
- 跨模块 E-DUP-DECL 判据：同模块内必须有全局唯一（既有）；跨模块同名合法（不同模块域）——E-DUP-DECL 判据的模块作用域化是落地产物，登记 OQ-9。

## 5 迁源形态 C 兼容：stdlib 根默认挂载

- 机制：编译根隐式预置一条「mount <stdlib 根>`（零 .settings 书写）——CLI 侧默认开，`--no-stdlib` 关（对齐既有 `--no-degrade/--no-lift` 开关族）。
- 替换路线（渐进）：stdlib 源码模块先以**零冲突命名**落（如 `core.List` 限定形态可用但裸 `List` 仍走 prelude 虚拟声明）；逐批把虚拟声明迁成 std 源文件并测套验证后，PreludeDecls 条目退役（每批一次 SAME 基线翻新，队长裁）。
- 公理库（标准库规划 §2 第三层）以 **axiom 语句**入 std 模块（命题位语句——解析层既有通道零改）。

## 6 冻红样本解法（设计范围 6）

### 6.1 需补的样本文件

```

├─ 主.subl               （既有冻红；fun main 调 tool.triple(4)/tool.square(3)）
```

- 工程模式（无 --script）下 `fun triple(n : Nat) : Nat = n * 3`（形参/返回标注齐——工程模式声明完备口径）。

### 6.2 e2e 导纳入评估

- manifest 加一行目录形态（`src=examples/模块系统`、dst 按模块单元展开：主 + tool 两 envelope；导出脚本扩目录分支——compile <目录> + rc 捕获照旧）。

  - 口径乙：新基线侧目录（jsoncmp/out/t130n 之类），68 计数口径 = 目录算 1 样本（产物按模块数计）。
- 68 → 69（或按单元计 70）前由队长裁；脚本门 14 与测套不受影响（单文件形态零动）。

## 9 风险与诚实边界

- **零码改承诺的可证伪面**：单文件 CLI 形态 + FieldExpr/方法糖/字段三通道 + SAME 68 面在本提案下**不预见变动**；落地任务第一步即复验上述门，任何破坏 = 本提案修订。
- **未决的最大件是编译单元集化**（§4.1/OQ-5）：compileFrontend 单源签名是多处的入口（CLI/测套 harness）；多单元化的重构面 + Elaborator 实例化语义是落地的主要工程风险。
- **限定引用消歧的诚实边界**：方案 B 的模块段链判据依赖**模块表先查**——若同名变量/字段在先（局部作用域），跨模块访问被遮蔽（P-7 延伸的代价）；遮蔽时**不给诊断**（用户写全限定即绕，但静默遮蔽是暗病面）（OQ-13 遮蔽提示口径）。
- 冻红样本的 12/9 输出是**后端验证**（F12）——前端件收口判据 = 零 E- 诊断 + 产物含跨模块限定调用载体，不冒充运行期验证。
- 本提案的实测基线为 2026-11-12 树态（t129 收口，commit 347e71f 附近）；行号锚点随树漂移，落地件复核。
