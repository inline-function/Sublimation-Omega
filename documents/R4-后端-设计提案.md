## 1 模块边界与工程接法

### 1.1 三个候选接法（评估，不代裁）

| | A：`:backend-js`（S-2 §1 既有名） | B：`:backend` | C：独立 TS 包（Node 侧） |
| --- | --- | --- | --- |
| 语言/产物 | Kotlin，产 JS（codegen 导向） | Kotlin，解释器 + 未来 codegen 二合一 | TypeScript，解释器（run-script） |
| 与 S-2 关系 | 既有登记名（表 1「JS 后端（消费 HIR）」🔴 待建）;启用须按规则 5 修订 S-2 留痕 | 同（新名，须修 S-2） | 非 Gradle 模块≈jsoncmp 同级工具件（S-2 规则 5 不适用）;契约面=schema 文档 |
| 与 D-6 关系 | D-6「解释器暂缓」不挡 codegen 路 | 需明示「解释器» 暂缓项解冻 | 同 B（解释器先行=暂缓项解冻的一面） |
| JSON 输入成本 | 需 JSON reader：手写最小 reader（与手写发射器对称，P-6 精神）或引第三方（破 S-2 规则 3 零依赖纪律） | 同 A | `JSON.parse` 免费（jsoncmp 已验证路径） |
| 守门器 | HirSchema.check 口径需重实现（最小扫描器 ~60 行，Kotlin 可移植） | 同 A | 同口径 TS 版（双向对拍可验证同义） |
| 复用既有工具链 | 弱（新建模块） | 弱 | 强（jsoncmp/out-subs、run-gate、parity 五段机制现成） |
| 后续 codegen 连续性 | 强（Kotlin 产 JS 是登记形态） | 强 | 中（codegen 须另起 A/B 路径） |
| 验收/对拍机制 | 需新建 | 需新建 | 沿用 jsoncmp 框架（差分台账同纪律） |

**提案倾向（供裁，非裁决）**：**C 先行 + A 收口**——V1 解释器走 C（消费面窄、工具链现成、零 JSON 成本、
对拍机制即刻复用）;V4 codegen 期启用 A（`:backend-js` 按 S-2 规则 5 include + 修订留痕）。
若队长/用户更倾向单语言面（Kotlin 一条龙），B 亦成立——代价是 JSON reader 手写与工具链重建（两路线的
语义模型完全相同，仅工程载体不同;本提案其余章节与该选择无关）。

### 1.2 消费方式：读 HIR JSON 文件 = 唯一输入（D-6/D-8）

- 输入单位 = envelope 文件（每文件一份 `{schema, compiler, unit, ok, diagnostics, hir}`）。
  编译侧三路径（单文件/脚本/模块目录）产物形态一致（单一发射源）⇒ 消费方一条入口。
- **模块态**：模块编译产多枚 envelope（主件 + 全部挂载子件），以 `unit.path` 区分;
  消费方按路径拼装模块图（挂载关系不在 envelope 内——由编译命令行/目录结构侧面给定，
  消费方按「主件 + 子件目录约定」重建;或改由 CLI 产 manifest 侧文件（OQ-6，不代裁）。
- **ok=false 的 envelope 不消费**（契约 §8:ok=false ⇒ 诊断袋含 error，后端不得继续——运行时零义务
  处理错误恢复树（Hir*Error* 节点是「诊断不丢、结构不断」的保留通道，非可执行语义）。
- uid/nid 不参与运行时调度（诊断反引用面）;拓扑执行只按结构序（条目保序映射源码顺序，S-1 §3）。

### 1.3 依赖方向

- 消费方**零源码依赖** `:frontend`（不引 hir/json 包）——契约面唯一耦合 = schema 文档 + 守门口径。
  理由：D-8「HIR 为后端唯一输入」的严格形态是**文本契约**而非 Kotlin API（跨语言面 A/C 皆成立，
  也杜绝后端回望前端内部的诱因——S-2 依赖规则 1「禁止回望」的延续）。
- 若采 A/B（Kotlin 模块）：Gradle settings include + JVM17 toolchain + 零第三方运行时依赖（S-2 规则 3/4 同纪律）。

## 2 深拷引擎

### 2.1 与 schema 的接点：哪些节点/note 携带拷贝指令（实测冻结态）

| 通道 | 形态 | 覆盖站点 | 结构化程度 |
| --- | --- | --- | --- |
| `HirVarStmt.deepCopy` | 布尔字段（固定字段集） | var 初始化位 | **结构化**（唯一一处） |
| D-REF-DISPATCH note | node `notes[]`（kind=supplement, code/message/pos/**from/to**） | @ref 涉及的赋值/借用位（共享/深拷判定） | 半结构化（from/to 槽是结构化的，判定结论在 message） |
| D-DEEP-COPY 补注 | 顶层 `diagnostics[]`（severity=supplement）+ message 含 got → want +「元素层：N 位深拷」 | 8 站点：var 初始化 / 赋值 / 默认值 / call 实参 / 构造子字段 / struct 构造字段 / return 值 / 函数表达式体 | **非结构化**（文案型 message） |
| `W-DEEP-COPY-LOOP` | warn 诊断 | 递归帧内的深拷成本告知 | 告示面（不参与调度） |

矩阵两复制格（R-28 后仅存）：**MUT→PLAIN** 与 **MUT→MUT**（目标无引用视图 ⇒ 深拷隔离）;共享格 = 目标持
引用视图（`@ref T` / `@ref @mut T` 源可写）⇒ 零操作同指;七格拒绝落 E-TYPE-MISMATCH（编译期拦死，运行时不会遇到）。

> **真契约缺口（诚实登记）**：8 站点中 var 初始化位虽有结构化布尔（`deepCopy`），实测**既往从未真化
> （恒 false——字段语义悬空）**;其余 7 站点的深拷指令只存在于 D-DEEP-COPY 的**诊断 message 文本**。消费方若 parse message 取判定 ⇒ 与未冻结的文案
> 耦合（message 属文档性字段，改文案不断契约、但断消费方）。**这是 R4 前必须补的缺口**——见前置件 R4-A0。

### 2.3 引擎设计

**值模型**（tagged values，uniform 表示——与 §5 单态化裁决无关）：

| 值族 | 表示 | 深拷行为 |
| --- | --- | --- |
| 标量 Nat/Int/Rat/Real/Str/Bool/Null/Nothing | 原值 | 拷语义=原值（不可变，零成本） |
| struct 值 | ctor 名 + 有序字段映射（保字段声明序，schema HirStructCtor.assigns 同构） | 递归拷字段 |
| List/容器 | 数组 + 长度（Nil/Cons 联合 = 俩 ctor 形态，List 走 ctor 同路） | 递归拷元素 |
| Optional/Result | ctor 形态（Some/None、Ok/Err） | 递归拷载荷 |
| Fn | closure：形参 + 体 + **env 快照** | 拷 env 中可变槽（捕获快照，§2.4） |
| @ref 视图 | **透传同一对象**（HirRefType 不产运行时包装——视图=类型层事实） | 零操作 |

**深拷算法**：对象图 DFS + visited 表——同一次拷贝内已访问节点**复用同一副本**（保共享、保环;
「深拷 = 整图复制」与「ID 同构」的差别即在此：共享子图只拷一份，环不无限递归）。栈深风险与语言
递归帧同源（W-DEEP-COPY-LOOP 告知的成本面在运行时同样存在 ⇒ V1 文档化递归深上限策略，栈深策略后版（与 W-DEEP-COPY-LOOP 同源的成本面））。

**R-14 元素层**：编译期 `deepElements` 是「容器实参位 N 位下钻」的**计数提示**（成本审计 + CoW 预算），
运行时实现 = 全图递归——**不做「只拷 N 层」的部分拷**（部分拷与「目标端拿不到原对象写口」的隔离语义不等价;
元素层计数只服务于优化决策，不进入正确性路径）。

**站点 → 运行时动作映射**（R4-A0 后的最终形态）：

| 站点 | HIR 位 | 运行时动作 |
| --- | --- | --- |
| var 初始化 | `HirVarStmt` + `deepCopy` / note | 声明绑定前拷值 |
| 赋值 | `HirAssign` + note | 右值拷后再写槽 |
| 默认值 | `HirParam` 默认值位 + note | 默认表达式求值后拷 |
| call 实参 | `HirCall.args[i]` + note | **caller 侧**拷后入帧（callee 无感） |
| 构造子/struct 字段 | `HirStructCtor.assigns` + note | 求值后拷再装字段 |
| return 值 / 函数表达式体 | `HirReturn` / 体 + note | 返回前拷 |

### 2.4 闭包捕获快照（创建时深拷）

- 语义：closure 创建时对捕获的**可变**值深拷快照（e2e 特性巡礼注释预期：`snapshot()` 返回 7
  （闭包持有创建时快照）——外层 ctr 后续写不映进快照）;@ref 捕获=共享（零拷，视图透传口径同族）。
- 依据：根文档旧实现同语义（旧 Evaluator `copyCapture`——深拷捕获变量）;效应分析 §4 登记为
  R4 需求（「闭包创建时对捕获可变值深拷快照（特性巡礼样本实证语义）」）。
- 落位：HirLambda/HirAnonFun 求值点（closure 构造时）扫 env 槽位、按捕获源的可变性拷;
  纯度/可变性事实编译期已闭（前端产物不重判）⇒ 捕获可变位的标记由 R4-A0 同路 notes 携带或按声明的 @mut 衣（§7 形态依赖）。

### 2.5 异步面（HirTask/HirFlow/awaitPoint/Channel）

V1 暂缓 = 桩语义（遇到 Task/Flow 值报运行时「异步面未实现」错误，不静默放行）。Chan/Task 的 @mut 共享

## 3 CoW 登记面与深拷切换判据

### 3.1 同构条件（CoW ⇔ 哪些复制格）

| 复制格 | 目标端写口 | CoW 等价性 |
| --- | --- | --- |
| MUT→PLAIN | 无（目标 plain，类型层保证零写口——R-28 拒了 PLAIN→MUT，反向亦封闭） | **CoW 候选**：目标不写 ⇒ 共享只读视图;源端写时才真拷 |
| MUT→MUT | 两端皆可写 | CoW **不成立**：必须 eager 真拷（隔离是语义本身） |
| 元素层（List[@mut T]→List[T] 等） | 元素位 plain | CoW 候选（同构，逐元素写屏障） |

### 3.2 R-21/别名不可知下的 CoW 形态（保守地板兑现）

借用「让它逃」（R-21）+ 零生命周期系统 ⇒ 运行时**不知别名集**。故 CoW 必须 pessimistic：
- 源端任何写 ⇒ **先拷后写**（写屏障/lazy copy：共享标记位 + 首写复制）;
- 目标端任何路径都不写（类型层已证 ⇒ 运行时信任该判定，不做防御性拷——类型层结论就是契约，S6 同源口径）。

### 3.3 切换判据与登记表

| 项 | 判据源 | 兑现期 | 备注 |
| --- | --- | --- | --- |
| eager 深拷（V1） | deep=true（8 站点 notes/R4-A0） | **V2 落** | 正确优先，零优化 |
| CoW（MUT→PLAIN 目标端） | deep=true + 目标类型 plain（from/to 串可判;或 R4-A0 携结构位） | **V3 候选** | 写屏障 + 首写拷 |
| CoW 预算提示 | 元素层计数（deepElements） | V3 | 审计/成本模型 |
| @ref 路径 | deep=false（共享格） | 常态 | 零操作 |

效应分析 §4 登记的「CoW 候选（复制格语义可优化为写时复制）」本提案逐条承接为上表;**前端类型层结论不变**
（该登记原文条款逐字成立——CoW 是后端策略层事实）。

## 4 借用运行时（S6 §4.2 五项逐项判定 + R-21 兑现）

| S6 §4.2 项 | 本提案判定 | 理由与兑现形态 |
| --- | --- | --- |
| ① 实际对象图深拷 | **落**（V2 eager / V3 CoW 策略层） | 静态 deep=true 只给判定;拷的执行=对象图 DFS（§2.3） |
| ② 别名/生命周期行为 | **不落**（顺序语义） | 零生命周期系统（ADR-53）⇒ 运行时按单线程顺序语义实现：`f(&x, &x)` = 同对象两读;并发可见性留 V3+ 异步面 |
| ③ 写穿透的物理事实 | **落**（共享格=同对象） | 共享格零操作 ⇒ `b.n = 1` 真改 a（特性巡礼注释预期「1（别名：c.n 改了 d.n 跟着变）」=验收样本）;深拷格=隔离（同文件「0（深拷后 a 不受 b 影响）」） |
| ④ 逃逸分析 | **不落**（R-21 兑现） | 「让它逃」的运行时义务 = 不假设实参独占：CoW/任何优化不得依赖逃逸信息（§3.2 pessimistic 的根据） |
| ⑤ 深拷成本/策略 | **落策略层** | V1 朴素 DFS → V3 CoW/惰性（元素层计数作预算）;前端产物只给判定（S6 原文兑现） |

**R-21 保守地板的运行时三义务**（「放行不封」的运行时含义，逐条兑现）：
1. 调用边界不假设实参独占（借入值可能被 callee 长期持有）;
2. @ref 借出后源端写的可见性 = **即时对所有视图可见**（顺序语义，无快照窗）——与闭包捕获快照（创建点）分家;
3. 快照义务只在闭包创建点（不全程跟踪别名 —— 别名无分析是前端裁定，运行时同向）。

**借用表示**：`&x`（HirBorrow）运行时 = 透传 x（零包装）;`recordCallArgs` 借用证据=编译期
通道（运行时忽略）;纯度闸（E-IMPURE-REQUIRED/E-IMPURE-CALL）编译期已闭 ⇒ **运行时不重判纯度**（契约 §8.2 同源）。

## 5 R-20 零参 per-call meta + OQ-1 单态化

### 5.1 R-20（零参 per-call `?T`）

- 现状：后版登记（stdlib 批史 §20 行「零参 per-call `?T` 形态仍登记后版（P-11 §5.1，R-20——本批不落）」）;
  零参构造（`MutableListOf()` 等）当前=固定 `Nothing` 合成（单态）。
- **运行时影响 = 零**：per-call meta 是类型推导面事实（形参返回类型的 call-site 合成）——值表示 uniform
  （ctor 名 + 字段），不依类型实参;若落 per-call meta，同一构造点可合不同元素类型 ⇒ 表示层不变。
- `inferred/evidence`（t108 推导元信息）= audit 通道，运行时忽略（schema 契约 §0 加性纪律同源）。
- 唯一影响面=V4 codegen 的特化提示（可选读 inferred/evidence 做静态特化——选读非必读）。

### 5.2 OQ-1（P-11 §3.7 单态化）

| 裁决态 | 解释器路径 | codegen（V4）路径 |
| --- | --- | --- |
| 单态（P-11 §3.7 现行：多态丢失即拒绝） | 零影响（uniform tagged values 天然兼容） | 静态特化（每函数一组具体形参类型 ⇒ 直传/内联候选） |
| C-2 推翻单态（R3-V1 OQ-1:P-12 证明救援多态） | 零影响 | 值标签分派 / per-call-site 特化（动态开销或代码膨胀权衡） |

**结论（分期理由 +1）**：单态化未决对**解释器路径零影响**（表示与分派皆 uniform），对 codegen 路径显著。
⇒ 先跑解释器，把 OQ-1 裁决点放在 V4 之前（路线图 §6 标门）。
