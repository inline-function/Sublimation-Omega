# 工具与管道缺陷台账

> 记录**会让"结论"变假**的工具缺陷。每条必须写：现象 / 影响 / 检出方式 / 处置。
> 立此文档的理由：2026-11-09 一天内出现 3 起"静默失效"，每一次都可能让一份比对结论失效而不报错。

## D-1 批量导出静默截断（emit-all）

| 项 | 内容 |
|---|---|
| 现象 | 一次性导出 68 个样本时，在 `peano → series` 之间**静默截断**，无报错、无提示 |
| 首次报告 | `syntax`（t82 期间），它逐个补齐 |
| 影响 | 任何基于"全量导出"的比对结论都会**少算文件**，且看起来"全绿" |
| 检出方式 | 核对**导出数量**（必须 = 68）与**文件名集合**（与基线差集为空） |
| 处置 | 导出后**立即**打印 `COUNT=68`；不足 68 拒绝出结论 |

## D-2 单次工具调用内连续 spawn 丢失进程输出（qa88）

| 项 | 内容 |
|---|---|
| 现象 | 在一次工具调用内连续 spawn **68** 个 `java` 进程，其中一个进程**无 stdout、无产物**（log 零行），单独复跑则正常 |
| 首次报告 | `qa`（t88），导出实得 **67/68**，缺 `examples/lambda与闭包.subl` |
| 连锁 | 队长据此被误报"基线缺文件"；实际是**导出缺口冒充基线缺口** |
| 检出方式 | 同上：数量 + 集合核对 |
| 处置 | 批量 spawn 控制在**≤ 20 个/次**，或每个 spawn 后立即校验产物存在；缺任何一个**整批作废重跑** |

## D-3 "测试存在" ≠ "测试被执行"

| 项 | 内容 |
|---|---|
| 现象 | 新写的测试类在 XML 里**没有执行记录**（当时判断为"刚写、还没跑"） |
| 影响 | 报告"某测试 6 例全绿"，实际可能根本没跑 |
| 检出方式 | 从 `build/test-results/test/*.xml` **读例数**，与源码里的 `@Test` 数对账 |
| 处置 | 任何"测试通过"的声明必须附 **XML 里的例数** |

## D-4 基线被"重导"覆盖

| 项 | 内容 |
|---|---|
| 现象 | 队长的一次任务书没指定输出目录，`qa` 按字面"重导基线"写进了 `jsoncmp/old/`，**覆盖 12 个基线文件** |
| 影响 | 失去 t74 前的对照物（后由 `base-t74/` 重建补回，56/56 逐字一致） |
| 检出方式 | 比对**基线文件 mtime**；基线目录必须只读 |
| 处置 | `jsoncmp/README.md` 铁律：基线只读；导出只写 `out/<tag>/`；**任务书必须写明输出目录** |

## D-5 构建槽只保护"同时一个构建"，不保护"树正在被改"

| 项 | 内容 |
|---|---|
| 现象 | 两成员文件不重叠，但共享一次编译 ⇒ 一方的中间态被编进另一方的验证结果 |
| 首次报告 | `infra`（t85），主动报告"无法归因"并拒绝跑 |
| 影响 | 验证结果**不可归因**，可能把别人的红记在自己账上 |
| 检出方式 | 构建前看目标文件 **mtime**；`< 10 分钟` 且非自己的改动 ⇒ 先问或等 |
| 处置 | 验证窗口协议：需要干净树的一方**申请窗口**，其余成员暂停落盘共享文件 |

## D-6 关键词命中 ≠ 残留（队长 t90 验收自查误报，2026-11-09）

| 项 | 内容 |
|---|---|
| 现象 | 用「旧表述关键词是否消失」验收文档修改，**3 条命中全是废止注**（「判定顺序不再是…（旧文已废止）」「旧写 HTrue 已废」「右操作数只取一元是 t74 前行为」），不是残留 |
| 影响 | 若只信正则不看上下文，会下「清理不彻底」的错误结论，并**诱导成员删掉本该保留的历史留痕** |
| 检出方式 | 命中后**必读上下文**，区分「仍在主张」与「声明已废止」 |
| 处置 | 验收规则改为：关键词命中 → 读上下文 → 废止注判「保留」、仍在主张判「残留」；**禁止以命中数下结论** |

## D-7 杀任务不杀 Gradle 守护进程 ⇒ 孤儿锁 ⇒ 后续构建静默挂死（2026-11-09 t92 验收）

| 项 | 内容 |
|---|---|
| 现象 | 用 `job_kill` 杀掉构建任务后，**Gradle 守护进程存活**并持锁；下一次 `build-slot run` 连上同一守护进程，**静默挂死**（CPU 停在同一数值，无任何输出）|
| 本次耗时 | 两次假运行共耗 **~50 分钟**（第一次 29 分、第二次 22 分）才靠「CPU 平台 + XML 不刷新」定位 |
| 检出方式 | 不看任务状态（`running` 是假的），看 **`java` 进程 CPU 增量**：10 分钟 <1 CPU 秒 ⇒ 僵死 |
| 处置 | 杀任务后**必须** `Stop-Process -Name java -Force` 清孤儿，再重跑；已发现 3 次长命令会被**转后台**（前台返回空壳），此时去 `job_output` 取，别在前台空等 |

## D-7b 长命令被转后台、前台返回空壳（同晚连遇 3 次）

| 项 | 内容 |
|---|---|
| 现象 | 超过某阈值的 `pwsh` 调用被自动转后台，前台返回 `kind: promoted / exit: undefined` 且**无输出** |
| 陷阱 | 若在前台等结果或按 exitCode 判断成败，会得到「失败」的错觉；真结果在 `job_list` 里的新 job |
| 处置 | 见到 `promoted`/空壳就去 `job_list` 找新任务，用 `job_output` 取；`Select-Object -Last N` 会缓冲到管道结束，中途无输出是正常的 |

## 通用纪律（由以上八条归纳）

1. **数量 + 集合**：任何"全量"结论必须同时报**数量**和**文件名集合**；
2. **产物存在性**：脚本"跑完不报错"不构成成功，必须**逐个校验产物**；
3. **执行记录**：测试"写了"不构成"跑了"，必须读 XML 例数；
4. **基线只读**：基线目录任何写入都是事故；
5. **报"对方缺东西"之前，先验证自己**；
6. **命中 ≠ 结论**：grep/正则只提供候选，**语义判断必须读上下文**——尤其区分「废止注」与「残留」；
7. **杀构建必清孤儿**：`job_kill` 不杀 Gradle 守护进程，**杀后立刻 `Stop-Process -Name java -Force`**，否则下一次构建静默挂死；
8. **构建在跑与否看 CPU 增量**，不看任务状态——`running` 可能是假的。
- **D-8 闸影响度量面**：闸类任务的阶段 A 冲击度量必须覆盖测试夹具源（SubtypeOrderTest 等），不能只数 e2e 样本——t97 阶段 B 爆出的 boom() 夹具在 warn 态被无诊断断言容忍，error 态才暴露。两阶段闸值差正是为此设计。
- **D-9 树改禁重复调用非幂等函数**：任何在 HIR 树上构造/标注的函数不得在同一处理路径重复调用（etyped 类函数每次落新类型节点吃 nid）——t98 assign 分支多调一次 etype 导致 3 份 @mut 样本 JSON 出现未归因nid 序列漂移。规则：一次遍历内取过的类型结论存局部量复用，不二次求值。
- **D-10 bisect 残留与审查覆盖调用点**：t98 二分调试留下的**重复 `is HirAssign` 分支**（Elaborator.kt 旧 :879）静默遮蔽了正确分支，使赋值位 D-REF-DISPATCH 留痕**全程不产出**——全量测试绿、t99 矩阵 16/16 绿都没暴露，因为测试程序**没有赋值语句**（走不到该分支）。两条连带教训：① 二分/调试留下的重复分支/死行必须即清（同 D-9 家族，bisect 残留是静默失效源）;②**结构审查必须覆盖新函数的调用点，不只审函数本身**——t99 审查只看了 copyDispatch/viewKindOf，漏了赋值分支的遮蔽。发现方：semantics t102 读码任务（被我批准的一行修复并行为级复验：探针恢复留痕产出）。
- **D-11 零参期望位对隐式单参 lambda 放行，无调用元数校验**：`applyZero({ _ + 1 })`（`f: () => Nat`）编译通过；HIR 里 `f()` 的 `args: []` 打在 `params: [_: Nat]` 的 lambda 上，无任何元数核对。机制来源：文法 S-36 无箭头=隐式单参、期望零参位放行 + 调用侧 args 与 callee 形参数无 consistency check。弹性无人消费故未爆，属 soundness 口子。发现：队长 R3 讨论 adj-hoc 探针（frontend/probe-lambda/{zero,noarrow,used}.subl 三组对照，产物在盘）。处置：R3 S2/S3 落地推导时一并处理（形参数 vs 调用元数 consistency check 是推导健全性的前置）；非阻塞。
- **D-12 工程模式顶层 axiom 被误判为脚本模式（模式真值无单源）**：链  Parser:204（工程顶层 axiom→StmtEntry）→ Elaborator:593（→HirStmtEntry）→ HirJson:187  （any HirStmtEntry ⇒ script）。样本实例：`公理化.subl:7` 顶层 `axiom moduleReady`，CLI 工程模式  编译，但 out/t99 envelope `mode="script"`——**基线冻着该误标**。  根因：Frontend.kt:41 `compile(pr.file, pr.notes)` **丢弃 CLI 真值 scriptMode**，下游只能自算。  连带：t106 的 Elaborator:578 自算判据继承同一错（含 axiom 的 .subl 会被 R-08 当脚本放宽）。  发现：队长 t106 飞行中代码审查（规程 §7.5，3c/3h 哨点）。  处置：**模式真值单源化**——CLI 标志经 compileFrontend 透传至 compile/emit，elaboration 与 envelope  均读真值，取消两处自算。验收口径重定：68 样本中 67 SAME，`公理化` 的 mode 翻转 script→project  为缺陷修复预期差（文档化，不得回退以求 SAME）。
- **D-13 连杀 java 可致 gradle daemon 注册表损坏**：槽位清理（Stop-Process -Name java）若在 gradle 仍在执行时做，  打坏 daemon registry，gradlew 客户端空等永不来的 daemon（无新 daemon 日志佐证）；恢复须清 registry 并全程 --no-daemon。  另注：槽位包装层在 gradle 完成后仍挂住（XML 已落盘），验收应直读 XML 勿空等 wrapper 退出（D-7 族新形态）。  纪律补：**Stop-Process java 清理须在确认无在执行 gradle 后再做**。
- **D-14 树改写/归一副本不可消费全局 nid 计数器**：t109 首轮 propNorm.termQuiet 注册归约规则体时调用全局  nid 分配 → JSON 逐字漂移（21 样本 DIFF，被 SAME 门当场兜住）。修法：零分配归一副本（propNormZero）+  瞬态项零 nid。与 D-9（树改写勿重调非幂等）同族新形态：**世间瞬态产物不得共享编译期单调计数器**。 发现：semantics t109（自查 + SAME 门双重兜住）。
- **D-15 并行成员共享编译单元**：t108/t110 首次双任务并行（文件面不相交），但一方瞬态坏源（测试文件写入半态）阻塞另一方的全量验收跑。规则（队长立）：①子步之间必须保持模块可编译（写文件一次成形，勿留半态离场）；②坏源一律**报告队长+物主修**，其他成员不得代修（避免双向踩写）。首例：T108DerivedMetaTest.kt:92于 05:21 缺引号（syntax 写入半态），semantics 机械补回（经核查确属队长可证的「不是我」（队长 03:2x 后零frontend 写入））。并行决策的结构代价已立规矩。
- **D-16 槽位包装在 gradle 挂住模式下不可靠地串行化**：D-13 记录的「wrapper 在 gradle 完成后挂住、须 XML 直读」形态下，槽位状态（FREE/ACQUIRED）与 gradle 实际执行可失同步——队长验收跑与成员在途构建撞车，test-results 目录被一方清空、一方只写了部分 XML（仅 T110 一份，7 红/12 例）。证据：SLOT=FREE + java=2 + XML=1。纪律补：**启动 gradle 前必须显式确认无在执行 gradle（看 java 进程树与最近 XML mtime），不只看槽位状态**；撞车时不争树，文件级验收先行，全量复算折到树稳定后。
- **D-17 A-LINARITH 两处 soundness 漏洞（假绿类）**：①零系数未规范化（n-1 与 n 的差 {n:0} 令 ceilDivSafe  (_,0)=null → 可证的 measure 义务证不出）；②negateAndApply 常数相消分支对四比较符一律 `C>=0`  符号反转 → `n+1 < n` 被误证（假绿）。两洞互补：②分支在①规范化前不可达 ⇒ **旧代码零 live 暴露**，  t110 measure 通道把它带出且当时错。成员负例先红当场照住并修（ProofChecker:593 trim + :997-1003 按  op 语义直判）。假绿类是证明信诺的 gravest 级（置换原则的反面成员），独立记此条。
