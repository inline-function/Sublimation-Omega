# 定理库与证明缓存（讨论稿 → 待讨论）

> 状态：**讨论稿 → 待讨论（裁决 6：定理库/归纳法暂缓）**。队长 2026-11-08 16:0x 起草。
> 用户裁决：「先暂时用大量公理，后续一步步把公理替换成定理。从 ZFC 公理库手动证明定理；**顶层定理的意义是降低编译器在证明上的耗时**——从公理推出 p 需要很长很长的路径，编译器每次都要推很久甚至推不出来；如果直接证明 p，编译器直接把它加入命题集，显著降低编译耗时。」

## 1 现状实测：`@theorem` **没有任何语义**

`@theorem` 语法已存在（`SymbolTable` 有 THEOREM 分表，`zfc.subl` / `derived.subl` / `自动证明.subl` 都在用），但队长 4 条探针证明：**定理调用对证明零作用**。

| # | 探针 | 期望（若机制存在）| 实测 |
|---|---|---|---|
| t1 | `@theorem fun `thm five`(): Null <∀n . (n >= 5)>` + 调用 + `∴ n >= 5` | 通过（后件入 Γ）| **`E-CANNOT-PROVE`**，`Γ：>=<n, 0>` |
| t4 | 带形参：`thm p(a: Nat): Null <a >= 5>`，`thm p(n)` + `∴ n >= 5` | 通过 | **`E-CANNOT-PROVE`** |
| t5 | 在 `else` 支内调用 + `∴ n >= 3` | 通过 | **`E-CANNOT-PROVE`** |
| t2 | `∵ ∀n . (n >= 5) ∴ n >= 5`（**手写全称形**）| 通过 | **通过** ✅ |

**结论**：

| 事实 | 含义 |
|---|---|
| 定理调用不注入后件 | 「签名即定理」只是**符号表登记**，没有证明语义 |
| `∵` 全称形态可用 | MP + ∀ 实例化通道是好的，只是**没有"定理"这层封装** |
| 未核验定理也不进 `trustedBase` | 审计口径里连「我假设了它」都看不到（`trustedBase` 只收 `AxiomStmt`）|

**所以 `zfc.subl` / `derived.subl` 头注描述的用法（"实例化定理调用 → 注入后件 → 饱和 MP 推结论"）与实现不符。** 那些样本能过，靠的是 `∵` 手写形态 + `axiom` 供给，不是定理机制。

这违反我们的纪律：**文档说存在而实际不存在，比没有更坏**。两条出路——实现它，或改正注释。用户已裁决要实现（§2）。

## 2 用户裁决的含义（重构表述）

把「证明」当作**编译期计算**，那么：

```
成本三级：
  公理实例化   O(1)   信任，但可信基变大
  定理实例化   O(1)   需要「证明一次」的前期投入，可信基不变
  现场证明     O(fuel) ← 今天的唯一路径，长链必撞饱和封顶 256
```

用户要的是能把**长链推导折叠成一步**的设施。这与 ADR-13 §三 推迟的「定理空间搜索（`@theorem` 匹配）」是同一件事的**前置**：没有定理库，搜索无内容可搜。

## 3 机制设计

### 3.1 两级定理

| 形态 | 语义 | 信任 |
|---|---|---|
| `@theorem` **无体** | 断言 = 公理（今日形态，保留但**必须计入 `trustedBase`**）| trusted |
| `@theorem` **有体** | 声明位**核验一次** → 进全局定理库 → 调用点实例化注入 | **verified**（不计信任）|

```subl
// 有体：证明一次，之后处处 O(1)
@theorem
fun `nat nonneg`(n: Nat): Null <n >= 0> {
    ∴ n >= 0            // 体即证明：用既有 prover 证后件
}

// 使用：后件实例化入 Γ
`nat nonneg`(x)
∴ x >= 0
```

### 3.2 实例化（调用点）

1. 形参实参代入后件（项级替换，`propNorm` 已有 `$` 代换机制）；
2. 理论参数（`[T]`/`[@P]`）按显式角表或同名头部匹配（`core.logic` 已有同名命中口径）；
3. 注入当前事实帧，并记 `matched = SymbolRef(定理名)` —— **ADR-13 里空着的 `matched` 字段终于有内容**；
4. 若定理有前件（`preps`），**调用点必须自行证明前件**（不得无条件注入后件）。

### 3.3 依赖与顺序

- 定理可依赖：公理、**先前的**定理（DAG）；
- 循环依赖（含相互定理）→ **拒绝**并给明确诊断（不得靠轮次上限兜）；
- 定理体核验时，可用的就是**到该点为止**的事实集（确定性，与文件顺序绑定）。

### 3.4 与饱和封顶/燃料的关系

| 现状 | 后果 |
|---|---|
| MP 饱和封顶 256 | 长链（ZFC 推导）必撞上限 ⇒ 证不出 |
| 燃料（t51）| 无限搜索的兜底 |

定理实例化是 **O(1) 注入**，不参与饱和搜索——这正是它能救长链的原因。

### 3.5 可观测性（用户关心的"耗时"必须可见）

| 设施 | 内容 |
|---|---|
| `--proof-stats` | 每条义务：步数、规则、命中定理、是否撞封顶 |
| 诊断提示 | 燃料/封顶耗尽时提示「**可将此命题提取为顶层定理**」 |
| HIR | 定理调用记 `matched`，义务记 `steps` |

没有这三个，用户无法判断"该不该提定理"，优化就变成盲猜。

## 4 健全性（三条硬线）

1. **有体定理必须核验**：核验失败 = 错误（`@theorem` 不得因为"是定理"就免证）。
2. **无体定理必须计入 `trustedBase`**（今日的洞）：它与 `axiom` 等价，只是拼写不同。
3. **`--no-trust` 必须排除无体定理**：否则 CI 模式形同虚设。

## 5 ZFC 起步路线（用户指定起点）

| 阶段 | 内容 |
|---|---|
| Z0 | `zfc.subl` 八组公理 = 信任基（今天就位，8 条）|
| Z1 | 机制落地（§3）；`derived.subl` 的无体定理**改为计入信任**并标注 `W-THEOREM-UNPROVED` |
| Z2 | 逐条给 `derived.subl` 补证明体：空集存在/唯一/最小 → 单元素集 → 布尔运算 → 分离 → 子集四性质 |
| Z3 | 补完即从 **trusted 降级为 verified**，`trustedBase` 相应收缩 |
| Z4 | 归纳法落地 ⇒ 皮亚诺/有限序数，`Nat` 的公理也可降级为定理 |

**Z2 是体力活，但每一步都可核验、可度量**（trusted 条数单调下降）。这正是用户说的"一步步把公理替换成定理"的**可执行版本**。

## 6 一个必须提前想清楚的问题：定理的**前提**

ZFC 公理多为蕴含形（`∀x. (x∈s1 ↔ x∈s2) → s1=s2`）。定理化之后：

```subl
@theorem
fun `set extensionality`(s1, s2): Null <(∀x . ((x ∈ s1) ↔ (x ∈ s2))) → (s1 = s2)> { … }
```

调用点（`s1`、`s2` 已代入）必须**先证前件** `∀x. (x∈s1 ↔ x∈s2)`。这是**正确的**（否则就是无条件假设），但会带来：

- 前件往往与后件同形复杂度 ⇒ 用户仍需 `axiom` 供给前件 ⇒ **定理的实用价值打折**；
- 折中：`axiom ∀x. ((x ∈ s1) ↔ (x ∈ s2))` + 定理调用（今日 `zfc.subl` 头注的用法），**前件仍由用户断言**。

这不是设计缺陷，是**诚实的代价**：蕴含形定理不能免费使用。需要用户确认这个口径（§7 Q2）。
