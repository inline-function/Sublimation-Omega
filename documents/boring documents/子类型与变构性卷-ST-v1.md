# 子类型与变构性卷 ST-v1

> 状态：**草案（2026-11-06）**，用户已裁决部分为 🟢，待裁决为 🔵。
> 本卷为 P-10（类型系统第二改向）的总纲。与 `类型系统卷-TS-v1.md` 的关系：TS 卷管「特质/扩展函数/满足判定」，本卷管「子类型、变构性、解选择」，TS-23（V1 无字典派发）**作废**。

## 1 原则

### ST-1 健全性铁律 🟢
类型系统在**不使用 `axiom` 或 `unchecked` 等手段绕开时，必须健全**。
含义：凡「为了让某个常见写法通过而放宽」的规则，一律不合法，必须改为可证明健全的规则，或**显式**要求用户写 `unchecked`。
> 用户原话（2026-11-06 16:24）：「原则是类型系统在不使用axiom或者unchecked等手段绕开时必须健全」。

### ST-2 逃生门 🟢（存在性已定，形态待定）
`axiom` 与 `unchecked` 是**唯一**允许不健全的通道，且必须显式书写、可被检索。

## 2 关键字：`class` → `trait` 🟢

类型类声明关键字由 `class` 改为 `trait`。语义不变：声明一组函数规范；实现由扩展函数承担（P-8）。
```subl
trait Show[T] {
    fun show(): Str
}
```
连带：文法 S-9 改写；诊断文本、样例、注释、文档中的「类型类」术语统一为「**特质**」。

## 3 子类型关系

### ST-3 满足即子类型 🟢
若类型 `T` 满足特质 `C`（P-8 的结构化满足），则 **`T <: C`**。无需任何声明即成立（隐式、结构化）。

### ST-4 特质可作值类型 🟢（推翻 TS-23）
变量/形参/字段的类型可以是特质：
```subl
var s: Show = Point(1, 2)      // Point 满足 Show ⇒ Point <: Show
s.show()                        // 运行期需派发到 Point 的 show 实现
```
**后果**：必须有运行期派发装置。🟢 **裁决（16:50）：采用显式字典传递（dictionary passing）**——每个装箱值携带其实现表，调用点显式取字典。HIR 须逐点表达「装箱值 + 字典」，**不做**「只留 existential 标记」的省事版本。此项属 HIR schema v3 级改动。

### ST-5 泛型类型参数可为特质 🟢
```subl
var xs: List[Show] = …          // List 的类型参数是特质
```

### ST-6 底类型 `Nothing` 🟢
`Nothing <: T` 对任意 `T` 成立（`Nothing` 可用于任何类型位）；**反向不成立**（`T` 不可当 `Nothing`）。
现行实现 `TypeInfer.adaptOk` 的 `isNothingT(got) || isNothingT(want)` **双向放行是错误的**，须改为仅 `got` 侧。

### ST-7 函数类型变构性 🟢
`(A) => R <: (B) => S` 当且仅当 **`B <: A`（参数逆变）且 `R <: S`（返回协变）**。
现行实现两侧皆协变，**不健全**，须改。

### ST-8 联合类型 🟢
`A <: A | B`（注入，单向）；`A | B` 不得当 `A` 用（消去须靠 `is` 收窄）。

### ST-9 特质继承 🟢
**保留**父链：`trait Sub[T] : Base[T]`。父子特质之间有**子类型关系**——`Sub <: Base`，且规范取并集（TS-8 继承闭包继续有效）。
> 用户裁决（16:50）：「特质保留继承，父子特质有子类型关系」。

### ST-10 数值塔 🟢
数值塔为 `Nat <: Int <: Rat`（单向只升），三者是真子类型，须有**运行期表示转换**。

**`Nat` 为任意精度（无界），队长 2026-11-08 05:2x 裁定**（修正原「具界无符号」措辞）：

| 理由 | 说明 |
|---|---|
| 证明器健全性 | 证明器已对 `Nat`/`Int` 做**线性算术**推理（差分图、等式链）。若 `Nat` 有界，则 `a + b ≥ a`、`a * 2 ≥ a` 这类**已证命题在运行时可假**（溢出）⇒ 类型/证明系统与运行时脱节 |
| 语言承诺 | 本语言对「编译器检查时无法停机」都选择拒绝而非放任；对**算术溢出**同口径——不允许存在「证过的命题运行时却假」的缝隙 |
| 代价 | 运行时用无界整数；`Nat - Nat` 结果必须是 `Int`（见下）|

**减法规则（ST-10.1）**：`-` 的结果类型**至少为 `Int`**：

| 运算 | 结果 | 理由 |
|---|---|---|
| `Nat - Nat` | **`Int`** | 差值可为负 |
| `Nat - Int` / `Int - Int` | `Int` | 闭包 |
| `Rat - Rat` / `Rat - Nat` | `Rat` | 闭包 |
| `Nat + Nat` / `Nat * Nat` / `Nat % Nat` | `Nat` | 无界 ⇒ 闭包 |

**ST-10.2 证明驱动的收紧（用户 2026-11-08 09:3x 裁决）：减法返回 `Int`，非负性由证明器智能转换**

> 裁决原文：「`Nat - Nat` 应该返回 `Int`，由自动证明器进行智能转换，比方说当前环境可以证明前 `Nat >=` 后 `Nat`，就智能转换返回值为 `Nat`。」

**规则**：

| 情形 | 类型 |
|---|---|
| `a - b`（`a, b : Nat`），Γ ⊬ `a >= b` | **`Int`**（ST-10.1 不变）|
| `a - b`（`a, b : Nat`），Γ ⊢ `a >= b` | **`Nat`**（证明驱动的收紧）|

这是**收紧**方向（`Nat` 比 `Int` 严），不会放行非法程序；若证明失败，行为退回 ST-10.1，**不改变错误面**。

**实现前提（2026-11-08 09:4x 队长实测，两个都尚未具备）**：

| # | 前提 | 现状 |
|---|---|---|
| 1 | **类型事实注入 Γ**：`x : Nat` ⇒ 事实 `x >= 0` | ❌ 未注入。实测 `n : Nat` + `axiom n != 0` ⇒ `∵ n != 0 ∴ n >= 1` **证不出** |
| 2 | **分支事实注入**：`if (n == 0) { } else { }` 的 else 支注入 `n != 0` | ❌ 未注入。实测 else 支内 Γ 为**空** |
| 3 | 算术通道本身 | ✅ 已有。实测 `∵ a >= b ∴ a - b >= 0` **通过** |

所以「智能转换」不是加一条类型规则，而是**要让证明器看见足够的事实**。第 1、2 条是它的使能条件。

**为何这两条本来就该有**：证明器连「`n` 是 `Nat` 故 `n >= 0`」都不知道，意味着**它读不懂类型**——这本身是 V1 的能力缺口（ADR-13 §三 的「类型判定 (e:T)」同源）。

**与 P-12 的关系**：本规则是 `P-12 证明驱动的类型精化` 的**第一个落地实例**，也是其第 ③ 级的最小验证场景——比 `id(1) : Nat` 更容易做（不涉及函数体展开），且立刻有实用价值（下标算术 `take(xs, n - 1)` 在下溢可证时不再报错）。
### ST-11 顶端类型 `Any` 🟢（待细化实现）
现行 `Any` 仅作「期望位放行」（`isAnyExpect`）。若 `T <: Any` 是子类型关系，`Any` 须成为真类型（可作变量类型、可被 `is` 判定）。

### ST-11.1 视图降级与单向子类型（队长 2026-11-08 01:2x 补，源自 t60 暴露的分类缺陷）🟢

`@mut T` 是**能力视图**，不是独立的值类型。规则：

| 判定 | 成立？ | 理由 |
|---|---|---|
| `@mut T <: T` | ✅ | 可变格可只读使用 |
| `T <: @mut T` | ❌ | 不可变值没有写入能力 |
| `@mut T <: @mut U` | 仅当 `T = U` | ST-13.1：可变视图不变 |
| `T <: U`（无视图） | 按偏序 | — |

**初始化是例外，不是子类型**：`var x : @mut T = v` 是**造格**（新建可变单元），故核对 `typeof(v) <: T`；同理赋值 `x = v` 写入的是格内容，核 `typeof(v) <: T`。**不得**据此推出 `T <: @mut T`。

**硬性实现要求（类型计算一律先降级）**：

> 任何「按类型分类」的判定——数值性（`isNumeric`）、算术结果类型、区间端点、字符串拼接、比较的名义性检查、联合成员判定——**必须先做 `demoteView`（`@mut T → T`）**，不得直接对 `HirNamedType` 模式匹配。

**反例（必须都成立）**：
```subl
fun f(a: @mut Nat): Nat = a            // ✅ 读视图给值
fun g(a: Nat): @mut Nat = a            // ❌ 不可变值无写入能力
var x : @mut Nat = 1
x = x + 1                              // ✅ 算术看降级后 Nat
fun h(p: @mut P): Nat = p.x + 1        // ✅
fun r(a: @mut Nat): Range[Nat] = 0..a  // ✅
```

**禁止猜测**：类型计算路径上不得用「猜一个类型」兜底（如算术无法定类时返回 `Bool`）。无法定类 ⇒ 落诊断 + 返回**合成位**（由 R-38 闸抑制级联），**绝不返回一个看似合理的具体类型**——那会把「不知道」伪装成「知道」，并在别处以错误的面目爆出来。

## 4 变构性自动推断 🟢

**用户要求**：特质的类型参数根据**使用处**自动推断为逆变/协变/不变，无需用户声明。

### ST-12 推断规则（草案，待确认）
对特质 `C[X]`，收集 `X` 在其全部成员规范签名中的**位置极性**：
| 出现位置 | 极性 |
|---|---|
| 函数返回类型 | 正（协变） |
| 函数形参类型 | 负（逆变） |
| 形参本身是函数类型 `(X)=>…` | 负×负 = 正 |
| `@mut X` 下 | 不变 |
| 作为另一泛型 `G[…]` 的实参 | 乘上 `G` 对应参数的极性 |

合并：只出现正位 → **协变**；只出现负位 → **逆变**；两者都有 → **不变**。
递归特质需**不动点迭代**（初值取双变/bivariant，逐步降级）。

## 5 类型参数声明文法 🟢

```ebnf
理论参数 ::= "[" 类型参数 ("," 类型参数)* "]"
类型参数 ::= 名字 (":" 类型)?
```

> 🟢 **裁决（2026-11-06 17:05）**：**不区分 `:` / `<:` / `:>`**，统一为 `:`；`<:` 与 `:>` **不引进**。
> 🟢 **裁决（2026-11-06 17:1x）**：`:` 是**子类型语义**，不是特质约束语义。

### ST-13 界的含义由使用处的变构性推断 ℹ️🟢
`[T: X]` 中的 `X` 是**上界还是下界**，由 `T` 在声明体中的使用处自动推断：

| `T` 的使用处极性（按 ST-12 复合计算） | `X` 的含义 | 读作 |
|---|---|---|
| 协变（正位） | **上界** | `T <: X` |
| 逆变（负位） | **下界** | `T :> X` |
| 正负皆有（不变） | **非法**——报错 `E-BOUND-INVARIANT` | — |

**示例**：
```subl
trait Show[T] { fun show(): Str }

fun showAll[T: Show](xs: List[T]): Str   // T 只出现在协变位 → 上界：T <: Show
fun minOf[T: Nat](a: T, b: T): T         // T 出现在形参（负）与返回（正）→ 不变，待定
```

#### ST-13.1 变构性**按视图**分别推断（用户 2026-11-08 00:2x 裁决）🟢

> 裁决原文：「类型参数的变构性推断看它的使用位置。如果只在函数参数上使用，则是逆变；如果只在返回类型以及**不可变属性**上，则是协变；如果又协变又逆变，就自动推断为不变。如果**在所有的非 `@mut` 函数里都是协变位，但是在 `@mut` 函数里有逆变位的使用**，则认为这个类型参数在**类型没有 `@mut` 的时候是协变，在有 `@mut` 的时候是不变**。」

**结论**：变构性不是一个值，而是**一对值**——由视图决定：

```
variance(C, T) = (σ_imm, σ_mut)
  σ_imm：T 在**不可变视图**（不含 @mut 接收者的成员、不可变字段）中的极性 → 协变 / 逆变 / 不变
  σ_mut：T 在**可变视图**（@mut 接收者成员、可写字段、及全部不可变视图使用）中的极性 → 协变 / 逆变 / 不变
```

| 规则 | 内容 |
|---|---|
| R1 | 只在形参位 | 逆变 |
| R2 | 只在返回位 / 不可变属性位 | 协变 |
| R3 | 两者皆有 | 不变 |
| R4 | 非 `@mut` 全协变，`@mut` 中有逆变位 | **`σ_imm = 协变`，`σ_mut = 不变`** |
| R5 | 对称情形：非 `@mut` 全逆变，`@mut` 中有协变位 | `σ_imm = 逆变`，`σ_mut = 不变` |

**单调性**：因为 `@mut` 视图只**增加**使用处，所以 `σ_mut` 的「混合程度」恒 **≥** `σ_imm`。即：
```
σ_imm = 不变  ⟹  σ_mut = 不变
σ_mut = 协变  ⟹  σ_imm = 协变
```

**对子类型的直接后果**（这是 R4 的真正意义）：

| 判定 | 要求 |
|---|---|
| `List[A] <: List[B]` | `A <: B`（协变）|
| `@mut List[A] <: @mut List[B]` | `A = B`（不变）|

**为什么必须如此**：若 `@mut List` 允许协变，则
```
var ns : @mut List[Nat] = MutableListOf()
var as : @mut List[Any] = ns      // 协变允许
as.add("abc")                     // 把 Str 塞进声明为 List[Nat] 的容器
```
直接违反 ST-1。**可变性是不变性的代价**，不是可以商量的偏好。

**对类型推导的后果**（P-11）：元变量落在 `@mut` 视图下 ⇒ 约束为**等式**（取交）；落在不可变视图下 ⇒ 按极性取 `lub` / `glb`。

**实现注意**：
- 计算 `σ_mut` 时须把 `@mut` 接收者方法的**形参位**计入（这正是 R4 的触发点）；
- 可写字段同时提供读取（+）与写入（−），故**自身即不变**；
- 递归类型仍需不动点迭代（ST-13 原「DAG + SCC」要求不变）。

**开放问题**：`@mut` 作为**类型构造子本身**出现在参数位时（如 `fun f(xs: @mut List[?T])`）如何参与外层的极性复合，待 P-10 步骤 3 实测后补。

### ST-14 `:` 与满足判定的统一 🟢
由于 ST-3「满足即子类型」，**特质约束不再需要独立记法**：
```
T : Show   ⟺   T <: Show   ⟺   T 满足 Show
```
即：`[T: Show]` 的检查**从 satisfiesCheck 通道并入子类型偏序判定**。

> 后果：现行 `E-TC-BOUNDARY`（「约束是具体类型而非特质」）**语义作废**——`[T: Nat]` 变为合法（上界 Nat）。见 §8 L7。
## 6 类型变量解选择 🟢（规则待细化）

**用户原话**：「当函数泛型中的类型参数的使用处皆为逆变时取上界，否则取下界；对不可比候选解再求它们的上界」。

🟢 **裁决（16:50）：极性按位置复合计算**（负×负 = 正）。据此：
| 情形 | 结果 |
|---|---|
| 全部使用处复合后为**逆变**（即无反转为正的位） | 取**上界** |
| 出现复合后为**正**的位（协变），或正负皆有 | 取**下界** |

即：「复合」这一情形归入**取下界**一侧。

### L1 遗留项：类型参数记法 ✅ 已裁决（17:05 / 17:1x）
统一为 `:`，不引进 `<:`/`:>`；`:` 为**子类型**语义，界的方向由使用处变构性推断（ST-13）。

### L6 遗留项：不变的类型参数如何写界 ✅ 已裁决（17:15）
**裁决：报错。** 若 `T` 在声明体中既有协变使用又有逆变使用（不变），则 `[T: X]` 非法——
落 **`E-BOUND-INVARIANT`**：「类型参数 T 在使用处既作协变又作逆变（不变），`:` 界无法确定是上界还是下界；请改为 `[T]` 不加界，或调整使用处使 T 的变构性单一」。

理由：不变参数加界本身就是没想清楚——报错强制用户表态，优于替他猜一个方向。

**实现顺序（重要）**：变构性推断必须先于界方向判定。变构性只依赖签名的**位置结构**，不依赖界本身，因此不存在真循环：
```
签名 → 位置极性复合 → 变构性（协变/逆变/不变） → 判 `:` 的方向（或对不变者报错）
```
### L7 遗留项（**新增**）：`E-TC-BOUNDARY` 语义作废后的去向
`[T: Nat]` 现为合法（上界 Nat），故「约束必须是特质」的边界诊断失去依据。该码要么废除（进 `码名迁移台账.md`），要么改造为「界的类型不存在/不可为界」。
### L2 遗留项：诊断码名迁移（缓慢进行，**须留台账**）
`E-TC-*` → `E-TRAIT-*` 等码名改动**缓慢推进**，每改一处必须在 `码名迁移台账.md` 登记（旧名 / 新名 / 位置 / 是否已同步 ADR 与测试）。
**该台账是防遗忘的唯一凭据**，未登记者一律视为未改。

### L3 遗留项：子类型判定与满足判定的缓存共用
`T <: C`（结构满足）与 `satisfiesCheck` 必须共用同一缓存与同一「可见集」口径（TS-19 修订版），否则会出现「满足但非子类型」或反之的矛盾。

### L4 遗留项：`Any` / `Nothing` 是否为真类型
二者当前靠**名字硬判**（`isAnyExpect` / `isNothingT`），未在符号表登记。若升级为真类型，须能被用户引用、能参与 `is` 收窄、能出现在诊断文本里。

### L5 遗留项：`unchecked` 的形态
ST-2 的逃生门目前只有一个成员 `axiom`。`unchecked` 是关键字、注解（`@unchecked`）还是块级修饰，尚未确定。
### ST-15 双向类型检查的燃料（fuel）与不可停机拒绝 🟢

> 用户裁决（2026-11-07 08:45）：「在进行双向类型检查的时候，需要为函数增加燃料，使得函数总在有限次内停机，当函数燃料耗尽却仍然没有完成检查时，拒绝这个检查，并且给出错误诊断：『编译器进行检查时无法停机』」

**问题来源**：P-9 允许**归纳类型别名**（`type Peano = Zero | Succ[Peano]`，ST 之外的 P-9 ⑦）；t47 的 R-28 又在 `adaptOk` 侧引入别名↔联合双向合一。结构比较一旦沿 `Peano → Succ[Peano] → Peano → …` 展开，检查器**可能不终止**。

#### 15.1 燃料计量
| 项 | 规定 |
|---|---|
| 计量单位 | **判定步**：每发生一次 `adaptOk` / `unifyInto` / 别名展开 / 联合展开 / 结构成员逐个核对，扣 1 |
| 预算池 | **每次顶层检查请求**（一次表达式或声明的类型核对）新建一个预算池；该请求内的所有嵌套调用**共享同一池** |
| 不得逐层重置 | 若每层递归各自重置预算，深度爆炸将不受控（O(深度×预算)），等于没有燃料 |
| 默认上限 | 常量 `FUEL_DEFAULT`，初值取「正常代码消耗的 100 倍以上」量级；允许调试期通过系统属性覆盖 |
| 确定性 | 计数器须为单线程单调递减，**不得**依赖 Map 迭代顺序或哈希序，保证同输入同计数 |

#### 15.2 耗尽行为
1. **拒绝该检查**（返回失败，不放行）。
2. 落 **`E-FUEL-EXHAUSTED`**，文案**严格**为：**「编译器进行检查时无法停机」**。
3. 诊断须附带：①触发耗尽的**源位置**；②检查目标摘要（期望类型 / 实际类型）；③**已消耗步数**与上限；④建议（多由归纳类型展开导致，可加显式类型标注切断推导）。
4. **不得**降级为 `synthetic` 放行、不得吞掉、不得改为 `warn`。

#### 15.3 健全性取向（关键）
燃料耗尽 → 拒绝，方向是**保守的假阴性**（可能拒绝合法程序）。这在健全性上可接受。
**绝对禁止**的相反方向：把燃料耗尽当作「未知相容」放行——那会成为绕过类型检查的后门，违反 ST-1。

#### 15.4 覆盖范围（必须全部纳入）
- `TypeInfer.adaptOk`（赋值相容性）；
- `unifyInto`（t47/R-28 的别名↔联合双向合一）；
- 别名/联合展开（t41/R-16、t47/R-28）；
- 结构成员逐个核对（struct 字段、函数参数位）；
- 约束求解（P-10 步骤 4 落地后同样纳入）。

#### 15.5 与后续步骤的关系
燃料是**兜底**，不是**解法**。递归类型比较的正解仍是**结构化等价 + 余归纳（coinductive）假设集**（比较 `Peano` 与 `Peano` 时先假设成立、再验成员）。
V1 允许只用燃料兜底；但若某递归类型场景**经常**耗尽燃料，说明缺的是假设集而不是预算，须单独立项。
