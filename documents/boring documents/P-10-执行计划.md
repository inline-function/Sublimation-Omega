## 0 总原则

1. **一步一收口**：每一步必须独立到达「测试 0 失败 + e2e 不回退」才进下一步。
2. **归因优先**：任一步引起的 e2e 转红，必须逐条分类为「预期（裁决后果）/ 意外（缺陷）」，**不得合并报告**。
3. **旧路径已死**：每个 ADR 必须有一节「旧路径已死」——列出被替代的旧代码位置，并证明其不可达（t44 的教训：注入新实现却没让位内置名表，一份真相变两份）。
4. **禁止放宽凑数**：不得为让样例绿而放宽判据、加 `unchecked`、删断言、删样本。
5. **构建槽位独占**（S-3 §8.3）。

## 步骤 1：健全化收口（纯收紧，不引入新概念）

**目的**：先让类型检查「诚实」，再往上加偏序。否则新规则会架在不健全的地基上。

| # | 现行不健全规则 | 位置 | 改法 |
|---|---|---|---|
| 1 | `synthetic` 位一律放行 | `adaptOk` 内 synthetic 分支 | 改为「仅在推导未完成时容忍，完成后必须复核」，禁止长期放行 |

## 步骤 3：变构性自动推断

| # | 内容 |
|---|---|
| 3.1 | 位置极性计算：形参负、返回正、嵌套复合（负×负=正） |
| 3.2 | 递归类型（自引用）用不动点迭代；依赖图为 DAG + SCC |
| 3.3 | 每个类型参数定出 **变构性对** `(σ_imm, σ_mut)`——不是单个值，见 **ST-13.1**（用户 2026-11-08 00:2x 裁决）|
| 3.4a | 视图划分：不可变视图（返回位、不可变字段）/ 可变视图（`@mut` 接收者成员的形参位、可写字段、含全部不可变视图使用）|
| 3.4b | R4/R5：非 `@mut` 全协变但 `@mut` 中有逆变位 ⇒ `(协变, 不变)`；对称情形 ⇒ `(逆变, 不变)` |
| 3.4c | 单调性自检：`σ_imm = 不变 ⇒ σ_mut = 不变`；`σ_mut = 协变 ⇒ σ_imm = 协变` |
| 3.4 | 界方向判定：协变→上界、逆变→下界、**不变→`E-BOUND-INVARIANT`** |

**实现顺序（关键，避免假循环）**：
```
签名 → 位置极性复合 → 变构性 → 判 `:` 的方向（不变者报错）
```
变构性只依赖**签名的位置结构**，不依赖界本身，故无真循环。

**验收**：`List[T]` 协变、`(T) => U` 中 T 逆变 U 协变；`fun f[T: Nat]` 与 `fun g[T: Nat]`（用于逆变位）分别判为上界/下界；**声明位**不变者报 `E-BOUND-INVARIANT`。

**新增验收（ST-13.1 触发）**：
1. `List[T]` 判 `(协变, 协变)`；`@mut List[T]` 判 `(协变, 不变)`；子类型判定 `List[Nat] <: List[Any]` **成立**、`@mut List[Nat] <: @mut List[Any]` **不成立**。
2. 反例探针（必须被拒绝）：`var ns : @mut List[Nat] = MutableListOf(); var as : @mut List[Any] = ns; as.add("abc")`。
3. 单调性机械自检：全仓类型声明扫一遍，断言不存在 `σ_imm = 不变 且 σ_mut ≠ 不变` 或 `σ_mut = 协变 且 σ_imm ≠ 协变` 的组合。

**e2e 零覆盖警告（qa t55 核查）**：e2e 样本中 `[T: X]` 形态**零处**（`core/number/num.subl:4` 仅注释提及）⇒ ST-12/ST-13 **没有任何回归保护**。故本条**必须新建测试**；不新建就进步骤 4 判失败（**G7**）。

## 7 验收方案（外部依据）

`documents/P-10-验收方案.md`（qa t55）是本章的可执行展开；本计划与其冲突时**以验收方案为准**（它给出了逐条正负例、佐证通式与反向门禁）。

三条必须内化的方法论：
1. **佐证通式**：每条负例配一个「仅规则关注处不同」的对照例；只有「负例落错 **且** 对照例通过」才证明拒绝源于该规则——否则可能拿语法错/未定义名冒充健全性拒绝。
2. **负例先于实现**：实现方先把负例跑红（留今日基线证据），再改实现跑绿。**先绿后红不可信**（可能是判据本来就不管）。
3. **反向门禁 G1~G12**：三件套全绿仍判失败的情形（负例缺失/被放宽、码名漂移、燃料耗尽被降级、台账未登记、预期红未声明就改样本、确认型条目回退等）。

**步骤 1 预期转红声明**：qa 预估 **0~3 条**（P1 `Nothing` 反向 / P2 函数参数协变 / P4 `synthetic` 泄漏——今日实测三者全部放行，修好即转红）。若实际 **>5 条**，先归因为缺陷，**不要先改样本**。
