## 0 范围、术语、总原则

**TS-1** 本卷规定类型系统的声明形态、扩展函数、特质与结构化满足、约束检查，以及它们与 HIR 的映射。语法层形态见《形式化文法》相应修订；本卷不重复抄录产生式。

**TS-2（总原则）** 类型系统遵循「**二要素**」：**特质声明（trait）** 与 **类型声明（struct / enum / alias）**。`impl` 不再是语言要素，凡出现即报 `E-IMPL-REMOVED` 并给出迁移提示。

**TS-3（术语）**

| 术语 | 含义 |
| --- | --- |
| 特质（trait） | trait 声明，仅含**函数规范**，不含实现体与字段 |
| 函数规范（spec） | 特质内的一条函数签名：名字 + 形参表 + 返回类型 + 理论参数 |
| 扩展函数（extension function） | 接收者类型写在函数名前的函数：`fun Nat.f(...)` |
| 接收者（receiver） | 扩展函数声明中函数名前的类型表达式 |
| 结构化满足 | 类型 T 的扩展函数集覆盖特质 C 的全部规范 ⇒ T 满足 C |
| Self | 特质体内指代「最终满足该特质的类型」的隐式类型名 |
| 约束（constraint） | 形如 `T: C` 的签名附加条件 |

## 1 特质（trait）

**TS-4（语法形态）**

~~~
trait Functor {
    fun map[A, B](fa: Self[A], f: (A) => B): Self[B]
}
~~~

**TS-5（Self）** trait 体内 `Self` 隐式在作用域中，指代满足该特质的那个类型。`Self` 可带类型实参（`Self[A]`），以表达对类型构造器的要求（如函子）。

**TS-6（成员限制）** trait 体只允许：①函数规范（无实现体）；②常量规范（`val name: T`，无实现）——V1 允许但不参与满足判定的必需项（TS-17）；③特质继承声明（TS-8）。禁止字段声明、禁止实现体、禁止嵌套类型声明。

**TS-7（规范语义）** 函数规范是**要求**，不是实现。规范不得含默认值（默认值属实现细节，归实现方扩展函数）。

**TS-8（继承）** 保留 `trait Sub : Base`。语义：满足 Sub ⇒ 满足 Base（父类规范并入子类要求），传递闭包参与满足判定。循环继承报 `E-CYCLE`。

## 2 扩展函数

**TS-9（语法形态）**

~~~
fun Nat.f(): Nat = self + 1
fun List[A].map[B](f: (A) => B): List[B] = ...
~~~

形态：`fun Receiver.name[理论参数](形参表): 返回类型 = 体`。Receiver 是类型表达式，可含类型参数（`List[A]`）、可嵌套（`List[Optional[A]]`）。

**TS-10（接收者绑定）** 扩展函数体内，接收者以保留名 **`self`** 绑定，静态类型为 Receiver。若函数另声明了同名形参，报 `E-DUP-NAME`。

**TS-11（登记）** 扩展函数按 **(接收者类型头, 名字)** 登记，与自由函数分属不同解析桶，互不遮蔽。

**TS-12（调用形态）** 三种，语义等价：

| 形态 | 例 | 解析桶 |
| --- | --- | --- |
| 方法糖 | `x.f(a)` | 只查扩展函数（按 x 的静态类型头） |
| 直接调用 | `f(x, a)` | **先查自由函数**；无匹配再按实参 1 的类型头查扩展函数 |
| 类型限定 | `Nat::f` | 按给定类型头查扩展函数 |

**TS-13（重复声明）** 同一 (接收者类型头, 名字, 形参类型列表) 重复声明扩展函数 → `E-DUP-EXT`（两处位置均报）。

**TS-14（歧义裁定）** 直接调用形态下，若自由函数与某扩展函数**同时**匹配，**自由函数优先**。此裁决保证同一源码在任何实现下解析唯一（不按「更具体」打分）。

**TS-15（泛型扩展）** 扩展函数可泛型；理论参数在 Receiver 与签名其余部分均可使用。Receiver 中出现但未在理论参数表声明的类型名 → `E-UNBOUND-NAME`。

**TS-16（递归与自调用）** 扩展函数体内可直接调用自身（方法糖或直接调用形态），按普通函数递归处理。

## 3 结构化满足

**TS-17（定义）** 设类型 T、特质 C。**T 满足 C** 当且仅当：对 C（含继承链闭包）的**每一条函数规范** σ，都存在以 T 为接收者的扩展函数 f，使得把 σ 中 `Self` 全部替换为 T 后，σ 与 f 的签名**一致**。

签名一致 = 名字相同 ∧ 形参个数相同 ∧ 形参类型逐位一致（经归一与别名展开）∧ 返回类型一致。

常量规范（TS-6②）V1 不参与必需项判定（记入 §10 边界）。

**TS-17a（空规范特质）** 规范集为空（且继承链亦空）的特质，被**所有类型平凡满足**——这是 TS-17 定义域的辑后承，不是缺陷。因此旧体系里「空特质 + `impl`」所表达的「标记/分类」语义在新体系下**没有语言效果**：要让某个分类产生约束，特质必须至少含一条函数规范。（t31 迁移中 `num.subl` 的 `impl Num for Rat` 即属此类，迁移时移除。）

**TS-18（判定时机）** **使用期现场判定**：在约束检查点（TS-22）对 (T, C) 求值。声明期不判定——未来仍可能补充扩展函数，声明期判定会与增量扩展冲突。结果可在单次编译内按 (T, C) 缓存。

**TS-19（顺序无关，2026-11-06 修订）** ~~判定基于同一编译单元内已登记的扩展函数全集，与声明先后无关（前向引用合法）。~~

> **修订（2026-11-06，用户裁决「扩展函数理应可以局部声明，而且这是我们语言的核心特性」）**：判定改为基于**调用点可见的扩展函数集合**——即沿词法作用域**内→外**，按 **(接收者类型头, 名字)** 键遮蔽后的可见集，再并上全局其余键。
>
> **仍然成立的性质**：**同一域内**声明顺序无关（因为同域同键不允许重复，见 TS-19b）。被放弃的只是「跨域也是全集」这一点——那是局部扩展函数引入的必然结果。
>
> **正当结果**：同一类型在**不同词法位置**的满足性可以不同。这不是缺陷，是局部扩展函数的语义（示例见 ADR-27）。

**TS-19a（局部扩展函数，2026-11-06 新增）** 扩展函数**可以在任何出现函数声明的位置声明**，包括块内（局部）。局部扩展函数的可见性与生命周期同其所在词法域：出域即不可见，出域即不再参与任何判定。

**TS-19b（扩展函数的同域唯一与跨域遮蔽，2026-11-06 新增）**
1. **每个域内**，同一 (接收者类型头, 名字) 只允许一个扩展函数声明；重复报 `E-DUP-EXT`（TS-13 不变，只是把「全局唯一」收窄为「域内唯一」）。
2. **跨域**按 **(接收者类型头, 名字)** 键遮蔽：内层同键声明遮蔽外层同键声明，且**不回退**。
3. **异键不遮蔽**：内层 `Nat.f` **不得**遮蔽外层 `Str.f`——它们是不同接收者的不同函数。这是扩展函数与自由函数遮蔽粒度的**关键差异**：自由函数按**名字**整体遮蔽（TS-19c），扩展函数按键遮蔽。

**TS-19c（自由函数与变量的遮蔽粒度，2026-11-06 新增）**
1. **顶层**：自由函数与自由变量**名称唯一**；重名报 `E-DUP-DECL`。
2. **局部域内**：**允许**重名，**后声明遮蔽先声明**（不报错，落 `H-SHADOW` 提示）。
3. **跨域**：内层按**名字**整体遮蔽外层同名者——内层一旦声明 `f`，外层所有 `f` 在内层不可见，**类型不匹配就报错，不回退外层**。
4. 遮蔽发生时编译器落 `H-SHADOW`（H 族提示，非警告：遮蔽是合法行为）。

**TS-20（部分满足）** 缺任一必需规范即**不满足**。诊断须列出**缺失规范清单**（名字 + 期望签名），而非只说「不满足」。

## 4 约束与检查

**TS-21（约束语法）** 函数与扩展函数的理论参数表可带约束：

~~~
fun combine[T: Monoid](a: T, b: T): T = a.append(b)
~~~

**TS-22（约束检查点）** 调用点：实参推导出 T 的具体类型后，检查该类型是否满足约束中的特质（TS-17）。不满足 → `E-TC-NOT-SATISFIED` + 缺失规范清单。

**TS-23（不做字典传递）** V1 不引入字典传递 / 隐式解析 / 分派：约束只用于**检查**，调用点的实际函数解析**始终**按 TS-12 落到具体函数。因此 V1 不存在「特质多态分派」，只有「编译期满足性检查」。

> 动机：与用户方向一致——「满足特质即视为子类型」是**子类型关系**，不是运行时分派；且避免字典传递把 HIR 复杂度推高。运行时分派留待后继卷。

**TS-24（约束边界）** V1 约束仅支持「单个类型变量 : 特质」。不支持并报 `E-TC-BOUNDARY`：高阶类型约束（`F[_]: Functor`）、多约束合取（`T: A + B`）、约束中出现具体类型。

## 5 Self 与类型参数的分界

**TS-25** `Self` 只在 trait 体内有意义。出现在体外 → `E-SELF-OUTSIDE-CLASS`。

**TS-26** 扩展函数的 Receiver 与特质的 `Self` 是**不同机制**：前者声明处即已确定具体类型头；后者是待替换占位。不得互相冒充。

**TS-27** 满足判定替换 `Self` 后**不得残留**；残留即判定失败并报 `E-TC-NOT-SATISFIED`（附原因「Self 未被完全替换」）。

## 6 与 HIR 的映射（保真要求，D-9）

**TS-28（扩展函数）** `HirFunDecl` 增字段 `receiver: HirType?`（null = 自由函数）。接收者的类型实参、嵌套结构**原样保留**，不得丢弃。

**TS-29（特质）** trait 保留为 `HirTraitDecl`（含规范列表与继承列表）；规范内的 `Self` 以专门节点 `HirSelfType` 表示，**不得**替换成具体类型或 unknown——满足判定发生在检查层，不在 HIR 层。

**TS-30（impl 废除）** `HirImplDecl` 与 AST `ImplDecl` **删除**。解析到 `impl` 时产出错误声明节点并报 `E-IMPL-REMOVED`（保证容错链不断，且 HIR 不出现半成品 impl 结构）。

**TS-31（JSON）** HIR-JSON schema 版本号升为 `sublimation/hir@v2`；`receiver` 在自由函数上省略、扩展函数上必现；`HirSelfType` 固定输出 `{"k":"self"}`。

## 7 迁移表（旧 → 新）

| 旧写法 | 新写法 | 备注 |
| --- | --- | --- |
| `impl Functor for List[a] { fun map(...) }` | `fun List[A].map[B](f: (A) => B): List[B]` | 特质成员名成为扩展函数名 |
| `impl Nat { fun inc(): Nat }`（无特质） | `fun Nat.inc(): Nat` | 无特质扩展直接等价 |
| `impl T { by field }`（委托） | **废除** | 手工改写为显式转发；V1 不提供 by |
| 调用 `xs.map(f)` | 不变 | 方法糖查扩展函数桶 |
| 调用 `map(xs, f)`（旧 impl 成员按名直调） | 不变 | 直接调用按实参 1 类型头查扩展函数桶 |
| 约束 `[T: A + B]` | 声明继承 A、B 的特质后约束到该特质 | 若无此形态则按边界报错由样本改写 |
| `trait Sub : Base` | 不变 | 继承保留 |

## 8 裁决表（对 ADR-8 §四 六个待决问题的回答）

| 编号 | 问题 | 裁决 | 理由 |
| --- | --- | --- | --- |
| **Q1** | 满足检查时机 | **使用期现场判定 + 单次编译缓存**（TS-18） | 声明期判定与增量扩展冲突；使用期可前向引用 |
| **Q2** | 冲突与优先级 | 重复 → `E-DUP-EXT`；扩展函数与自由函数**不同桶**；直接调用时**自由函数优先**（TS-13/14） | 保证解析确定性，不做不可预测的「更具体者胜」 |
| **Q3** | impl 两种糖 | 无特质 impl → 扩展函数；`by` 委托 **V1 废除** | by 与结构化满足无必然联系 |
| **Q4** | 特质继承 | **保留**，满足子类 ⇒ 满足父类 | 迁移成本低，样本已用 |
| **Q5** | `for` 关键字 | **释放**为普通标识符 | 唯一用处是 impl，impl 已废除 |
| **Q6** | 渐进迁移 | **不设兼容期**：impl 直接报 `E-IMPL-REMOVED` + 迁移提示；样本手工迁移 | 新工程无外部用户，兼容期是纯成本 |

## 10 V1 边界（明确不做，记档备后继卷）

1. 运行时分派 / 字典传递（TS-23）——只有编译期满足检查。
2. 高阶类型约束 `F[_]: C`（TS-24）。
3. 多约束合取（TS-24，用继承替代）。
4. 常量规范的满足判定（TS-17 注）。
5. `by` 委托（Q3）。
6. 孤儿规则 / 扩展函数跨模块可见性——待模块系统立项后另卷。
7. 扩展函数重载的「更具体者胜」——直接调用一律自由函数优先（TS-14）。
8. **元组 / 函数类型作扩展接收者**：S-43 的 `TypeExpr` 只覆盖具名类型与应用（`Name TypeArgs?`），不含元组与函数类型。故 `(Nat, Nat).f()` 这类接收者在 V1 不可声明；样本迁移时以具名包装类型替代（t31 中 tuple 的 9 种形状仅具名 2 种迁移）。后继卷可扩 S-43 的 TypeExpr 到完整类型文法。

## 10.5 联合类型 / 空构造子单例 / 归纳类型（t41，ADR-28）

**声明形态**：「type E = A | B」（TypeAliasDecl；成员可为一切类型表达式——struct 名、别名、类型应用「Some[T]」、元组、函数类型）。

- **展平与判重**：构造即展平（变体里的具名别名就地展开、嵌套联合拼接，深度上限 8）；同名重复成员落 E-DUP-UNION-MEMBER。带实参的联合别名「Box[Nat]」同展开为「Some[Nat] | None」（理论参数按位代入）。
- **子类型方向**：成员 → 联合**单向拓宽**成立；联合 → 成员非法（适配失败落 E-TYPE-MISMATCH）。
- **空构造子单例**：判据 = 字段数 0。「struct None()」的 nullary 旗标贴 HIR 与 JSON；「None()」调用与圆括号模式落 E-NULLARY-PAREN（裸名「None」构造；「is None」与裸名模式都计入 when 覆盖）；带默认值的「struct P(x: Nat = 0)」**不**是空构造子。
- **归纳类型**：联合右值至少一成员不引用自身 → D-INDUCTIVE-TYPE（SUPPLEMENT 留痕）；全部成员引用自身（含「A=B|C, B=A, C 也引用 A」的团） → E-CYCLE。
- **when 穷尽性**：联合主题成员全部具名 struct 时按成员根名判覆盖（「is A」/ 构造子模式 / 裸名成员模式均计入）；缺成员 W-NON-EXHAUSTIVE（函数体位 E-NON-SEALED-MATCH）；非具名成员无法静态穷尽，提示补 else。
- **模式槽位类型**：结构体 ctor 模式的槽位按成员字段声明类型 + 主题实参代入（「var v: Box[Nat]」主题下「is Some(x)」的 x: Nat）。
