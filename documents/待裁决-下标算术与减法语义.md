# 待裁决：下标算术与 `Nat` 减法的语义

> 状态：**待用户裁决**（不阻塞 P-10 步骤 3）。队长 2026-11-08 07:5x 起草。
> 起因：ST-10.1 裁定 `Nat - Nat : Int` 后，`take(xs, n - 1)` 这类**下标算术**全部被拒。

## 1 事实盘点（全仓实测）

`e2e` 样本中 `x - 1` 形态共 **11 处**（早先粗测 26 处含注释误命中），其中：

| 文件 | 处 | 形态 | 当前是否受 ST-10.1 影响 |
|---|---|---|---|
| `core/collection/list.subl` | 5 | `elementAt(t, i - 1)`、`take(t, n - 1)`、`drop(t, n - 1)`、`slice(t, 0, to - 1)`、`slice(t, from - 1, to - 1)` | **是**（全部落 `Nat` 形参位）|
| `examples/日常-数列与区间.subl` | 1 | `fact(n - 1)` | 否（已改 `n: Int`）|
| `examples/高阶函数与lambda.subl` | 1 | `{ _ - 1 }` | 否（泛型解 `Int`）|
| 其余 4 处 | — | 注释文本误命中 | — |

**结论**：真实受影响的只有 `list.subl` 的 5 处，而该文件**本来就是红**（模块系统边界）。所以 ST-10.1 目前**没有让任何绿样本转红**——代价被掩盖了，但**语言里的写法缺口是真实的**。

## 2 四个候选方案

### A. 内建检查减法（显式）
```subl
fun natSub(a: Nat, b: Nat): Opt[Nat]      // 或返回 Opt，或饱和版
take(xs, natSub(n, 1))                     // 用法变啰嗦
```
| 优点 | 缺点 |
|---|---|
| 保住 `Nat` 非负不变量；无隐藏运行时失败 | 每个下标表达式多一层；`Opt` 版本还要解包 |

### B. 下标型改 `Int`
```subl
fun take[T](xs: List[T], n: Int): List[T]
take(xs, n - 1)                            // 直接可写
```
| 优点 | 缺点 |
|---|---|
| 写法自然 | **丢掉「非负」这条免费命题**；每个下标 API 都要运行期查界；与「HIR 尽可能多保留信息」相反 |

### C. 证明驱动（`axiom n >= 1` ⇒ `n - 1 : Nat`）
| 优点 | 缺点 |
|---|---|
| 最符合本语言方向 | 依赖 P-12 第 ③ 级，**V1 不可用**；且每个下标都要用户写断言，比 A 还啰嗦 |

### D. `Nat - Nat : Nat`，**下溢即 `panic`**（检查减法）
```subl
fun diffMs(a: Nat, b: Nat): Nat = b - a    // 类型仍是 Nat
// b < a 时：运行期 panic（不是得到负数）
```
| 优点 | 缺点 |
|---|---|
| 写法自然 **且** 保住 `Nat` 不变量；无「静默负数」 | **部分正确性**：类型/证明只对「正常返回」的执行成立；运行期可能 panic |

## 3 队长分析

### 3.1 先排除 B
`Nat` 下标携带「非负」这一**免费证明事实**。改成 `Int` 等于用一条事实换写法便利——与本项目「HIR 尽可能多保留信息」的方向相反。**不建议。**

### 3.2 A 与 D 的实质差别：错误发生在哪儿

| | A（`Opt`）| D（panic）|
|---|---|---|
| 下溢何时暴露 | **编译期**（类型强制你处理）| **运行期** |
| 代码噪音 | 每处 `natSub` + 解包 | 无 |
| 漏处理后果 | 写不出来 | 运行时崩 |

### 3.3 D 与本项目哲学是否冲突？
有人在燃料裁决里会问：「我们连『编译器检查时无法停机』都选择拒绝，为什么这里允许运行期 panic？」

回答：**两件事不同层**。
- 燃料是**编译器自己的不确定性**——它不知道，却给出结论，就是猜（违反 R-NO-GUESS）；
- 检查减法是**程序自身的失败路径**——语言**明确**规定「下溢即 `panic`」，这不是不确定，是确定的语义。

而且本语言已有 `panic()`（返回 `Nothing`，e2e 中 16 处使用），检查减法正好落在既有设施上。

### 3.4 D 对证明的影响（必须诚实说明）
`a - b : Nat` 让证明器可以免费得到 `a - b >= 0`。在 D 下这条命题**对正常返回的执行恒真**，对 panic 的执行**无值可言** ⇒ 属**部分正确性**。这与主流验证语言（Dafny/Why3 的 partial correctness 口径）一致，但**必须在文档里写明**，不能让人以为是全正确性。

## 4 队长建议

**建议 D**，理由：
1. 保住 `Nat` 的非负不变量（这是类型系统的资产）；
2. 下标算术写法自然（`take(xs, n - 1)` 直接可用）；
3. 下溢**不产生错值**，而是显式失败；
4. 复用既有 `panic` 设施，无需新语法；
5. 代价（部分正确性）是**可声明**的，不是隐藏的。

若判 D，需回退 ST-10.1 中「`Nat - Nat : Int`」一条（t63 的 `minusSup` 改为：`Nat - Nat` 取 `Nat` 但标记**检查算术**），并：
- ST-10 增加「检查算术」条款与部分正确性声明；
- 解释器设计（P-11/P-12）增加「检查减法在运行期核对 `a >= b`，否则 panic」。

若判 A，则需在 prelude 增加 `natSub`（并决定 `Opt` 还是饱和版），并把 `list.subl` 的 5 处改为 `natSub`——**这会改动既有红的细节**，需更新该红的证据记录。
