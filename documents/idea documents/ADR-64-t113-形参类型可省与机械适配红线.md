# ADR-64:t113 形参类型标注可省（S2 语法层先决件）与机械适配红线

日期：2026-11-11 · 任务：t113 · 依赖：t112 §1.1 设计、C-8/D-12、队长裁「路线 A」

## 语境

R3 S2 推导面要求语义层能看见「未标注的形参」。旧 parseParams 对无冒号形参落 E-SYNTAX
「期望形参类型标注（: 类型）」errType——语法层先截断，推导面根本不出现。先决件=解析接受。
契约原文「Param.type: Type 改 Type?」与「不触 semantics」冲突：改可空会强制 15 处 semantics
编译适配（Elaborator 11、VarianceInfer 3、Collector 1）。

## 决策（队长裁路线 A）

1. **AST**:`Param.type: Type` → `Type?`（t112 §1.1;kot 结构体字段同节点随改）。
   `FunDecl.retType` / `VarStmt.type` 本就可空——零改。
2. **Parser.parseParams** 无冒号分支 → `type = null`，**无诊断**（解析接受、空类型槽=空位）。
   解析器不知模式（D-12 真值单源）——工程模式硬拒 E-OMITTED-TYPE 是语义层 R-13 的活。
3. **15 处机械适配红线**（队长放行 Elaborator/VarianceInfer/Collector）：
   `X.type?: ErrorType("形参类型标注省略", X.pos)` 兜底。
   **①语义逻辑零写**:E-OMITTED-TYPE / R-13 工程硬拒 / 推导面一律不碰（t115+ 的活）。
   **②行为零变**:既有输入 Param.type 全部非空，兜底是死路径——由全量门 + e2e 冻红逐字 +
   SAME 68/68 兜证。t115 接管时逐位替换为元变量处理。
   AstPrinter 形参位改空安全打印。
   （未取的路线 B:omitted 旗标 + ErrorType 占位——占位把「省略」混入解析错误通道，
   S2 消费判别更脆，队长否。）
4. **先红态取证**（旧 classes CLI 探针）:`fun f(x) = 1` / `struct P(x)` 均落 E-SYNTAX
   逐字拒；绿态同一源 E-SYNTAX 消失（余留 E-TYPE-MISMATCH 为「= 1 返回 Null」的既有 cascade,
   与省略无关）。

## 风险与不变量

- 兜底 ErrorType 经既有全含通道（type()/specTypeQuiet/sigSkeleton/Site 结构相等映射）,
  消费侧把省略当解析占位——t115 前**无任何语义处置**（两种模式均放行到语义层接管）。
- 68 样本零含省略形参 → 解析层产物零变化（SAME 68/68 机器证）。
