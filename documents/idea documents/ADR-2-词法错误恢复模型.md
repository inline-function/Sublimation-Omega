# ADR-2 词法错误恢复模型：错误不停机与 71 项 Kind 的调和

> 状态：🟢 已决策（2026-11-04，t2 词法层实现）
> 相关任务：t2；相关规范：S-1 §1、S-3 §6、D-10（P-4 已决）
> 编号承接：ADR-1 为 semantics 的 HIR 设计（t5）；本文自 ADR-2 追加（documents/README 写作规范）

## 背景

t2 任务书（《形式化文法》§1 L-1~L-12 + 契约 S-1 §1）同时要求：

1. **错误 token 不停机**（全角标点提示、字符串未闭合、反引号跨行）——S-1 §1：「非法字符不停机——
   产出错误 token 并继续，错误恢复从第一层开始」。
2. **Kind 恰 71 项**——《形式化文法》§1.7「Token 全表（Lexer.Kind，共 71 项）」与任务书一致。

二者存在表面冲突：S-1 §1 字面要求「产出错误 token」，而 71 项 Kind 表中没有 ERROR 类别可承载它。
旧实现（点查 Lexer.kt）以抛 LexFailure 实现这三类错误——与新契约的「不停机」直接冲突。

点查另发现两处旧实现与文法的偏差：

- 旧 readToken 的分派顺序使 isSymbolStart 先于单字符分派命中全角标点（（、：等非 ASCII 非字母数字），
  故全角标点被读作 SYMBOL token，fullWidth 提示分支（旧 :139-142）实际不可达。
  文法 §1.5/§5.4 则声明「全角标点一律词法错误并提示改半角」——任务书亦显式列出「全角标点提示」。
- 旧 fullWidth 集合内含转义后的 ASCII 双引号，该字符在分派中已被字符串通道收走，提示永远不生效；
  单字符 `≠` 分支同样被 readSymbol 先收而不可达（文法 §1.2 注 5 已载明）。

## 候选方案

- **A 诊断旁路**：Kind 保持 71 项；词法错误以独立诊断记录（位置+信息）输出，恢复策略按错误类型
  产出恢复 token（未闭合字符串→STR、断裂反引号→IDENT），非法字符最小跳过（skip 1 字符）。
- **B 增设 ERROR Kind**：token 流内显式携带错误 token。违反 71 项 Kind 的硬约束（§1.7）。
- **C 语义映射**：全角（直接映射为 LPAREN 等。等于静默改写用户程序，与「全角是错误」的
  文法表述相悖，且会掩盖下游诊断。

## 决策

采用 **A**：

1. `LexError(fileName, line, col, message)` 为词法层最小诊断记录，只记错误起点位置；
   `Lexer.errors` 在消费 token 流后暴露。D-10（P-4 决议）已定为结构化诊断
   （`SourceRange(start, end?)` + envelope，码族 E/W/D/H 对齐旧体系），本记录是其中
   start 的承载——词法层不预建 diag 横切包（t6 的在域工作，S-2 §3.2 依赖方向），
   t6 实现后由其将 LexError 提升为 SourceRange 形态，lexer 接口无需变动。
2. 恢复 token：字符串未闭合/反引号未闭合/跨行时，已读内容照常作为 STR/IDENT 产出——即 S-1 §1
   所指的「错误 token」由恢复 token 承载；非法字符（含全角标点）记诊断后跳过一格，无对应 token。
3. 全角标点落实为**错误带提示**：isSymbolStart 剔除 fullWidth 集合（先于符号名通道拦截），
   使 §1.5/§5.4 生效。fullWidth 集合修正为全角双引号 ＂（U+FF02）。此为相对旧实现行为的偏差，
   依据是任务书显式列出「全角标点提示」与文法 §1.5/§5.4；旧实现的分支不可达属缺陷而非规格。
4. 不复制 ≠/ASCII" 不可达分支（S-4 禁死代码），行为与旧实现等价，溯源注释载明理由。
5. 流式契约（S-1 §1）以 `tokens(): Sequence<Token>` 落地：惰性序列、可提前终止；
   `tokenize()` 为其便捷完整消费（含 EOF 结尾）。Lexer 实例单次消费。

## 后果

- 语义层下游（parser）面对非法字符时以「缺一个 token」的方式恢复；S-1 §2 的容错解析在语法层
  自行决定局部子树形态——词法层不越权造 token（如方案 C）。
- t2 回归移植：旧「非法字符报错带行列」测试以诊断断言形式保留（S-1 §1 覆盖旧 LexFailure 语义），
  其余 7 条旧测试行为等价直接移植。
- D-10（P-4）落定后，LexError 与 t6 的 SourceRange 诊断对接为一次性提升；若后续诊断体系要求 token 流内携带错误标记，需修订 S-1 §1 与 §1.7 并再次权衡（届时以新 ADR 取代本文）。
