## 2 承载形态设计（推导结果放在哪、怎么进消费位）

### 2.1 推导纯度表（P-11 §4 不动点）

- **形态**:`MutableMap<String, Boolean>`（函数名→impure）+ 单调闭包（P-11 §4 四条:初值=顶层语句/内建不纯/标 @impure;传播=调不纯者不纯;SCC 整体;迭代到不动点,最多 |V| 轮必然终止）。
- **落点**:注入 t96 的 `declaredPurity`（`Elaborator.kt:2457`）——**既有变量即注入点**,无需新消费通道。
- **新表 1 张**（闭包工作内存）。工程模式 gatePurityOf 保持注解口径（基线红线）;脚本模式分叉 = `gatePurityOf` 一处先查推导表。分叉点单一是「工程模式语义不变」的结构保证。
- 与 t94（:1228）的关系:节点 purity 底向结果 = 闭包的**初值**;推导表 = 闭包的**终值**;两者不一致即推导轮未收敛（P-11 §6 E-INFER-NOT-CONVERGED 的可观测点）。

### 2.2 上提的合成 prep（证明义务上提）

- **形态**:推导证得 `f` 纯 ⇒ 合成 `HirPAtom(head="pure", terms=[HirTName(f)])` 追加进 `f` 所在声明的 `d.preps`（`hir/Decl.kt:25` 既有字段）。
- **消费链零改**:`d.preps` → `GateScope.facts`（:2606）→ `g.proven`（:2440）→ `gateCheckCall`（:2504）。**纯增量追加,不触碰既有解析路径的 preps**。
- 与工程模式用户写的 `<pure<f>>` 同走一条消费链;**区分与否 = C-8 设点 ②**（§4）。

### 2.3 可变性推导入视图判定（P-11 §5）

- **走既有变量者**:`isWritableView` / `sub` @ref 三支 / `borrowView` / `copyDispatch` 全部以 HirType 树为输入 ⇒ 合成 `@mut` 落进类型树即被消费,**零新表零接口**。
- **需新表 1 张**:可变性需求位表（P-11 §5 表:赋值位 / 传入 @mut 接收者位 / 字段写位 → 变量名集合）单调闭包;产物 = 合成 `@mut` 注入 var/形参类型,经 `varAnnotated`（:877 同族通道）落类型树。
- 赋值通道共用前提已满足:P-11 §5 注明依赖 t60（赋值类型核对）——已落地（`:877` assignTypes）✓。
- **字段可变性是否入类型 = C-5（未裁,§4 双分支）**,影响:是否需要「字段可变性表」第二张新表,以及 §1.2 的 patOrigins 字段链可解性。

## 5 I-1 两套 walker 统一方案（供 S4 落地免二次重构）

**现状**（结构债台账 I-1,2026-11-10 登记）:
- `containsImpureCall` 族（`Elaborator.kt:2366-2402`）——t94 纯度扫描与 lambda/anonFun 节点 purity 底向输入;
- `gateWalk` 族（`Elaborator.kt:2549-2609`）——t96 闸扫描;
- 13 个相同分支,`else -> false` / `else -> {}` 兜底,相距约 140 行;现状无分歧（68 样本两套均 0 行为差异）——**维护性问题不是 bug**,风险=新增节点形态需同步改两处、漏改经 else 静默通过（t101 的 BorrowExpr 即下一个待补位例证）。
- I-4 unchecked 不对称（:2398 递归进 vs :2589-2591 推 scope 放行——语义已定义:豁免**检查**不豁免**效应存在**）;台账要求「①ADR 写明 ②锁定测试」需核（见 §6-F4）。

**方案:单 walker 发事件 + 三消费者订阅**（签名级草案,落地任务再细化）:

```kotlin
// 草案（非实现）:统一 Hir 遍历,事件驱动,取代 containsImpureCall/gateWalk 两族
private interface HirWalkerSink {
    fun enterScope(scope: GateScope-like)   // fun/local/unchecked 域进出
    fun callSite(call: HirCall, args: List<HirExpr>)  // 统一承载:gateCheckCall / checkTermination / impureCallee
    fun exprEnter(e: HirExpr)
}
// 消费者订阅:t94 节点纯度扫描 / t96 闸检查 / t97 停机判定（现内联于 :1732/:1828/:1871 的调用位检查改由 callSite 事件统一承担）
```

**迁移点清单**（S4 落地时逐条核销）:
1. `gateCheckCall`（:2498）+ 3 处内联 `checkTermination`（:1732/:1828/:1871）→ `callSite` 事件;
2. `GateScope` 进出（:2589-2591/:2593-2597/:2602-2609）+ `funFrames`（FunFrame:3116）→ `enterScope` 事件——两套作用域栈需先归并或明确分工（gate 栈=检查序,funFrames=返回/停机序）;
3. `containsImpureCall`（:2366）/`containsImpureStmtCall`（:2393）→ 由 t94 订阅者直接消费事件折叠;
4. 保留 `else` 兜底的代价:新节点漏改静默 → walker 本体走 sealed 穷尽（Kotlin 编译器强制,与 t95/t101 的 sealed 改造同构——即 t101 正在支付的穷尽税,统一后只付一次）。

**时序**:R3 任务书 :61-62 已注明「S4 若统一遍历可顺带收口」——本方案对齐该时序;**不要在 S4 前为收敛 Walker 单开任务**（会与 t101 的 sealed 改造撞车）。
