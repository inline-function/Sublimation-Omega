# ADR-47 算术链同类判定提示（H-ARITH-PREC 重构）

**日期**：2026-11-08（t71）
**状态**：已落（替换原 D-10「右侧更紧才提示」规则）

## 一、决策

用户裁决 A1-A3:**没有优先级，中缀一律左结合**(`a f b f c` = `(a f b) f c`);对 `+ - * / % ^` 六个
算符的混用给**提示级**诊断（不规范代码，劝显式圆括号），**不实现优先级**。

新规则：**同一括号层级**内一条算术链若同时出现**不同类**算符 ⇒ 提示 `H-ARITH-PREC`:

```
类 1: ^        类 2: * / %        类 3: + -
```

| 写法 | 提示 | 理由 |
|---|---|---|
| `a + b * c` / `a * b + c` / `a ^ b * c` / `a + b ^ c` / `a % b + c` | **提示** | 同层跨类 |
| `a + b + c` / `a - b + c` / `a * b / c` | 不提示 | 同类：左结合无歧义 |
| `(a + b) * c` / `a + (b * c)` | **不提示** | 括号重置层级——括号已显式定本意 |

仅判六算符；**不判**用户自定义中缀、比较算符（`<=`）、命题算符。提示恒为 H 族，不得升级 W/E。
诊断码不变（仍 `H-ARITH-PREC`)，只改触发规则与文案。AST 不受影响——一律左结合的解析结果逐字不变。

## 二、旧规则为何出局（9 探针：3 漏 1 误报）

旧规则「右侧算符比左侧更紧（arithPrec 数值）才提示」且**不看括号层级**:

- 漏：`a * b + c`(h1)、`a ^ b * c`(h3)、`a % b + c`(h9)——右侧不更紧即不报；
- 误报：`(a + b) * c`(h6)——用户已显式括号，编译器却劝他加括号（把人做对的事当错误）。
- 新规则 12 探针（含三算符链/嵌套括号/比较式）全中，见 §四。

## 三、实现（parser/Parser.kt,纯解析层）

| 位置 | 改动 |
|---|---|
| `arithClass(op)` | 替换 `arithPrec`:^=1、* / %=2、+ -=3、其余 0 |
| `depthAt`(新属性） | token 的括号层级 Map——**AST 无 ParenExpr**(parsePrimary 括号分支返回内层表达式），「括号重置层级」只能由 token 序列算（LPAREN 进、RPAREN 出；调用/元组括号同理，语义上是链的天然边界）。BinExpr.pos 恰指向算符 token ⇒ 按算符位置查深度 |
| `maybeArithHint` | 沿左侧 BinExpr 链收集**同层级**算符类；非六算符节点或跨层节点即截断；链本身已跨类（更早结合点已报）不重复；位置指向**跨类的那个算符**（当前 tok) |

链只报一次的去重：当前结合点收集到的链类集合若 `size > 1`,说明此前结合点已报（如 `a + b * c + d`
的第二个 `+`:左链已含 {3,2}),直接返回。文案去掉「本应先于」这类暗示优先级的措辞。

```
文案：算术链混用了不同类算符（`+` 与 `*`）：中缀一律左结合，写出来的顺序就是
      计算顺序——如 `a + b * c` 实际是 `(a + b) * c`。请用圆括号显式指定本意（如 `a + (b * c)`）
```

## 四、验收（12 例，ArithPrecHintTest 12/0)

队长 9 探针（BEFORE → AFTER):h1 0→**1**、h2 1→1、h3 0→**1**、h4 1→1、h5 0→0、h6 1→**0**、
h7 0→0、h8 0→0、h9 0→**1**——旧 3 漏 1 误报全消。补充 3 例：#10 `a + b * c + d` = 1（不重复）、
#11 `a + (b * c + d)` = 1（内层报）、#12 `a + b * c <= d` = 1（比较符不判，算术部分照报）。
护栏例：自定义中缀 `m add n` 不判；解析期无错；提示落 diag 不混入 notes。

## 五、后果

- 既有 12 处混用样本**全部已加括号**(h6 型）⇒ 新规则下零提示——「改提示」不改出大面积噪音。
- 提示信用修复：不再把「已加括号」当错误（h6 误报是信用流失点）。
- 优先级永远不存在：本 ADR 不引入任何优先级求值，H-ARITH-PREC 仅是风格劝告。
