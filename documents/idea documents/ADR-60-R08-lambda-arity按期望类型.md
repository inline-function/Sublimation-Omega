# ADR-60:lambda 隐式参数糖的 arity 由期望类型定（R-08 / R-10 收口）

| 状态 | 口径 |
|---|---|
| 已接受（2026-11-11，队长裁决;仲裁记录 §R-08 + §R-10）| 推翻 S-36 旧「无箭头=无条件隐式单参」;Parser 不动,Elaborator 侧定 arity |

## 背景

S-36 把无箭头 `{ e }` 形态定义为解析器合成的**无条件**隐式单参糖（`_` 引用形参）。该设计放行了
两类失配形态:零参期望位打单参 lambda（`applyZero({ _ + 1 })` 今日放行）、以及工程模式无期望位
的 `_`（`var f = { _ * 3 }` 今日放行）;同时把「无箭头 { e } 无 _ 用法」错报为单参（`f()` 落缺实参）。

## 决策

1. **语法层零语义**:Parser 产 implicit-It 糖不变（`{ e }` → implicitIt=true,params=["_"]）;
   成参与否、arity 全由语义层（Elaborator LambdaExpr 分支）按期望类型决定。
2. **已知期望（lambdaExpect 单通道:声明型直调实参位,含尾随）**:
   - 零参 fn ⇒ 零参（`_` 用即未绑定——复用既有 E-UNBOUND-NAME 的 `_` 口径文案）;
   - 单参 fn ⇒ 一参（`_` 启用,**参数可不用**——Kotlin 对齐:`listOf(1,2,3).map { 7 }` 同形态）;
   - 多参 fn ⇒ 无箭头形态不可,落 E-ARITY 引导写显式参数表。
3. **未知期望位走模式分立**（R-06 同族:工程=严格声明,脚本=宽松推导）:
   - 工程模式（顶层语句不存在）:`_` 报错 E-IMPLICIT-IT,须写 `{ x => … }`（补法 2,Kotlin 同款）;
   - 脚本模式（顶层语句存在——与 HirJson.unitMode 同源判据）:`_` 用法自定单参,类型由用法推（补法 1,
     唯一超出 Kotlin 的宽松）。
4. **D-11（调用元数一致性）**:`TypeInfer.callFun` 实参位核对中,函数型实参的元数一致性单独落 E-ARITY——
   元数是**结构信息**,与推导完成度无关,不受 reportMismatch 的 synthetic 未完成容忍位保护
   （原漏洞:`((推导:lambda参数_)) => T` 贴 `(() => T)` 形参位被整位容忍放行）。
5. **无下划线 `{ e }` 按期望定形**（R-10）;单参期望位参数可不用、保持通过
   （`apply({ 7 }, 4)` 不收紧——队长读法 i,推翻读法 ii）。

## 通道范围

期望通道**仅** lambdaExpect 单点（两遍定型第二遍供给,Elaborator:2021-2022）。未达位态
（方法糖 / 函数值调用 / var / 赋值 / return）按「无期望类型」走模式分立——通道扩展属 S2 推导机域,
不进本 ADR。qa t105 机器扫:implicitIt:true 位点 4 个,全在单参期望实参位、体内全用 `_`
（68 样本形态不变,SAME 68/68 已证）。

## 后果

- 半成品树原则不变:多参期望位/工程模式 `_` 位仍构造可继续分析的节点（arity=0/1 + 诊断并行落）。
- 诊断族:新增 E-IMPLICIT-IT（已登记 诊断码-文档与实现对照审计）;E-ARITY 复用,E-UNBOUND-NAME 复用
  （`_` 丢弃标记口径）。
- ParserTest:545-554（parser 层断言 params=["_"]）不受影响（parser 未改）;语义层断言在
  T106R08LambdaTest（10 例,含 5 条负例红态构造）。
- F1 教训的延续:ParserTest 的 params=`["_"]` 与 implicitIt=true 同时为真的形态,正是本次
  `implicit = e.implicitIt && e.params.isEmpty()` 判据险些误判的坑（首版编译过、行为错;
  由 canonical 探针诊断捕捉修正）——**parser 的糖既带标志位又带合成参数,判据只取标志位**。
