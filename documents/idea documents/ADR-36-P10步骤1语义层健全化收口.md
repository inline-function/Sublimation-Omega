# ADR-36：P-10 步骤 1 语义层健全化收口（synthetic 放行删路 / Nothing 单向 / 参数位逆变 / 函数值调用通道）

> 状态：Accepted（t58 收口）。基线（t57）：531 用例 / 0 失败、e2e 65/68、双快照零警告、结构违规 0。
> t58 交付：542 用例 / 0 失败（+11 SoundnessTighteningTest，+1 旧契约断言收紧）、e2e 65/68、双快照零警告、结构违规 0。

## 一、动机
旧 `adaptOk` 里有四条「一律放行」式的宽松契约，使类型判定通道把推导未完成的产物与真失配混为一谈：
1. synthetic 位一律 `-> true`（adaptOkBody 开头）；
2. Nothing 双向放行（got 或 want 为 Nothing 都算成）；
3. 函数类型参数位按协变比对；
4. 函数值（`fun g(f: (Nat)=>Nat): Nat = f(1)` 里的 `f`）调用结果一律取合成位「调用f」。
验收方案（P-10）的目标口径：**仅在推导未完成时容忍，完成后必须复核，禁止长期放行**；推导失败被放过的用例必须报错（P4）。

## 二、决策
- **R-34**：`adaptOkBody` 头部 synthetic 一律放行分支删除（`got.isSynthetic() || want.isSynthetic() -> true` 删除）。
  - 「判官」（adaptOk 及其 FunType 递归）无条件严格——验收方案「完成后必须复核」的落点。
  - 「推导未完成」的容仍保留，但位置**从判官移到落点闸**：见 R-38（R-34 修复侧）。
- **R-35**：Nothing 单向。`isNothingT(got) -> true` 保留（Nothing 可赋给任意返回位）；`|| isNothingT(want)` 删除——want 为 Nothing 仅由下方 typeEq 落（`var x: Nothing = 5` 拒；`panic()` 返回 Nothing 放行）。
- **R-36**：函数类型参数位逆变。`gotFT <: wantFT ⟺ wantP <: gotP 且 gotRet <: wantRet`，即 `want.params.zip(got.params).all { adaptOk(it.first, it.second) }`（参数位两两翻转），返回位协变不变。
- **R-37**：Elaborator 新增 `funValueCall(name, argTypes, pos, explicitTps)`——函数值调用按其函数类型（`symbols.lookupValue(name)` 的 HirFunType）走 callFun 核对实参与返回，不再产出合成位「调用f」。callExpr 的 FUN/THEOREM/LOCAL 分支 `?: funValueCall(...)`，`else` 分支同上。
- **R-38（R-34 的落点闸）**：TypeInfer 新增统一落点 `reportMismatch(got, want, pos, msg)`，理由二段：
  - ① t51/t52 口径：同请求燃料耗尽不报；
  - ② **以 synthetic 为操作数的拒绝保持在「推导未完成」容忍内**（验收方案明文独条的例外）
    `containsSynthetic(got) || containsSynthetic(want) → 不报`（复合类型深扫：函数型/可变型/联合/元组/参数位）。
  - 理据：合成位判定为「未完成」而非「失配」——该位置的 lambda 参数位、内建泛型位等在 V1 推导能力下本就无法收尾，也不会吐根因诊断；对其落错是对**合法但超出推导能力**的样例过拒。
  - **真失配（两边均具体，synthetic 叶为零）如实落 E-TYPE-MISMATCH**：P1（Nothing 体）、P2（参数位逆变）、R-35 反向（Nothing 期望位）、P4（apply 的裸类型参数 T 撞具体型）皆由此通道落错。
- **R-34 修复侧（内建位）**：旧 synthetic 位承担了两类「真需求」，严格化后必须给真通道：
  - 通配期望位：`syntheticT("任意")` → `namedT("Any")`（`isAnyExpect`：期望 Any 接受任意具体类型）。
  - 内建泛型位：`syntheticT("T")` → `namedT("(内建T)")`——具名类型变量标记；新增 `builtinTheoryNames(name)`（扫签名中的标记位），三个 builtinSig→callFun 落位（方法糖、BUILTIN/PRELUDE 自由函数位）下传 `theoryNames`，由 instCall 按名解出（`r in (1..10)`：右侧 Range[(内建T)] ← 实参 Range[Nat] 解出，旧只靠放行通过）。

## 四、「旧路径已死」机械佐证（验收门槛 ①）
- `grep -n "adaptOkBody" TypeInfer.kt` 后函数体头部：**不存在 `-> true` 的 synthetic 分支**（R-34 删除；保留的只有 `isNothingT(got) -> true` 单向位与下方的 typeEq 位）。
- 残存 synthetic 容忍**不在判官内**，只在 R-38 落点闸，且以「该拒绝的操作数含合成位」为充要条件——判官对合成位一律回 false，旧「判官放行」路径在调用链上不可达。
- 旧契约单测 `TypeInferTest.adaptOkTolerances` 第 195 行原断言 `assertTrue(adaptOk(syntheticT("半成品"), namedT("Nat")))`（**字面断言被删的旧分支**）已最小翻为 `assertFalse(...)`——唯一一处断言更新，逐条登记于此。
