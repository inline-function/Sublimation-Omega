# ADR-61:R-07 捕获外部可变变量并访问 ⇒ 不纯（闸增强）

| 状态 | 口径 |
|---|---|
| 已接受（2026-11-11,队长口述 + 全数子问裁决;R3 裁决记录 §R-07）| t96 纯度闸新增捕获维度;不动 elaboration / HIR 树 / JSON |

## 背景

t96 的 `gatePurityOf` 只看声明位:`@impure` 注解 / `@root` + 内建不纯名表 —— **无自由变量维度**。
裁决（队长原话):「函数捕获任意的外部可变变量并依赖于这个变量,则函数不纯」:
- **可变状态 = 效应**:捕获的可变变量可在调用间变化 ⇒ 同输入异输出 ⇒ 破坏引用透明（R-02 同原理族）;
- b 子问:仅读也算依赖（读 = 依赖可变外部态;写 = 本就是变化效应);
- c 子问:`@ref @mut T` 等同（判据 = **类型含 @mut** 即可变,@ref 只是视图,递归穿透判 inner);
- a 子问:工程与脚本模式同效（不纯上下文内无需管——脚本顶层与 `@impure` 体内本就不纯;
  D-12 模式真值缺陷在裁期内由 t111 修复,本闸读既有自算判据,行为与 t111 后一致:纯链守卫在前）。

## 决策（机械规则）

**捕获的自由变量其类型含 @mut 且被访问（读或写）⇒ 该函数不纯**,经既有 t96 传播链上提:

1. **判据**（`gateMutCapture` 单点):符号 id 不在本函数绑定集内（自由 = 外层局部/形参/全局变量;
   函数与构造子名非捕获口径) + kind 为值种类（LOCAL/PARAM/FIELD/TRAIT_CONST) + 占位类型
   `containsMutT` 递归含 HirMutType（HirRefType/HirAtomicType/Tuple/Union/Fun/Qualified 递归穿透)。
2. **分析位**（纯 gate 侧,runPurityGate 内;**不改 elaboration、HIR 节点与 JSON**——`purity` 字段不动,
   故 68 样本产物逐字节不变）:
   - 全局具名函数:**预扫描**先于调用位诊断（顺序无关:调用方在文件里先于被调方亦见其捕获不纯),
     置 `GateCtx.declaredPurity` —— 纯作用域内调用它即落既有 E-IMPURE-FUN-CALL；
   - 局部 fun（gateWalkFun):捕获成立则翻 scope 不纯 + 回写其 `declared` 登记位,调用方走 t96 链;
   - 局部 lambda / 匿名 fun（gateWalkExpr 分支):捕获与 t94 的 e.purity 并联推入 scope（创建闭包≠
     调用,t97 口径);体内调用闸放开。
3. **报告守卫**:仅纯链内报告（`g.stack.any { it.impure }` 先行守卫——不纯上下文内无需管）。
4. **嵌套各归自身**:扫描遇 HirLambda/HirAnonFun/HirLocalFun 不下降——内层闭包的捕获在自身作用域
   推入时分析（与 containsImpureCall 同构）。
5. **诊断**:新码 `E-MUT-CAPTURE`（E 族拒绝）,文案给三路可编译出路:改形参显式传入 / 先取不变快照 /
   标 `@impure`。

## 不做（明确边界）

- **闭包经变量持有后的调用传播**（`var f = { … }; f()`):类型位 purity 名义 PURE 的 ADR-54 过渡态缺口,
  t94 与 R-07 同缺;不进本 ADR（S2 推导机域）。
- 工程模式无顶层 var（Parser:201）——全局捕获形态只能落在函数体内;脚本顶层 impure 语义下全文件豁免
  （与既有 t96 脚本口径一致）。
- 用户语义门（E-IMMUT-ASSIGN 等）不动;`unchecked` 通道不动（unchecked 内的捕获扫描穿透——
  既有 t96 语义:豁免检查不豁免效应存在,但 R-07 判据是纯链守卫,unchecked 语句位于纯链内时其内捕获仍计）。
