# S-3 流程与角色分工

> 状态：🟢 初稿。2026-11-04 起草，落实 D-5 角色分工与 D-4 规格三件套的操作流程。

## 1 角色与权限

| 角色 | 职责 | 红线 |
| --- | --- | --- |
| 用户 | 方向拍板；冲突仲裁（D-4） | —— |
| 队长 | 规划、任务书、审查、规范维护 | 不写代码（D-5） |
| 工人 | 一切代码产出、测试、验收证据 | 不擅自修改 specification/ |

## 2 任务书纪律（硬规则）

1. 任务书只允许引用**条款编号**：本目录 `S-x / D-x`、`documents/boring documents/` 的规则编号（`L-n / S-n / D-n`、语义规则如 `S-IMMUT-1`）。禁止引用对话记忆——对话会失传，规范不会（specification/README 效力 3）。
2. 旧实现是字典，不是蓝图（D-1）：按需打开旧仓库 `F:\KotlinProject\sublimation` 的具体文件点查，禁止通读。
3. 旧测试是行为规格（D-4）：前端回归必须移植旧 `frontend/src/test` 的对应测试。

## 3 任务生命周期

```
任务书下发 → 认领/分派 → 进行中 → 完成（附验收证据）→ 队长审查
```

- 完成任务必须附**验收三件套**：
  1. 测试证据：本期单测 + 移植回归通过；
  2. 条款对账：任务书引用的每条规则逐条说明落实处；
  3. 交付清单：产出物与下游任务的输入契约一致。
- 审查不过：队长出具书面 find list，工人修订后重新提交；同一任务两次不过，升级用户仲裁。

## 4 代码审查标准（落实 S-4）

- 每个阶段入口与树节点类具备**契约注释**（KDoc）。
- 实现 boring documents 编号规则处具备**溯源注释**（规则编号 + 一句话）——硬规则。
- 存在权衡处具备**动机注释**。
- 三禁：复述代码的注释、注释掉的死代码、未验证的断言。
- 英文标识符 + 中文注释。

## 5 文档与规范留痕

1. 修订 `specification/` 须注明日期与原因，禁止悄悄改动（specification/README 效力 2）。
2. 重大设计决策写入 `documents/idea documents/`（ADR 体：背景/候选/决策/后果，编号追加）。
3. 过程写入 `documents/log/YYYY-MM-DD.md`（编年体）。

## 6 升级与待决

- 遇 `P-x` 待决事项，工人不得擅自拍板：工人 → 队长 → 用户。
- 实现中发现既有规范不足以覆盖的新事实，补本目录条款（不靠对话约定）。

## 7 文件完整性与测试台账（2026-11-05 增补，事故驱动）

> 背景：HirJsonTest.kt 与 TypeInferTest.kt 两次因**向大文件追加写入被截断**而丢失内容；后者更因「停放残骸 + 在残缺测试集上取得全绿」而一度掩盖覆盖丢失（305→277 tests 仍报 0 failures）。

1. **禁止向大文件追加写入新测试**：新增测试一律落**新文件**（一主题一文件），降低截断影响面。
2. **移走/改他人文件前必须验完整性**：①含 `package` 头；②含顶层 class 或等价声明；③`@Test` 计数与最近一次全量运行一致。三者缺一不得移动，只能通知作者处理。
3. **测试台账硬要求**：报告测试结果必须写总数，并与上一轮比对；**总数下降必须显式解释来源**，否则该验收无效。仅「0 failures」不构成证据。
4. **跨所有权操作单列**：任何改/移他人文件的动作须在报告中单列「跨所有权操作」小节，说明原因、影响、验证方式。
5. 队长审查不采信「全绿」字样，须核对测试总数与台账。

## 8 编译快照握手（暂态树采样纪律，2026-11-06 立）

**背景**：三人同树并行时，A 的验收会被 B 的在途编辑（未完成、暂不可编译）打断。t32/t33 已发生过一次（64→57→64 假跌），t42 又遇到一次（`Elaborator.kt` 1246/1746 Unresolved，瞬时拦编译）。

### 8.1 规则
1. **验收前必须取「快照可编译」状态**：连续两次 `compileKotlin` 均为 `BUILD SUCCESSFUL` 才可开始验收采样。
2. **诊断归属判读**：若编译错误落在**自己不拥有的文件**上，判为「他人编辑中的暂态」，**不计入失败**；稍后重试，不修改他人文件。
3. **单向依赖等待**：需要他人文件可编译时，**留言等待**，禁止代改（t42 已按此执行，正确）。
4. **完成即广播**：自己的改动达到可编译状态后，一句话广播「main 可编译」，解除他人等待。
5. **报告须带采样时间戳**：任何「全绿/零警告」结论必须注明采样时刻，否则不可复核。

### 8.2 判据不变
零警告判据仍为：`BUILD SUCCESSFUL/FAILED` 标记 + 合并流扫 `.kt:\d+` 且带 `(e:|w:)`（ADR-24 §五）。**不得**用 `^e:` 前缀过滤（PowerShell 会加 `gradlew.bat : e:` 前缀，曾造成假阴性）。

### 8.3 构建槽位互斥（2026-11-06 新增，因并发 Gradle 覆盖测试结果）

**事故**：t43 与 t39 同时跑 Gradle，两个 daemon 并发，**JUnit 结果 XML 被部分覆盖**，测试统计不可信；并出现双 daemon 警告。

**规则**：
1. **同一时刻只允许一人运行 Gradle**（构建槽位是独占资源，不是文件）。
2. 需要在飞期间做构建的，**向队长申请槽位**；队长按「谁离收口最近」分配。
3. 拿到槽位者**一次跑完**（编译 + 测试 + e2e 一轮），立刻释放并广播「槽位已释放」。
4. **`--rerun-tasks` 不是并发保护**：它只强制重跑，不隔离结果目录。
5. 若报告里出现「双 daemon 警告」或结果文件时间戳异常，**该次统计一律作废，重跑**。

### 8.4 零警告的责任划分
编译警告**按文件归属**：谁的文件出的警告谁消。若警告来自他人文件，留言请其处理，**不得**代改。

### 8.3.1 构建槽位已机械化：`tools/build-slot.ps1`（2026-11-07 12:40 起强制）

**背景**：§8.3 的「向队长申请槽位」是**社会约定**，靠自觉。t43 期与 t53 期各发生一次并发 Gradle，症状相同：`compileKotlin` 期进程被杀、test XML 被部分覆盖（290/507）。约定显然不够，改为机械互斥。

#### 用法（PowerShell 5.1 环境，`pwsh` 未安装）
```
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build-slot.ps1 status
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build-slot.ps1 run -Note t5x -GradleArgs ':frontend:test --rerun-tasks'
```

| 命令 | 行为 |
|---|---|
| `status` | 打印 `SLOT=FREE` 或 `SLOT=BUSY pid=… started=… note=… stale=…` |
| `acquire -Note <id>` | 独占创建 `<repo>/.build-slot`；已被占则 **exit 3** |
| `release` | 删除槽位文件 |
| `run -Note <id> -GradleArgs '<gradle 任务…>'` | **推荐**：acquire → 跑 gradlew → 无论成败都 release |

#### 语义要点
- 槽位 = 仓库根的 `.build-slot` 文件，内容 `pid|ISO时间|备注`，用 `CreateNew` 保证原子性。
- **失效判定**：超过 `-StaleMinutes`（默认 30）→ 视为陈旧可抢占；或 pid 已死**且**已过 2 分钟 grace 期。
- 为什么不用「pid 一死即失效」：`acquire` 常在**短命进程**里执行（执行完即退出），只看 pid 会把**合法持有**误判为失效——这个坑在自测时当场踩到并修正。
- 拿不到槽位**不许绕过**（不得直接调 gradlew）。绕过即视为破坏纪律。

#### 纪律不变
§8.3 的其余条款仍然有效：一次跑完（编译+测试+e2e）、跑完广播释放、出现双 daemon 警告则统计作废重跑。

#### 8.3.2 `run` 的参数形式（**2026-11-07 14:10 修正，务必用新形式**）

**错误形式**：`run -Note t51 -- :frontend:test --rerun-tasks`
PowerShell 5.1 会把 `--` 当作**空参数名**、把 `--rerun-tasks` 当作**参数名**来解析，直接报 `AmbiguousParameter`。

**正确形式**：`run -Note t51 -GradleArgs ':frontend:test --rerun-tasks'`
把整串 Gradle 任务作为**一个字符串**传入，由脚本自行切分。这样 `--rerun-tasks` 这类以 `--` 开头的 Gradle 选项不会被 PS 吞掉。

**若拿不到槽位或脚本报错**：`status` 看持有者，**不要退回直接调 gradlew**。

#### 8.3.3 陈旧槽位清理
槽位文件残留（如执行者进程被杀）时，`status` 会显示 `stale=True`；此时 `acquire` 会自动抢占（`SLOT=STALE_STOLEN`）并继续，无需手工删文件。
